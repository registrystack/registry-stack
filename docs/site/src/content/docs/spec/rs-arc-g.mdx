## 1. Scope

This specification defines the ownership and composition rules shared by maintained Registry Stack
products.

## 2. Product ownership

REQ-ARC-G-001: Registry Manifest MUST remain a portable metadata library and CLI. Its output MUST
NOT grant runtime authority.

The [Registry Manifest reference](../../products/registry-manifest/reference/) owns the current
metadata key and field inventory.

REQ-ARC-G-002: Portable metadata MUST NOT carry deployment secrets, source paths, database
credentials, or caller authorization.

REQ-ARC-G-003: Each runtime product MUST own its routes, configuration, authorization decisions,
audit behavior, and recovery boundary.

REQ-ARC-G-005: Security primitives that must behave identically across products SHOULD come from
Registry Platform while product policy remains in the product.

REQ-ARC-G-010: Base Registry Engine MUST own the PostgreSQL records it creates and mutates.

REQ-ARC-G-014: Evidence Gateway MUST authorize a request before protected source access.

REQ-ARC-G-015: Evidence Gateway MUST release only the concepts and value forms declared by the
reviewed requirement.

REQ-ARC-G-017: Registry Discovery selections MUST remain inert metadata until the application
validates and accepts them locally.

REQ-ARC-G-019: Registry Casework MUST leave source mutation authority with the source system.

REQ-ARC-G-021: Products MUST be deployable and recoverable independently. No shared project root or
activation coordinator is implied.

## 3. Composition

Products compose through documented HTTP contracts, signed assertions, portable static artifacts,
and explicit client calls. A package, credential, trust decision, or audit record from one product
MUST NOT silently authorize another.

## Conformance

An implementation conforms when it satisfies every applicable requirement above.
