## 1. Authentication and authorization

REQ-SEC-G-001: A protected operation MUST authenticate the caller and complete its authorization
decision before protected source access or mutation.

REQ-SEC-G-006: Unknown, malformed, expired, wrongly issued, or insufficient credentials MUST fail
closed without disclosing protected source state.

REQ-SEC-G-007: Authorization inputs MUST come from verified credentials, reviewed configuration,
and governed state rather than an arbitrary caller field.

## 2. Disclosure and audit

REQ-SEC-G-008: A response MUST NOT disclose fields or concepts outside the product's reviewed
contract for that operation.

REQ-SEC-G-011: HTTP problem responses MUST use the product's documented bounded error contract and
MUST NOT contain credentials, source values, filesystem paths, or unbounded internal diagnostics.

REQ-SEC-G-013: Portable artifacts MUST NOT contain private keys, credential secrets, or audit
pseudonym secrets.

REQ-SEC-G-016: A request that requires durable audit MUST fail closed when the audit boundary is
unavailable.

REQ-SEC-G-018: Principal-scoped responses MUST use cache controls appropriate to their sensitivity.

## 3. Outbound access

Every outbound source request MUST derive its destination, method, path, credentials, transport
trust, timeout, redirect behavior, and response limits from reviewed product configuration.

## 4. Verification-key publication

An issuer MUST publish only the public verification material a relying party needs. Private signing
material remains under operator custody and MUST NOT appear in portable artifacts.

## 5. Audit

Every admitted request that touches protected records or assertions MUST produce the product's
documented audit records. A product whose contract requires durable audit MUST fail closed when it
cannot write them.

## 6. Error and disclosure posture

Problem responses MUST keep credentials, source values, filesystem paths, and unbounded internal
diagnostics out of the public response. Principal-scoped responses MUST use cache controls
appropriate to their sensitivity.

## 7. Replay-protection authority

No maintained Registry Stack resource server holds a replay table, replay reservation, or
persistent single-use record. A service that keeps no replay state MUST NOT claim to consume a
credential or prevent its reuse. Replay prevention belongs to the surrounding protocol or issuer
that creates and validates a one-time challenge.

REQ-SEC-G-018: A service that holds no replay state MUST NOT claim replay prevention or single-use
enforcement. It MAY validate signatures, expiry, audience, nonce equality, and other request
bindings, but those checks alone MUST NOT be described as consuming a credential.

## 8. Transport and outbound-call posture

Outbound calls MUST follow the fixed destination, transport trust, redirect, timeout, and response
bounds in reviewed configuration. Public errors MUST use the product's documented bounded error
contract.

## 9. Operator boundary

The operator owns identity issuance, key custody and rotation, transport termination, network
policy, audit storage and retention, database administration, monitoring, backup, recovery, and
incident response.

## Conformance

An implementation conforms when it satisfies every applicable requirement above.
