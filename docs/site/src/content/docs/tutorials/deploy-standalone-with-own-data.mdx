Use this guide to replace a synthetic development source with institution-owned data while
keeping source access in Registry Relay and every Registry Notary claim rooted in exactly one
Relay consultation.

## When to use this

Use the `http` template for a bounded HTTP source.
Use the `spreadsheet` template for a reviewed XLSX source.
OAuth and Rhai adapt the HTTP project and do not introduce another template or runtime.

Use a separate manual design review when the source cannot fit the bounded HTTP, Rhai, snapshot,
or spreadsheet capabilities.
Registryctl does not infer source authority, identity mappings, or disclosure policy.

## Before you start

You need:

- A project created with `registryctl init <directory> --template http` or
  `--template spreadsheet`
- A source-owner-approved non-production endpoint or workbook derivative
- A stable subject identifier and exact mapping from the request to one consultation input
- The smallest typed output required by each claim
- Synthetic observations for match, no match, and every meaningful failure
- Secret references for the selected environment, with values kept outside authored files

Do not copy production credentials, source responses, or personal data into fixtures or
generated evidence.

## Author the Relay source boundary

In the integration file, declare only the reviewed source authority:

- Source product and reviewed version context
- Authentication profile
- Exact method and bounded path pattern
- Response media type and byte ceiling
- Typed consultation inputs
- Closed minimized outputs
- Call, request-byte, source-byte, and deadline limits

For OAuth, the environment binds the token and source destinations plus client-credential secret
references.
Relay owns token acquisition, caching, authorization headers, Transport Layer Security,
redirects, source calls, and source audit.
Rhai receives no credential, token, token response, filesystem, process, or arbitrary network
authority.

## Keep every claim consultation-backed

Each evidence service must map the request to exactly one Relay consultation before declaring
claims:

```yaml
consultations:
  record:
    integration: reviewed-record
    input:
      record_id: request.target.identifiers.registry_record_id
claims:
  record-exists:
    cel: record.matched
    disclosure: predicate
  reviewed-status:
    output: record.status
    disclosure: value
```

The consultation name `record` is the only root used by these claims.
Do not add source-free, self-attested, delegated-attestation, or caller-defined fallback claim
paths.
If a claim has no reviewed source, keep it out of the Registry Stack evidence service.

## Prove the source contract offline

Author wholly synthetic fixtures for:

- Authorized match
- No match
- Ambiguity where the source can return several candidates
- Source rejection
- Subject mismatch
- Malformed and oversized response
- Timeout
- Authorization denial before source access
- Output minimization
- Malformed OAuth response when OAuth is enabled

Run all fixtures:

```sh
registryctl test
```

`test` is offline.
Fixture success proves behavior against the authored observations, not interoperability with a
live source.

Inspect only synthetic values when a focused trace is necessary:

```sh
registryctl test \
  --integration <integration-id> \
  --fixture <synthetic-fixture-id> \
  --trace
```

## Review the effective plan

Validate the complete authored environment:

```sh
registryctl check --explain
```

Review source destinations, secret consumers, request authority, subject binding, output types,
limits, claims, and disclosure.
The redacted plan must keep source authority in consultation Relay and claim evaluation in
Notary.

## Exercise the disposable product path

Use the project's declared default synthetic scenario:

```sh
registryctl dev --detach
registryctl dev smoke
registryctl dev down
```

The denial scenario must perform no token or source call.
The authorized scenario must perform only the declared bounded calls and report only minimized
claim identifiers.
This development trust, credential, and state material is disposable and cannot be promoted.

Testing an operator-bound non-production source requires explicit source-owner authorization.
It remains development evidence and does not replace offline negative fixtures or production
acceptance.

## Build and hand off product inputs

Build deterministic unsigned lane inputs:

```sh
registryctl build
```

Keep `relay-public`, `relay-consultation`, and `notary` separate.
The consultation Relay lane owns the source contract.
Notary owns claims and disclosure but receives no direct source credential or origin.

Independent product owners review and sign the affected lanes, then the operator assembles the
approved set.
Use [Run the generated single-node Compose package](../../operate/single-node-compose-behind-proxy/)
for the governed deployment handoff.

Do not add a direct source connection to Registry Notary. A combined Registry Stack project
compiles the source integration and consultation into Relay, then compiles Notary claims against
the pinned Relay contract. A Notary-only project may contain no claims.

Follow [Author an HTTP Registry Stack project](../author-registry-project/) to run offline fixtures,
inspect the redacted plan, and build separate unsigned product inputs. Package, sign, verify, and
activate each product input through its Config Bundle workflow.

The generated Compose package is portable and operator-adaptable.
Registryctl can certify only the managed or verified override-adapted boundary it understands.
Manual orchestration changes remain operator-owned.

## Troubleshooting

| Symptom | Cause | Fix |
| --- | --- | --- |
| A source call is rejected before dispatch | The request is outside the reviewed method, path, or budget. | Correct the adapter or narrowly change the authored source authority. |
| A claim lacks a consultation root | The claim has no Registry Stack evidence source. | Add one exact Relay consultation or remove the claim. |
| A secret appears in an authored or generated file | A secret value crossed its ownership boundary. | Stop, remove the exposed material, rotate it, and report the failure through the security process. |
| A fixture passes but the live source differs | Synthetic and interoperability evidence have been confused. | Keep the version `unverified` and run a separately authorized compatibility review. |
| The managed Compose model cannot express an operator need | The orchestration change is outside the binding schema. | Use an operator override or adapt a separate exported package and accept the reported ownership state. |
