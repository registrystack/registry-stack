Complete [Return a governed value](../return-a-governed-value/) before starting. You will reuse its
normalized project to observe both sides of the trust boundary: Evidence Gateway denies a purpose
outside the complete target grant, and the verifier rejects a response changed after signing.

## Start the local boundary

In another terminal, start the synthetic source:

```sh test-cwd="first-evidence-assertion/adult-status" test-background="http://127.0.0.1:8081/healthz"
python3 serve-source.py \
  --port 8081 \
  --token-file .generated/secrets/synthetic-source-token
```

In the project terminal, start a fresh Evidence generation:

```sh test-cwd="first-evidence-assertion"
cd adult-status
evidencectl dev start . \
  --target local-target.yaml \
  --evidence-port 18080 \
  --issuer-port 8082
```

```text test-excerpt
Evidence ready at http://127.0.0.1:18080
```

## Prepare one authorized request

Preparation records the exact verification expectations and obtains authorization for the
registered client. It performs no Evidence Gateway request and no source access.

```sh
evidencectl request prepare adult-status \
  --client tutorial-client \
  --purpose age-check \
  --subject subject:record-id=adult \
  --name refusal-check
```

## Change the purpose after preparation

Copy the prepared request and change only its purpose:

```sh
cp .evidence/requests/refusal-check/request.json unauthorized-request.json
python3 - <<'PY'
import json
from pathlib import Path

path = Path("unauthorized-request.json")
request = json.loads(path.read_text())
request["purpose"] = "undeclared-purpose"
path.write_text(json.dumps(request) + "\n")
PY
```

Send the changed body with the same valid authorization:

```sh
curl --silent --show-error \
  --config .evidence/requests/refusal-check/authorization.curl \
  --request POST \
  --url http://127.0.0.1:18080/v1/evidence \
  --header 'Content-Type: application/json' \
  --header 'Accept: application/jose+json' \
  --data-binary @unauthorized-request.json \
  --output unauthorized-response.json \
  --write-out 'HTTP %{http_code}\n'
```

```text test-expect
HTTP 403
```

Inspect only the public problem code:

```sh
python3 - <<'PY'
import json
from pathlib import Path

problem = json.loads(Path("unauthorized-response.json").read_text())
print(problem["code"])
PY
```

```text test-expect
evidence.denied
```

The response does not reveal the missing grant, source facts, selector, or credentials. Evidence
Gateway applies the target's complete grant and refuses the request before source access.

## Verify the unchanged control request

Send the unchanged prepared body and verify the signed response:

```sh
curl --silent --show-error --fail-with-body \
  --config .evidence/requests/refusal-check/authorization.curl \
  --request POST \
  --url http://127.0.0.1:18080/v1/evidence \
  --header 'Content-Type: application/json' \
  --header 'Accept: application/jose+json' \
  --data-binary @.evidence/requests/refusal-check/request.json \
  --output authorized-response.jws.json

evidencectl verify authorized-response.jws.json \
  --context .evidence/requests/refusal-check/verification.json \
  --output authorized-response.verified.json
```

```text test-expect
VERIFIED
```

This control request matches the definition, purpose, audience, representation, subject role,
selector profile, and value origin fixed by the complete grant.

## Change the signed response

Change one byte of the signed payload in a copy:

```sh
python3 - <<'PY'
import json
from pathlib import Path

source = Path("authorized-response.jws.json")
document = json.loads(source.read_text())
payload = document["payload"]
document["payload"] = ("A" if payload[0] != "A" else "B") + payload[1:]
Path("tampered-response.jws.json").write_text(json.dumps(document) + "\n")
PY
```

Verification must fail and must not create trusted output:

```sh test-exit="1"
evidencectl verify tampered-response.jws.json \
  --context .evidence/requests/refusal-check/verification.json \
  --output tampered-response.verified.json
```

```text test-expect
evidencectl: Evidence response verification failed
```

Application decisions must use verifier output, never an unverified response body.
