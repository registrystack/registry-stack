Connect Evidence Gateway to the public SMART Health IT FHIR R4 server through a bounded local
read-through adapter, then verify two minimum-disclosure answers as Selective Disclosure JSON Web
Token Verifiable Credential (SD-JWT VC) responses. You will return a coverage-record result for a
patient and a healthcare-provider result for an organization without disclosing either FHIR resource.

## Before you start

Complete [Get your first Evidence Gateway assertion](../first-evidence-assertion/) if you have not
used `evidencectl` before.

The previous version of this tutorial was run against the [SMART Health IT R4 open
endpoint](https://docs.smarthealthit.org/) at `https://r4.smarthealthit.org` on 10 August 2026.
The current commands are replayed against sanitized local FHIR responses. The public endpoint
contains synthetic data, and its operator can add, change, or reset records. Discovery and the
answers can therefore change. Do not send real patient identifiers or other sensitive data to it.

The example returns two narrow administrative facts:

| Subject | FHIR resource | Governed answer |
| --- | --- | --- |
| Patient and coverage record | `Coverage` | The selected record reports `active` and names the selected patient as beneficiary. |
| Healthcare establishment | `Organization` | The selected record reports `active` and has exactly one coding, with the standard organization-type system and code `prov`. |

An active Coverage record is not an independent insurance-eligibility decision. An active
healthcare-provider Organization is not facility accreditation or a professional licence. A real
deployment can rely on either answer only when its FHIR server is authoritative for that fact and
the governing rule has been reviewed.

## Copy the complete project

From the root of the matching source archive, copy the maintained FHIR example into a writable
directory. Generated keys, client material, and responses stay in that copy.

```sh
evidence --version
evidencectl --version
mkdir fhir-evidence-credentials
cp -R products/evidence/examples/fhir fhir-evidence-credentials/fhir-record-evidence
cd fhir-evidence-credentials
```

The versions must match. The copy contains one `evidence.yaml`, four named Functions, synthetic
fixtures, a `local-target.yaml`, and complete grants in `dev-authority.yaml`. It also contains the
reviewed FHIR OpenAPI subset and the two Python scripts used in this tutorial.

The project fixes each GET path, selector role, bounded response projection, private Facts, and
disclosed Output. The target binds the local connection and keys. Each grant permits the complete
request shape and both signed JWS and SD-JWT VC.

## Select live synthetic records

Run the discovery script from the tutorial directory:

```sh
python3 fhir-record-evidence/discover-records.py
```

```text test-expect
Coverage selector file: ready
Organization selector file: ready
```

The script selects one active Coverage whose beneficiary resolves to an existing Patient, and one
active Organization meeting the exact coding rule. It writes only their selectors to owner-only
`fhir-coverage-subjects.json` and `fhir-organization-subjects.json` files outside the project. It
prints neither identifiers nor resources.

If discovery cannot find coherent records, remove any selector files already created and try again
later. Do not weaken the beneficiary or coding checks to recover a former answer.

## Start the read-through adapter

In another terminal, enter `fhir-evidence-credentials` and start the source:

```sh test-cwd="fhir-evidence-credentials" test-background="http://127.0.0.1:8000/healthz"
python3 fhir-record-evidence/serve-source.py
```

Leave the terminal running. The adapter binds only to `127.0.0.1:8000`, permits the two resource
paths, requests `application/fhir+json`, and exposes the same body as `application/json`.
It denies redirects and ambient proxies, bounds responses, validates resource type and identity,
and suppresses request logging.

The numeric-loopback, credential-free connection is permitted only under local assurance. A
deployment needs reviewed authenticated HTTPS source transport. The scripts' test origin override
accepts only numeric-loopback HTTP and is used for the sanitized documentation replay; another
institution's FHIR server requires its own reviewed profile and authorization.

{/* Evidence: products/evidence/examples/fhir/serve-source.py, products/evidence/examples/fhir/discover-records.py, products/evidence/examples/fhir/source.openapi.yaml */}

## Prove the project before starting Evidence

Return to the project terminal and generate disposable local material:

```sh
cd fhir-record-evidence
python3 test_source.py
umask 077
evidencectl keygen signing --output-dir .generated/secrets
evidencectl keygen secret --output .generated/secrets/audit-hmac-key
evidencectl keygen secret --output .generated/secrets/subject-binding-hmac-key
evidencectl check . --target local-target.yaml
evidencectl test . --target local-target.yaml
evidencectl access client add fhir-client \
  --access-profile fhir-service \
  --generate-local-key
```

The Python check exercises the bounded adapter and discovery failures without network access.
`check` compiles the project and target without contacting the FHIR server. `test` evaluates the
declared synthetic success, false, mismatch, missing-data, bounds, and privacy cases offline.
This focused local suite does not establish production promotion readiness.

Only the `coverage-record` role fills the Coverage path. The patient selector reaches derivation,
where the beneficiary must equal that patient. A mismatch refuses the assertion rather than
signing a result about a different patient. The organization extraction checks each coding's
system and code together; unrelated coding entries cannot be combined into a provider match.

## Start Evidence Gateway

Use the target explicitly and select the tutorial ports:

```sh
evidencectl dev start . \
  --target local-target.yaml \
  --evidence-port 18080 \
  --issuer-port 8082
```

```text test-excerpt
Evidence ready at http://127.0.0.1:18080
Issuer ready at http://127.0.0.1:8082
```

Evidence Gateway now reads the selected resources through the adapter at request time. Source
projection removes unselected fields before extraction and derivation. Rust retains destination,
credentials, transport, response bounds, authorization, signing, and audit ownership.

## Request the patient coverage credential

Prepare a request bound to the patient and coverage-record roles. The selector file keeps
identifiers out of shell arguments and command output.

```sh
evidencectl request prepare fhir-coverage-status \
  --client fhir-client \
  --purpose coverage-record-verification \
  --subjects-file ../fhir-coverage-subjects.json \
  --response-format sd-jwt-vc \
  --name fhir-coverage-vc
```

Preparation fixes the nonce, expected definition revision, response format, and verifier pins
before any source read. Send the prepared body, then verify the exact response offline:

```sh
curl --silent --show-error --fail-with-body \
  --config .evidence/requests/fhir-coverage-vc/authorization.curl \
  --request POST \
  --url http://127.0.0.1:18080/v1/evidence \
  --header 'Content-Type: application/json' \
  --header 'Accept: application/dc+sd-jwt' \
  --data-binary @.evidence/requests/fhir-coverage-vc/request.json \
  --output fhir-coverage.sd-jwt \
  --write-out 'HTTP %{http_code}\n'

evidencectl verify fhir-coverage.sd-jwt \
  --context .evidence/requests/fhir-coverage-vc/verification.json \
  --output fhir-coverage.verified.json
```

```text test-expect
HTTP 200
VERIFIED
```

Inspect only the verified payload:

```sh
python3 -m json.tool fhir-coverage.verified.json
```

Its `supportedValues` carries the Boolean concept
`urn:example:concept:coverage-record-reports-active:v1`. Pseudonymous bindings identify the two
roles within the audience and purpose. Neither selected FHIR identifier, the beneficiary reference,
nor the unselected Coverage fields belong in the assertion.

## Request the healthcare-establishment credential

Prepare, request, and verify the second credential:

```sh
evidencectl request prepare fhir-healthcare-establishment \
  --client fhir-client \
  --purpose healthcare-establishment-verification \
  --subjects-file ../fhir-organization-subjects.json \
  --response-format sd-jwt-vc \
  --name fhir-healthcare-establishment-vc

curl --silent --show-error --fail-with-body \
  --config .evidence/requests/fhir-healthcare-establishment-vc/authorization.curl \
  --request POST \
  --url http://127.0.0.1:18080/v1/evidence \
  --header 'Content-Type: application/json' \
  --header 'Accept: application/dc+sd-jwt' \
  --data-binary @.evidence/requests/fhir-healthcare-establishment-vc/request.json \
  --output fhir-healthcare-establishment.sd-jwt \
  --write-out 'HTTP %{http_code}\n'

evidencectl verify fhir-healthcare-establishment.sd-jwt \
  --context .evidence/requests/fhir-healthcare-establishment-vc/verification.json \
  --output fhir-healthcare-establishment.verified.json
```

```text test-excerpt
HTTP 200
VERIFIED
```

The verified concept is `urn:example:concept:healthcare-provider-record-active:v1`. The assertion
does not repeat the organization's source identifier, name, address, contact details, or coding.
A verified `false` is the source's current administrative answer and does not justify changing
the rule to recover an earlier `true`.

## Inspect the audit and clean up

Stop the retained generation, inspect its last completed operation, and remove generated runtime
state:

```sh
evidencectl dev stop .
evidencectl audit show --last-operation
evidencectl dev clean .
```

The audit view names the authorized definition, purpose, requester pseudonym, and released Output.
It omits FHIR identifiers, source resources, credentials, and the Boolean value. The tutorial runner
stops the adapter; if you started it by hand, press `Ctrl+C` in its terminal.

Remove the selector files created by discovery:

```sh
cd ..
rm -f fhir-coverage-subjects.json fhir-organization-subjects.json
```

## Troubleshooting

| Symptom | Resolution |
| --- | --- |
| Discovery finds no coherent records | The public demo may have changed. Remove partial selector files and rerun later without weakening the relationship or coding rule. |
| The adapter cannot bind port `8000` | Check which process owns the port. Stop only an adapter you started, or use another environment with the documented ports available. |
| Evidence Gateway refuses a source result | The record may have changed identity or shape, exceeded a bound, redirected, timed out, or disappeared. Review the current source profile before changing the project. |
| A production FHIR server refuses access | Use a reviewed authenticated HTTPS adapter applying the institution's FHIR trust and authorization, commonly SMART Backend Services. The anonymous public-demo configuration is local only. |
