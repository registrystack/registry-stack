Registry Relay can publish a protected, read-only API over a spreadsheet
without copying the workbook into a second database. This tutorial starts the
synthetic public-works project, proves that anonymous and invalid callers are
denied, reads one minimized record as an authorized caller, and changes one
human-owned disclosure rule.

<QuickstartMeta
  outcome="A protected local API over a synthetic workbook, with an IPv4-loopback listener, owner-only local credentials, one denied request, and one authorized minimized result."
  time="About 15 minutes after Docker is installed"
  level="Local single-node"
  prerequisites={['Linux amd64', 'Docker Engine with Compose v2', 'curl'] }
/>

The workbook and caller identifiers in this tutorial are synthetic. Do not put
personal data or production credentials in this project.

## Install Registryctl

Download the versioned Registryctl 0.14.0 installer from the same release whose
artifacts it installs:

```sh
tag=v0.14.0
curl -fsSLO "https://github.com/registrystack/registry-stack/releases/download/${tag}/registryctl-${tag}-install.sh"
bash "./registryctl-${tag}-install.sh"
registryctl --version
```

The last command prints:

```text
registryctl 0.14.0
```

The quick installer trusts GitHub and TLS to deliver the installer and
`SHA256SUMS`. It then checksum-verifies the Registryctl binary and matching
image lock. It does not authenticate those files. Follow the tag-frozen
[release verification guide](https://github.com/registrystack/registry-stack/blob/v0.14.0/release/VERIFY.md)
when you need signature and provenance verification before installation.

The complete local beginner runtime is supported and release-gated on Linux
amd64. Registryctl also has Linux arm64 and macOS arm64 assets for CLI
authoring, validation, and build tasks, but the current release image lock
binds Linux amd64 images and does not advertise those hosts for this complete
runtime journey. This beginner path does not require or describe a source
build.

If your shell cannot find `registryctl`, add the install directory printed by
the installer to `PATH`.

## Create the canonical project

Create the spreadsheet starter in a new directory:

```sh
registryctl init --from spreadsheet --project-dir my-first-api
cd my-first-api
```

Registryctl reports a Registry Stack project created from the `spreadsheet`
starter and points to the first project check. The project is already runnable.
You do not copy a sample product configuration or edit generated Relay YAML.

The important paths have different owners:

| Path | Owner | What to do with it |
| --- | --- | --- |
| `registry-stack.yaml` | Project reviewer | Review service, purpose, scopes, filter, and projection |
| `entities/projects.yaml` | Project reviewer | Review the stable key and strict field types |
| `environments/local.yaml` | Environment owner | Bind the workbook, sheet, columns, and local caller identities |
| `data/public_works_projects.xlsx` | Source owner | Keep as a read-only input |
| `.registry-stack/build/local/` | Registryctl | Review generated product input; never edit it |
| `.registry-stack/runtime/local/` | Registryctl | Treat as private disposable runtime state |

The `.registry-stack/` directory is ignored by version control. On Unix,
Registryctl gives its runtime secret directories mode `0700` and raw
credential files mode `0600`.

## Run the required preflight

Validate the authored project, workbook, generated Relay input, locked image,
Docker Compose v2 provider, and closed local runtime:

```sh
registryctl doctor --profile local
```

The command runs the product-owned Relay validator through the digest-pinned
container. It does not need a host `registry-relay` executable. It also rejects
an unavailable Docker provider, a different runtime engine, an alternate
Compose file, a changed generated artifact, an unsafe listener, or an invalid
workbook before the API starts.

## Start the API

Start the exact compiled project:

```sh
registryctl start
```

After Relay becomes ready, Registryctl prints:

```text
Relay API:  http://127.0.0.1:4242
API docs:   http://127.0.0.1:4242/docs
```

The generated Compose document publishes only
`127.0.0.1:4242`. It mounts the compiled Relay configuration and workbook
read-only.

## Run the maintained checks

Run the complete local smoke set:

```sh
registryctl smoke
```

The checks report:

```text
PASS allowed public health check
PASS allowed match source is ready
PASS denied anonymous records request
PASS denied wrong local API key
PASS allowed matching principal returns one record
PASS wrong principal safely returns no match
```

The retained report is
`.registry-stack/runtime/local/smoke-results.json`. It contains check names,
paths, status classes, and pass states. It does not contain raw keys or
workbook rows.

## Make one denied request

Call the records route without a credential:

```sh
curl -i \
  -H "Data-Purpose: public-works-case-management" \
  http://127.0.0.1:4242/v1/datasets/projects/entities/projects/records
```

Relay returns `401 Unauthorized`. The API is ready, but the route does not
accept an anonymous caller.

## Make one allowed request

Load the private local caller keys into this shell:

```sh
set -a
. .registry-stack/runtime/local/secrets/local.env
set +a
```

Do not print, paste, or commit this file. Use the matching synthetic caller to
make the same request:

```sh
curl -i \
  -H "Authorization: Bearer $REGISTRYCTL_LOCAL_RELAY_MATCH_KEY_RAW" \
  -H "Data-Purpose: public-works-case-management" \
  http://127.0.0.1:4242/v1/datasets/projects/entities/projects/records
```

Relay returns `200 OK` with exactly one record because this local caller's
reviewed principal is bound to one synthetic project key. The record can
contain only the explicitly projected fields:

```text
project_id
district_code
sector
status
```

The wrong key is denied, and the maintained no-match caller receives an empty
result rather than another project's row.

## Inspect the human-owned boundary

Review the small authored files:

```sh
sed -n '1,120p' registry-stack.yaml
sed -n '1,120p' entities/projects.yaml
sed -n '1,120p' environments/local.yaml
```

Then ask Registryctl for the value-free effective plan:

```sh
registryctl check --project-dir . --environment local --explain
```

The project file owns the service purpose, scopes, filters, principal-bound
filter, and public projection. The entity file owns the strict schema and
primary key. The environment owns the physical workbook binding and local
caller identities. Registryctl owns the generated Relay input.

Spreadsheet fields compile as sensitive. A field is not externally readable
merely because it exists in the workbook or entity schema. It must also appear
in the reviewed service projection.

## Change one disclosure rule

Open `registry-stack.yaml`. Under the `projects-records` service, change:

```yaml
projection: [project_id, district_code, sector, status]
```

to:

```yaml
projection: [project_id, district_code, sector]
```

Restart through Registryctl so it validates and rebuilds the project:

```sh
registryctl restart
registryctl smoke
```

Repeat the allowed request. It still returns one record, but `status` is no
longer present. You changed reviewed human intent, not generated Relay YAML or
the workbook.

Restore `status` to the projection and restart if you want the starter's
original result.

## Stop and clean up

Stop the local runtime:

```sh
registryctl stop
```

This stops the container. It keeps the authored project and workbook. The
generated build and runtime directories are disposable and can be regenerated
from the authored project.

## Troubleshooting

| Symptom | Cause | Resolution |
| --- | --- | --- |
| `registryctl` is not found | The install directory is not on `PATH`. | Add the directory printed by the installer, usually `~/.local/bin`, to `PATH`. |
| The installer reports an unsupported platform | No Registryctl asset is published for that OS and CPU. | Use a published CLI platform for authoring, or Linux amd64 for this complete local runtime. |
| `doctor` cannot find Docker or Compose v2 | Docker Engine is absent or stopped. | Start Docker and confirm `docker info` and `docker compose version`, then retry. |
| `doctor` rejects the image lock | Registryctl and the image lock are absent, changed, or from different releases. | Rerun the same versioned installer. Do not substitute a mutable image tag or another release's lock. |
| `doctor` reports a workbook failure | The declared file, sheet, header, strict columns, types, formulas, or primary key failed validation. | Correct the human-owned workbook, entity, or environment file. Do not edit generated Relay input. |
| A generated artifact integrity check fails | A file under `.registry-stack/build/` or `.registry-stack/runtime/` was edited or replaced. | Remove the disposable generated closure and rerun `registryctl doctor`. Reapply intended changes only in human-owned files. |
| A request returns `401` | The credential is missing or invalid. | Load the generated local environment without printing it and use the matching local key. |
| A request returns `403` | The caller lacks the reviewed scope or purpose. | Review the service and environment bindings. Do not widen scopes merely to bypass the denial. |
| The documented recovery does not solve the problem | The local tutorial does not cover every host or workbook condition. | Open a [public Registry Stack issue](https://github.com/registrystack/registry-stack/issues/new/choose) with the command, stable code, operating system, and Registryctl version. Do not include keys, workbook rows, or private paths. |
