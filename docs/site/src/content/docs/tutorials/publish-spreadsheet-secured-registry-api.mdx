Create the maintained spreadsheet project, test its synthetic workbook contract offline, and run
the same protected Relay-to-Notary path in a disposable local environment.

  outcome="A tested spreadsheet project with a protected records policy, one consultation-backed claim service, and a disposable local runtime."

The workbook and identifiers in this tutorial are synthetic.
Do not put personal data or production credentials in this project.

## Before you start

Confirm the required tools:

```sh
registryctl --version
docker compose version
```

Registryctl reports its installed version without a network check.
Compose must report version 2.35.0 or later.

Start outside any existing Registry Stack project.

## Create the spreadsheet project

Initialize the tested spreadsheet template and enter the project:

```sh
registryctl init my-first-registry --template spreadsheet
cd my-first-registry
```

Initialization names the created project and prints `registryctl test` as the next action.
Registryctl copies the starter and workbook from the installed release.

The project separates authored decisions:

| Path | Decision you own |
| --- | --- |
| `data/public_works_projects.xlsx` | Synthetic source observations |
| `entities/projects.yaml` | Stable key, field types, and materialization limits |
| `integrations/project-record-snapshot/` | Exact snapshot lookup, minimized `status` output, and fixtures |
| `registry-stack.yaml` | Protected records policy plus one consultation-backed evidence service |
| `environments/local.yaml` | Workbook binding, default development scenario, and secret references |

The records API projects four reviewed fields and binds the required `project_id` filter to
authenticated principal identity.
The evidence service has one Relay consultation and releases two predicate claims.
Notary receives only the consultation's minimized `status` output, not a workbook row.

## Test the synthetic evidence

Run the complete offline fixture set:

```sh
registryctl test
```

A passing starter reports:

```text
Registry Stack test: passed for fictional-public-works-registry.
Fixtures: 7.
Next: registryctl dev
```

The fixtures distinguish:

- Project `pw_001`, which exists and has status `active`
- Project `PW-002`, which exists but does not satisfy the active-only policy
- Project `pw_999`, which is absent from the synthetic snapshot

No Docker container starts, no secret resolves, and no network request leaves the project.

Inspect the active-project fixture:

```sh
registryctl test \
  --integration project-record-snapshot \
  --fixture match \
  --trace
```

The trace may show fixture-authored synthetic values.
It demonstrates that Relay releases only `status` to Notary and that Notary evaluates
`project-record-exists` and `project-status-accepted`.

## Run the protected local path

Start the disposable runtime:

```sh
registryctl dev --detach
```

Registryctl validates the project, rebuilds stale inputs, checks the installed release lock, and
starts digest-locked public Relay, consultation Relay, Notary, and synthetic source workloads.
The command prints loopback endpoints plus the maintained request, smoke, log, and shutdown
actions.

Run the denial and authorized scenarios:

```sh
registryctl dev smoke
```

A passing spreadsheet report has this shape:

```text
Development smoke: passed.
  unauthorized: status=denied; passed=true; token_counter_delta=0; source_counter_delta=0; minimized_claim_ids=none
  authorized: status=authorized; passed=true; token_counter_delta=0; source_counter_delta=1; minimized_claim_ids=project-record-exists,project-status-accepted
```

The denial path performs no source call.
The authorized path performs one bounded spreadsheet snapshot lookup and reports only the two
claim identifiers.
The smoke report contains no raw credential, workbook row, or source-returned value.

## Inspect the authored policy

Open these files in a text editor:

| File | Decision to inspect |
| --- | --- |
| `entities/projects.yaml` | Primary key, field types, and source limits |
| `environments/local.yaml` | Workbook path, sheet, exact headers, and synthetic principals |
| `registry-stack.yaml` | Purpose, scopes, projection, principal-bound filter, consultation, and claims |

Ask Registryctl to explain the effective plan:

```sh
registryctl check --explain
```

`check` validates the workbook binding and authored policy without contacting a source or
resolving a secret.
Review the records projection, principal-bound filter, exact snapshot input, minimized output,
claims, and disclosure.

A workbook field is not externally readable merely because it exists in the workbook or entity
schema.
It must also appear in an explicitly reviewed projection or consultation output.

## Build the unsigned inputs

Build deterministic product-lane inputs:

```sh
registryctl build
```

The generated closure contains:

```text
.registry-stack/build/local/signing-inputs/relay-public
.registry-stack/build/local/signing-inputs/relay-consultation
.registry-stack/build/local/signing-inputs/notary
```

`build` does not create keys, sign product bundles, assemble an approved set, deploy, or activate
a product.
Keep the complete closure together and change authored files instead of generated product
configuration.

## Stop the disposable runtime

Stop the local workloads and remove the disposable trust, credentials, and state:

```sh
registryctl dev down
```

The authored project and workbook remain.

## What you built

You created a spreadsheet-backed project with a protected records policy and one
consultation-backed evidence service.
You proved authorization before source access, one bounded lookup, output minimization, and
predicate claim evaluation using synthetic data.

## Troubleshooting

| Symptom | Cause | Fix |
| --- | --- | --- |
| `registryctl` is not found | The verified installation directory is not on `PATH`. | Add the directory reported by the release installer. |
| `test` rejects the workbook fixture | The integration and synthetic expectation disagree. | Update the authored fixture or contract together. |
| `dev` rejects the release lock | Registryctl and the release lock are absent, changed, or from different releases. | Reinstall the verified release payload. |
| `dev` reports a port collision | Another process owns a required loopback port. | Stop the process or author distinct development ports. |
| Smoke reports source work on denial | Authorization did not stop the lookup. | Stop the runtime and report the failure through the repository security process. |
| A generated file differs after editing | A file under `.registry-stack/` was changed directly. | Remove the disposable generated closure and rerun Registryctl. |
