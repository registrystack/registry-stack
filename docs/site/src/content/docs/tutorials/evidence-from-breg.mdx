If you provide assertions from a registry, start with BReg and add Evidence when you
need a signed answer. Derive a small organization registry from PublicSchema, edit
a synthetic record, then add a narrow Evidence source without resetting the registry.

## Start with your model

In an empty working directory, save this selection as `organization-selection.yaml`.
It selects PublicSchema's Organization concept and name property. BReg adds a
required unique code; these are registry modeling choices, with no Evidence setup.

```yaml
apiVersion: registry.registrystack.org/breg-model-selection/v1alpha1
kind: ModelSelection
model: publicschema
modelVersion: "0.3.0"
registry:
  id: organization-registry
  title: Synthetic organization registry
entities:
  - concept: Organization
    id: record
    identifierField: code
    properties:
      - name: name
```

Create and start the registry:

```sh
bregctl init ./registry --from publicschema --selection ./organization-selection.yaml
bregctl dev ./registry
```

BReg starts PostgreSQL, Mint, and the registry. If defaults `8090`, `8091`, or `55432`
are occupied, choose unused ports on the first start instead:

```sh
bregctl dev ./registry --breg-port 8190 --mint-port 8191 \
  --database-port 55433
```

Use these ports only if they are available, or substitute another unused set.
Use your chosen BReg and Mint ports in the record requests below. Evidence setup
will obtain those retained endpoints directly. If startup fails, correct the
named prerequisite and retry; the error gives a private diagnostics path.

The generated operator and reader clients let you use the registry immediately.
This model declares no Evidence client, lookup grant, or selector profile.

## Create and edit a record

:::caution[Use synthetic data and keep credentials private]
The registry stores records in a local Docker volume. The following token header
and response files stay on your machine. Keep them out of version control and
support messages.
:::

Obtain an operator token:

```sh
umask 077
credentials=registry/.breg/dev/credentials/operator
mint token --url http://127.0.0.1:8091/token \
  --client-id "$(cat "$credentials/client-id")" --key "$credentials/assertion-key.jwk" \
  | sed 's/^/Authorization: Bearer /' > authorization.header
curl --silent --show-error --fail-with-body \
  --header @authorization.header --header 'Content-Type: application/json' \
  --header 'Idempotency-Key: composition-create-1' \
  --data '{"data":{"code":"SYNTHETIC-ORG-001","name":"Earlier name"}}' \
  --output created.json \
  'http://127.0.0.1:8090/v1/records/records?accessProfile=operator'
```

Read the new record and capture its ETag before changing its name:

```sh
record_id=$(python3 -c 'import json; print(json.load(open("created.json"))["data"]["recordIdentifier"])')
curl --silent --show-error --fail-with-body --header @authorization.header \
  --dump-header record.headers --output before-edit.json \
  "http://127.0.0.1:8090/v1/records/records/$record_id?accessProfile=operator"
record_etag=$(awk 'tolower($1) == "etag:" {print $2}' record.headers | tr -d '\r')
curl --silent --show-error --fail-with-body --header @authorization.header \
  --header 'Content-Type: application/json-patch+json' \
  --header 'Idempotency-Key: composition-edit-1' --header "If-Match: $record_etag" \
  --request PATCH --data '[{"op":"replace","path":"/data/name","value":"Synthetic Works"}]' \
  --output edited.json \
  "http://127.0.0.1:8090/v1/records/records/$record_id?accessProfile=operator"
python3 -m json.tool edited.json
```

Check that the identifier is unchanged and the name is `Synthetic Works`. Save this response
for comparison after setup. If a request returns `401`, repeat the token command.
If a concurrent edit changes the ETag, read the record again before deciding whether
to retry the edit.

## Connect Evidence after using the registry

Stop normally so records, audit history, and existing identities remain:

```sh
bregctl dev stop ./registry
evidencectl source add ./registry --project ./evidence \
  --source-id registry-name --selector-profile by-code
```

Choose entity `record`, the unique selector field `code`, and readable fact `name`.
Choose **All records in this entity** explicitly for these synthetic records.
The two flags name the source and selector used by the sample question below.
The command reports the proposed source authority and applies nothing. A supplied
code is not a row authorization rule; for institutional data choose the required
row boundary. When the report matches your choices, run the same command with
`--apply` to perform the connection:

```sh
evidencectl source add ./registry --project ./evidence \
  --source-id registry-name --selector-profile by-code --apply
```

This one setup operation prepares a lookup-only source client, exports its
contract, imports it into Evidence, copies the dedicated credentials privately,
and creates `evidence/targets/local` using the retained local endpoints. It resolves
local paths itself. Review the resulting project files before serving the source.
No operator credential becomes the Evidence source credential.

Do not use `--remove` during setup: it discards records. The source change creates
a successor registry package, activated when you restart. Existing record IDs,
revisions, values, and client identities remain; the package revision advances to
carry the explicitly chosen source authority.

## Add the sample question

Source setup does not invent business questions. Download the
[BReg and Evidence teaching files](../../examples/breg-evidence-starter.tar.gz)
for a reviewed example that asks whether the organization has a nonempty name:

```sh
mkdir teaching-inputs
tar -xzf breg-evidence-starter.tar.gz -C teaching-inputs
cp -R ./teaching-inputs/named-starter/questions \
  ./teaching-inputs/named-starter/derivations \
  ./teaching-inputs/named-starter/fixtures ./evidence/
evidencectl fixtures run --project ./evidence --target ./evidence/targets/local --local
```

The 11 synthetic cases check the name-present answer, empty name, absent facts,
identity mismatches, source failures, and disclosure refusals. A missing or null
name is unavailable evidence; an empty name gives `false`. `--local` rehearses generated local caller authority with the target source
connection. Fixtures use recorded responses, so BReg can remain stopped. If a case fails, rerun with `--explain` and
correct the named question or source before proceeding.

To open the common parent in VS Code or Zed, generate workspace-relative mappings:

```sh
evidencectl tooling editor --project ./evidence --workspace .
```

Customized settings are preserved with copyable mappings on conflict. Configure
`evidencectl tooling language-server` separately for Registry navigation; schema
mappings do not install it. Ordinary sibling YAML remains outside the mappings,
though the YAML server's suffix matching can also match another nested
`evidence/questions/` directory.

## Restart and read the retained record

Activate the prepared source package and resume the existing registry:

```sh
bregctl dev start ./registry
```

Renew the operator token using the earlier command, then read your record:

```sh
curl --silent --show-error --fail-with-body --header @authorization.header \
  --output after-setup.json \
  "http://127.0.0.1:8090/v1/records/records/$record_id?accessProfile=operator"
python3 -m json.tool after-setup.json
```

Compare the record identifier, revision identifier, and domain data with
`edited.json`. They remain the same. The successor package adds the reviewed
lookup permission without replacing the record.

## Start Evidence and verify an answer

Start the local caller rehearsal using the configured source connection:

```sh
cd evidence
evidencectl dev --target ./targets/local --detach
evidencectl request prepare record-named --purpose record-verification \
  --subject subject@breg-8-registry-6-record-7-by-code:code=SYNTHETIC-ORG-001 \
  --name by-code
```

Here `dev --target` uses only the local target's source connections and outbound
TLS settings. It generates the usual disposable local Evidence caller, issuer
and authority. It is a local integration rehearsal; it does not serve the full
target's caller governance. Production targets are refused by this command.

If Evidence's default ports `8080` and `8081` are occupied, start with
`evidencectl dev --target ./targets/local --detach --evidence-port 8180
--mint-port 8181` instead. Use that Evidence port in each curl command in this
section. BReg's two ports
are separate and stay as configured in the source connection.

Send the prepared request and verify its response against the expectations
recorded before the request:

```sh
curl --silent --show-error --fail-with-body \
  --config .evidence/requests/by-code/authorization.curl \
  --request POST --url http://127.0.0.1:8080/v1/evidence \
  --header 'Content-Type: application/json' \
  --header 'Accept: application/jose+json' \
  --data-binary @.evidence/requests/by-code/request.json \
  --output by-code.jws.json
evidencectl verify by-code.jws.json \
  --context .evidence/requests/by-code/verification.json --output by-code.verified.json
```

A refusal exits `curl` nonzero (from `--fail-with-body`), and `by-code.jws.json`
holds the returned Evidence problem body instead of a signed response, for
example an `evidence/unavailable` problem for a missing record or a record
whose name is absent or null. `evidencectl verify` fails closed on any signature, audience or nonce
mismatch rather than accepting a partially valid response, and writes no
output file when it refuses.

Open `by-code.verified.json` only after verification succeeds. For this named
synthetic record, it contains a `true` value for the `named` answer and an
opaque subject binding. It must not disclose the code or
organization name.

The authorization file contains a short-lived credential. Keep it private. If a
token or verification context expires, prepare a request with a fresh name.

## Stop and resume without reseeding records

From `evidence/`, stop both services and restart the registry:

```sh
evidencectl dev stop
bregctl dev stop ../registry
bregctl dev start ../registry
```

Restart Evidence with the same ports you selected earlier. Evidence does not retain
port overrides between starts. For the default ports:

```sh
evidencectl dev --target ./targets/local --detach
```

If you used the alternate ports `8180` and `8181`, repeat both flags instead:

```sh
evidencectl dev --target ./targets/local --detach \
  --evidence-port 8180 --mint-port 8181
```

Substitute your own pair if you selected different ports. Repeat these flags after
`dev clean` as well.

BReg retains its database, generated identities, audit history and seed
checkpoints. Existing record edits survive this restart. A lost checkpoint is
replayed through the same idempotent create request, so seeding does not overwrite
an edited record. BReg still refuses unrelated authored package or client changes against a retained
session. Guided source preparation is a narrow reviewed addition; it is not a
general model migration.

To edit Evidence questions or imported sources between local generations, stop
Evidence and run `evidencectl dev clean`, then start again. Clean preserves
authored files, project secrets and retained requests. It removes only the stopped
local generation. Review the completed audit with `evidencectl audit show
--last-operation` after stopping its writer.

## Keep the contract separate from record values

Editing record values needs no source re-export. When you change a consumed lookup
contract, export to a fresh directory, review `evidencectl source diff`, then run
`evidencectl source update`, fixtures, and build. Choose a fresh candidate output
and match its runtime path. A shared folder grants no source authority, selects
no production target, and deploys neither component.

The local `dev` run rehearses the source connection with generated caller authority.
For a complete production target and coordinated cutover, follow
[Deploy Evidence with a BReg source](../deploy-evidence-from-breg/).

Stop both owned service groups before leaving the exercise, from `evidence/`:

```sh
evidencectl dev stop
bregctl dev stop ../registry
```
