You are the operator who received the proved `adult-status` project from
[Prove an Evidence Gateway project](../prove-an-evidence-project/). Here you bind it to your
environment, package it into a candidate whose digest you can repeat, activate it on the target
host, and serve it with the listener and audit path you chose.

## What you need

You need the proved project and matching `evidence` and `evidencectl` binaries. Download the
installer with the release `SHA256SUMS`, check it, then run it:

```sh test-skip="the gate supplies the binaries"
tag="<released-tag>"
base="https://github.com/registrystack/registry-stack/releases/download/$tag"
curl -fsSLO "$base/evidencectl-$tag-install.sh"
curl -fsSLO "$base/SHA256SUMS"
sha256sum --check --strict --ignore-missing SHA256SUMS
bash "evidencectl-$tag-install.sh"
evidence --version
evidencectl --version
```

The installer checks every binary against the same `SHA256SUMS` before installing. Neither check
proves who published the release; the
[release verification procedure](https://github.com/registrystack/registry-stack/blob/main/release/VERIFY.md)
authenticates `SHA256SUMS` itself.

## Write the deployment target

The assertion provider owns the Evidence project: `assertionDefinitions`, `sources`, `functions`,
`selectorProfiles`, `outputs`, and each `grantCeiling`. You own the environment. From the
directory that holds `adult-status`, create your target from the project's local settings:

```sh test-cwd="first-evidence-assertion"
evidencectl target new ./deploy-target --settings adult-status/local-target.yaml
```

```text test-expect
Created Evidence target ./deploy-target
```

`deploy-target/target.yaml` is the deployment target, the operator's file: it names the
project, the authority file that grants callers access, and every host binding.

```yaml title="deploy-target/target.yaml" test-excerpt="deploy-target/target.yaml"
id: local
project: standalone-evidence
package:
  root: .generated/package
authority: dev-authority.yaml
```

`target new` refuses an existing destination. Generate a signing key for this replay:

```sh
evidencectl keygen signing --output-dir deploy-target/secrets \
  --public-output deploy-target/public-keys/signing.jwk.json
```

```text test-excerpt
wrote deploy-target/secrets/signing-p256-private-jwk
wrote deploy-target/public-keys/signing.jwk.json
```

`keygen` writes private material only to owner-only files, never to standard output. Production
signs through Vault or OpenBao Transit instead; the next page moves the `signer` there.

Point the package root, the secret root, the public key, and the audit path at directories you
chose. Relative paths resolve against the target directory:

```diff lang="yaml" title="deploy-target/target.yaml" test-edit
 package:
-  root: .generated/package
+  root: package
```

```diff lang="yaml" title="deploy-target/target.yaml" test-edit
 secretProviders:
   file:
-    root: .generated/secrets
+    root: secrets
 signer:
   type: local-jwk
   algorithm: ES256
   privateKeyRef: secret:file/signing-p256-private-jwk
-  publicJwkFile: .generated/secrets/signing-p256-public.jwk.json
+  publicJwkFile: public-keys/signing.jwk.json
```

```diff lang="yaml" title="deploy-target/target.yaml" test-edit
 audit:
-  path: .generated/audit/evidence.jsonl
+  path: audit/evidence.jsonl
```

The listener binds a loopback or private address unless `listener.networkExposure` says
`container-private`. Read back what the target binds:

```sh
evidencectl target explain deploy-target/target.yaml adult-status
```

```text test-expect
Target: local
Project: standalone-evidence
Authority: dev-authority.yaml
Access profiles: 1
```

`target explain` runs offline and resolves no secret.

## Check and package

Ask whether the target is fit for production:

```sh test-exit="1"
evidencectl check adult-status --target deploy-target/target.yaml --production
```

```text test-expect
error[evidence.target.production-assurance-required] deployment-target deploy-target/target.yaml:/assuranceProfile: --production requires production or evidence-grade target assurance
  next: Correct the selected project or target artifact and rerun check.
```

This target declares no production `assuranceProfile`, which a local key file cannot meet, so it
stays a replay target. Package it into a new directory outside the project:

```sh
evidencectl package adult-status --target deploy-target/target.yaml --output candidate
```

```text test-expect
Package digest: sha256:<digest>
Package: candidate/bundle
Runtime: candidate/runtime.yaml
Authority: candidate/compiled-authority.yaml
Provision secret:file/audit-hmac-key
Provision secret:file/subject-binding-hmac-key
Provision secret:file/synthetic-source-token
Target runtime paths and deployment secret material remain unverified until `evidencectl doctor --runtime-config candidate/runtime.yaml`.
```

`candidate` is the [deployment candidate](../../reference/glossary/#deployment-candidate). The package digest identifies its immutable `bundle/`:
the same project and target produce the same digest, so record it. Before writing, `package`
checks the bundle and runs every fixture through the `evidence` binary it finds through
`EVIDENCE_BIN` or on `PATH`, so you need no separate `evidencectl test`. It runs offline,
contacts no source, token issuer, or signer, and leaves the project unchanged.

```sh
find candidate -maxdepth 2 | LC_ALL=C sort
```

```text test-expect
candidate
candidate/bundle
candidate/bundle/SHA256SUMS
candidate/bundle/adapters
candidate/bundle/codelists
candidate/bundle/derivations
candidate/bundle/evidence.yaml
candidate/bundle/fixtures
candidate/bundle/public-keys
candidate/bundle/schemas
candidate/compiled-authority.yaml
candidate/runtime.yaml
```

`bundle/` holds no secret. `runtime.yaml` records the target's paths as absolute paths, including
`authority.root` and `authority.target`, so write a target for another host with that host's paths.

## Activate on the target host

Only the candidate travels to the target host; the editable project stays where you built it.
Here both hosts are this directory. Provision each secret the summary named beneath
`secretProviders.file.root`, and install `bundle/` at the package root:

```sh
evidencectl keygen secret --output deploy-target/secrets/audit-hmac-key
evidencectl keygen secret --output deploy-target/secrets/subject-binding-hmac-key
evidencectl keygen token --output deploy-target/secrets/synthetic-source-token
cp -R candidate/bundle deploy-target/package
```

```text test-expect
wrote deploy-target/secrets/audit-hmac-key
wrote deploy-target/secrets/subject-binding-hmac-key
wrote deploy-target/secrets/synthetic-source-token
```

Activate the authority against the installed package. The runtime file must be named by
an absolute path:

```sh
evidence authority activate --runtime-config "$PWD/candidate/runtime.yaml" \
  --document candidate/compiled-authority.yaml
```

```text test-expect
ACTIVATED sha256:<revision> sha256:<snapshot> sequence=1
```

Activation records the authority revision and snapshot for the next start; a running process
keeps its snapshot until restart. Check the installed package:

```sh
evidence check --runtime-config "$PWD/candidate/runtime.yaml"
```

```text test-expect
Evidence package sha256:<digest> passed check (4 requirements)
0 errors, 0 warnings in 28 files
```

The digest matches the one `package` printed. This check reads no secret and contacts no network
service. Then prove the startup dependencies:

```sh test-skip="needs the token issuer and source running and reachable from this host"
evidencectl doctor --runtime-config "$PWD/candidate/runtime.yaml"
```

`doctor` checks the signer, every source, and the token issuer as startup does, and refuses with
`evidence.deployment.dependency-unavailable` while one is unreachable. It opens no listener, sends
no evidence request, and appends no application audit event.

## Start serving

```sh test-skip="the gate starts no production listener"
evidence serve --runtime-config "$PWD/candidate/runtime.yaml"
```

Route traffic through your TLS front only after `GET /ready` succeeds. To send one synthetic
request, keep the access token in an owner-only curl configuration, never on a command line:

```sh test-skip="needs the running service and an access token"
umask 077
install -m 600 /dev/null "<owner-only-curl-config>"
```

Put `header = "Authorization: Bearer <access-token>"` in it through your secret-management path,
then send the request with `curl --config "<owner-only-curl-config>"` and delete the file. Confirm
that the request's `access-attempt` and `disclosure-release` entries, which share one
`correlation`, reached the deployment's append-only audit store, not only `audit.path`.

## Revision and digest

Editing the deployment target, for example to move a source endpoint, changes the package digest
but no definition's `configurationRevision`, which moves only with the definition's semantics.
[How Evidence Gateway works](../../explanation/how-evidence-works/) explains both.
