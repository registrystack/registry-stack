You are the operator who puts the proved `adult-status` project in front of real callers: bind it
to a host, package it into a candidate whose digest you can repeat, activate it, and prove its
dependencies before it opens a listener.

## Before you begin

You continue the `adult-status` project from
[Your first assertion](../first-evidence-assertion/). The deployment reaches the same synthetic
source on port 8081 and trusts the same local token issuer on port 8082. If you stopped the
source, start it again in another terminal:

```sh test-cwd="first-evidence-assertion/adult-status" test-background="http://127.0.0.1:8081/healthz"
python3 serve-source.py \
  --port 8081 \
  --token-file .generated/secrets/synthetic-source-token
```

If you stopped the development session, start it again from the project directory, so the token
issuer answers on `8082`:

```sh test-skip="the session from Your first assertion is still running"
evidencectl dev start . \
  --target local-target.yaml \
  --evidence-port 18080 \
  --issuer-port 8082
```

## Write the deployment target

The assertion provider owns the Evidence project: `assertionDefinitions`, `sources`, `functions`,
`selectorProfiles`, `outputs`, and each `grantCeiling`. You own the environment, in a
[deployment target](../../reference/glossary/#target) kept beside the project. Step out of `adult-status` and create one from the project's local
settings:

```sh test-cwd="first-evidence-assertion/adult-status"
cd ..
evidencectl target new ./deploy-target --settings adult-status/local-target.yaml
```

```text test-expect
Created Evidence target ./deploy-target
```

`deploy-target/target.yaml` names the project, the authority file that grants callers access, and
every host binding. `target new` refuses an existing destination.

```yaml title="deploy-target/target.yaml" test-excerpt="deploy-target/target.yaml"
id: local
project: standalone-evidence
package:
  root: .generated/package
authority: dev-authority.yaml
```

Give the deployment its own signing key:

```sh
umask 077
evidencectl keygen signing --output-dir deploy-target/secrets \
  --public-output deploy-target/public-keys/signing.jwk.json
```

```text test-excerpt
wrote deploy-target/secrets/signing-p256-private-jwk
wrote deploy-target/public-keys/signing.jwk.json
```

`keygen` writes private material only to owner-only files, never to standard output. Production
signs through Vault or OpenBao Transit instead; the next tutorial moves the `signer` there.

Point the package root, secret root, public key, and audit path at this host's directories,
relative to the target directory:

```diff lang="yaml" title="deploy-target/target.yaml" test-edit
 package:
-  root: .generated/package
+  root: package
```

```diff lang="yaml" title="deploy-target/target.yaml" test-edit
 secretProviders:
   file:
-    root: .generated/secrets
+    root: secrets
 signer:
   type: local-jwk
   algorithm: ES256
   privateKeyRef: secret:file/signing-p256-private-jwk
-  publicJwkFile: .generated/secrets/signing-p256-public.jwk.json
+  publicJwkFile: public-keys/signing.jwk.json
```

```diff lang="yaml" title="deploy-target/target.yaml" test-edit
 audit:
-  path: .generated/audit/evidence.jsonl
+  path: audit/evidence.jsonl
```

The development session holds `18080`, so listen on `18090`, changing the bind and the public
origin together:

```diff lang="yaml" title="deploy-target/target.yaml" test-edit
-  publicOrigin: http://127.0.0.1:8080
+  publicOrigin: http://127.0.0.1:18090
   trustDomain: urn:example:trust:standalone-evidence
 listener:
-  bind: 127.0.0.1:8080
+  bind: 127.0.0.1:18090
```

The bind must be a loopback or private address unless `listener.networkExposure` says
`container-private`. Read back what the target selects, offline:

```sh
evidencectl target explain deploy-target/target.yaml adult-status
```

```text test-expect
Target: local
Project: standalone-evidence
Authority: dev-authority.yaml
Access profiles: 1
```

## Check and package

Ask whether the target is fit for production:

```sh test-exit="1"
evidencectl check adult-status --target deploy-target/target.yaml --production
```

```text test-expect
error[evidence.target.production-assurance-required] deployment-target deploy-target/target.yaml:/assuranceProfile: --production requires production or evidence-grade target assurance
  next: Correct the selected project or target artifact and rerun check.
```

A local key file cannot meet a production `assuranceProfile`, so this target declares none and
stays a rehearsal. Package it into a new directory outside the project:

```sh
evidencectl package adult-status --target deploy-target/target.yaml --output candidate
```

```text test-expect
Package digest: sha256:<digest>
Package: candidate/bundle
Runtime: candidate/runtime.yaml
Authority: candidate/compiled-authority.yaml
Provision secret:file/audit-hmac-key
Provision secret:file/subject-binding-hmac-key
Provision secret:file/synthetic-source-token
Target runtime paths and deployment secret material remain unverified until `evidencectl doctor --runtime-config candidate/runtime.yaml`.
```

`candidate` is the [deployment candidate](../../reference/glossary/#deployment-candidate). The
package digest identifies its immutable `bundle/`: the same project and target produce the same
digest, so record it. Editing the target, even its port, changes the digest but no definition's
`configurationRevision`, which moves only with the definition's semantics
([How Evidence Gateway works](../../explanation/how-evidence-works/)). `package` first checks the bundle and runs every fixture through the
`evidence` binary on `PATH` (or `EVIDENCE_BIN`), contacting no source, issuer, or signer.

List the candidate to see the three parts that travel to the host:

```sh
ls candidate
```

```text test-expect
bundle
compiled-authority.yaml
runtime.yaml
```

`bundle/` is the package the digest names, and it holds no secret. `compiled-authority.yaml` is
the access authority you activate next. `runtime.yaml` records the target's paths as absolute paths, so write
a target for another host with that host's paths.

## Activate on the target host

Only the candidate travels to the target host, here this same directory. Provision each secret the summary named beneath
`secretProviders.file.root`. The source token is the source owner's to issue, and the running
source accepts only the one it was started with, so copy that one:

```sh
evidencectl keygen secret --output deploy-target/secrets/audit-hmac-key
evidencectl keygen secret --output deploy-target/secrets/subject-binding-hmac-key
cp adult-status/.generated/secrets/synthetic-source-token deploy-target/secrets/
cp -R candidate/bundle deploy-target/package
```

```text test-expect
wrote deploy-target/secrets/audit-hmac-key
wrote deploy-target/secrets/subject-binding-hmac-key
```

Activate the authority against the installed package:

```sh
evidence authority activate --runtime-config candidate/runtime.yaml \
  --document candidate/compiled-authority.yaml
```

```text test-expect
ACTIVATED sha256:<revision> sha256:<snapshot> sequence=1
```

Activation records the authority snapshot for the next start; a running process keeps its own
until restart. Check the installed package, which reads no secret and contacts no network service:

```sh
evidence check --runtime-config candidate/runtime.yaml
```

```text test-expect
Evidence package sha256:<digest> passed check (4 requirements)
0 errors, 0 warnings in 28 files
```

The digest matches the one `package` printed. Then prove the startup dependencies: `doctor`
resolves every secret, proves the signer, opens the audit log, and fetches the token issuer's
keys, as startup does. Name the runtime file by absolute path:

```sh
evidencectl doctor --runtime-config "$PWD/candidate/runtime.yaml"
```

```text test-excerpt
Dependency preflight passed for <runtime-file>
```

An unreachable dependency refuses with `evidence.deployment.dependency-unavailable`. `doctor`
opens no listener, sends no evidence request, appends no application audit event, and does not call the
source.

## Start serving

Start the service in a terminal of its own; it logs `evidence service listening` with the
package digest:

```sh test-skip="runs in the foreground until stopped"
evidence serve --runtime-config "$PWD/candidate/runtime.yaml"
```

Route traffic through your TLS front only after `GET http://127.0.0.1:18090/ready` succeeds. To
send one synthetic request, keep the access token in an owner-only curl configuration, never on a
command line:

```sh test-skip="needs the running service and an access token"
umask 077
install -m 600 /dev/null "<owner-only-curl-config>"
```

Put `header = "Authorization: Bearer <access-token>"` in it through your secret-management path,
then send the request with `curl --config "<owner-only-curl-config>"` and delete the file. In
production only, where the deployment ships `audit.path` to an append-only audit store, confirm
that the request's `access-attempt` and `disclosure-release` entries, which share one
`correlation`, reached that store.
