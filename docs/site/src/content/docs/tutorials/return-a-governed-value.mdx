Complete [Get your first Registry Evidence assertion](../first-evidence-assertion/) before starting.
You will reuse that normalized project to return a controlled region value. The project declares
the complete set of possible values, so a Function cannot invent a new category at runtime.

## Review the governed boundary

Enter the copied project:

```sh test-cwd="first-evidence-assertion"
cd adult-status
```

`evidence.yaml` already declares the `residence-region` definition. Its `region` output is a
`controlled-category` restricted to `north` or `south`. The named `derive-residence-region`
Function may choose only one of those values. The `standalone-service` target profile grants the
complete request shape: definition, purpose, audience source, representation, subject role,
selector profile, and value origin.

Prove the unchanged project and target before running them:

```sh
evidencectl check . --target local-target.yaml
evidencectl test . --target local-target.yaml
```

## Start the local boundary

In another terminal, start the synthetic source from the project directory:

```sh test-cwd="first-evidence-assertion/adult-status" test-background="http://127.0.0.1:8081/healthz"
python3 serve-source.py \
  --port 8081 \
  --token-file .generated/secrets/synthetic-source-token
```

Back in the first terminal, start a fresh generation on the alternate Evidence port:

```sh
evidencectl dev start . \
  --target local-target.yaml \
  --evidence-port 18080 \
  --issuer-port 8082
```

```text test-excerpt
Evidence ready at http://127.0.0.1:18080
```

## Request the controlled value

Prepare the request with the existing tutorial client and the definition's declared purpose:

```sh
evidencectl request prepare residence-region \
  --client tutorial-client \
  --purpose residence-check \
  --subject subject:record-id=adult \
  --name residence-region
```

Send the request, then verify the signed response before inspecting it:

```sh
curl --silent --show-error --fail-with-body \
  --config .evidence/requests/residence-region/authorization.curl \
  --request POST \
  --url http://127.0.0.1:18080/v1/evidence \
  --header 'Content-Type: application/json' \
  --header 'Accept: application/jose+json' \
  --data-binary @.evidence/requests/residence-region/request.json \
  --output residence-region.jws.json

evidencectl verify residence-region.jws.json \
  --context .evidence/requests/residence-region/verification.json \
  --output residence-region.verified.json
```

```text test-expect
VERIFIED
```

The synthetic adult record produces `north`. Read that value only from
`residence-region.verified.json`. The assertion excludes the source record's birth date and private
address canary because neither is an output of this definition.

## Clean up

```sh
evidencectl dev stop .
evidencectl audit show --last-operation
evidencectl dev clean .
```

The audit view records that the controlled output was released without printing its value or the
selector. The tutorial runner stops the synthetic source. If you started it by hand, press
`Ctrl+C` in its terminal.
