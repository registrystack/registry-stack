You will submit one ReviewRequest as a producer, decide it as staff, and read the answer as the
producer. The request carries its own snapshot, so no source registry is needed.

## Install Registry Stack

Download one exact `rstack-vX.Y.Z-install.sh` and the verification material from the same Registry
Stack release. Follow the
[release verification procedure](https://github.com/registrystack/registry-stack/blob/main/release/VERIFY.md)
before running the installer. From the verified release directory, install the `casework`
component:

```sh test-skip="uses a downloaded, independently verified release installer"
tag="vX.Y.Z"
bash "rstack-${tag}-install.sh" casework
rstack casework --version
```

The managed installation exposes `rstack` on your `PATH`. The `casework` component supplies the
Casework runtime and its command-line tools from the same release.

{/* Evidence: crates/registry-rstack/README.md; crates/registry-rstack/install.sh; release/VERIFY.md. */}

## Create the project

Create a project from the standalone template and work inside it:

```sh
mkdir -p tutorial-work
rstack casework init tutorial-work/casework --template standalone-decision
cd tutorial-work/casework
```

```json test-excerpt
{
  "command": "init",
  "status": "complete",
  "created": "tutorial-work/casework",
  "next": "Run caseworkctl check, test and types, then caseworkctl dev start.",
  "template": "standalone-decision"
}
```

## Check what the policy allows

The project declares one [ReviewPolicy](../../reference/glossary/#review-policy), `decision`: who
may ask, which team answers, and the outcomes allowed. Check it offline and run its fixture:

```sh
rstack casework check .
rstack casework test .
```

```json test-excerpt
{
  "policyBindings": [
    {"digest": "sha256:<digest>", "id": "decision", "version": "1"}
  ]
}
```

The digest pins the policy's behavior. To read what that behavior is, explain it:

```sh
rstack casework explain .
```

```json test-excerpt
{
  "contextCustody": "admitted bounded snapshot",
  "refusals": [
    "untrusted producer",
    "policy binding mismatch",
    "concealed source",
    "changed subject or contract",
    "stale task revision",
    "ineligible reviewer"
  ]
}
```

Casework keeps the snapshot the producer sends and refuses each listed case.


## Submit a ReviewRequest

Save the request. It names the policy, the subject under review, and the snapshot a reviewer will
read:

```json title="request.json" test-file
{
  "policy": {"id": "decision"},
  "subject": {
    "source": "standalone",
    "type": "batch",
    "id": "LIC-2026-0041",
    "version": "1",
    "digest": "sha256:6a3167d79ae3308448b24f2c9c0b9ac1cf116a7ad8be0c167c7e8660e43662bb"
  },
  "requesterReference": "LIC-2026-0041",
  "context": {
    "mode": "submitted",
    "snapshot": {"reference": "LIC-2026-0041", "summary": "Review licence batch LIC-2026-0041"}
  }
}
```

The subject digest is the producer's own fingerprint of the version it asks about, here the
SHA-256 of the snapshot's compact JSON; Casework binds the request and its result to it. Send it:

```sh
rstack casework api /v1/review-requests \
  --client requester \
  --idempotency-key tutorial-review-1 \
  --input request.json \
  --output accepted.json
jq . accepted.json
request_id="$(jq -r .requestId accepted.json)"
```

```json test-excerpt
{
  "requestId": "<id>",
  "policy": {"id": "decision", "version": "1", "digest": "sha256:<digest>"},
  "submissionDigest": "<digest>"
}
```

The request named only the policy ID, so Casework bound it to the active version and the digest
`check` printed. The same body under the same key returns this request, not a second one.

## Read the ReviewTask

The request opened a [ReviewTask](../../reference/glossary/#review-task). List it as staff:

```sh
rstack casework api '/v1/review-tasks?limit=25' \
  --client staff \
  --output tasks.json
task_id="$(jq -r '.items[0].taskId' tasks.json)"
task_revision="$(jq -r '.items[0].revision' tasks.json)"
```

Try to read it as the producer:

```sh
rstack casework api "/v1/review-tasks/$task_id" \
  --client requester \
  --output refused.json || test "$?" -eq 1
jq . refused.json
```

```json test-excerpt
{"code": "operation.not-authorized", "status": 403, "title": "Operation not authorized"}
```

A producer may read its result, never the human task.

{/* Evidence: crates/registry-casework/src/http.rs, review_tasks, get_review_task. */}

## Claim and decide

[Claim](../../reference/glossary/#claim) the task at the revision you read, so no one else decides
it while you work:

```sh
rstack casework api "/v1/review-tasks/$task_id/claim" \
  --client staff \
  --method POST \
  --if-match "\"$task_revision\"" \
  --idempotency-key tutorial-claim-1 \
  --output claimed.json
jq . claimed.json
claimed_revision="$(jq -r .revision claimed.json)"
```

```json test-excerpt
{
  "revision": 2,
  "state": {"held": {"holder": {"issuer": "http://127.0.0.1:8093", "subject": "<subject>"}}}
}
```

You hold the task at revision 2. Save one of the policy's outcomes as `decision.json`:

```json title="decision.json" test-file
{"decision":{"type":"answer","outcome":"confirmed"}}
```

Send the decision:

```sh
rstack casework api "/v1/review-tasks/$task_id/decisions" \
  --client staff \
  --if-match "\"$claimed_revision\"" \
  --idempotency-key tutorial-answer-1 \
  --input decision.json \
  --output /dev/null
```

The command exits successfully when Casework records the decision and answers `204`.

{/* Evidence: crates/registry-casework/src/http.rs, claim_review_task, decide_review_task;
    crates/registry-casework/src/review.rs, claim_review_task, decide_review_task. */}

## Read the ReviewResult

Back as the producer, fetch the answer:

```sh
rstack casework api "/v1/review-requests/$request_id/result" \
  --client requester \
  --output result.json
jq . result.json
```

```json test-excerpt
{"status": "answered", "outcome": "confirmed", "availableUntil": "<instant>"}
```

The [ReviewResult](../../reference/glossary/#review-result) repeats the request's policy, subject
and submission digest. It names no reviewer and is kept until `availableUntil`.
