You will submit one ReviewRequest as a producer, decide it as staff, and read the answer as the
producer. The request carries its own snapshot, so no source registry is needed.

## Install casework and caseworkctl

`casework` is the review service and [`caseworkctl`](/reference/cli/caseworkctl/) its tool. The
installer checks the checksums on the
[releases page](https://github.com/registrystack/registry-stack/releases/latest) and puts both
in `~/.local/bin`; keep it on your `PATH`.

{/* Evidence: crates/registry-casework/install.sh, CASEWORK_INSTALL_DIR. */}

```sh test-skip="downloads a release; the gate uses binaries built from this checkout"
curl -fsSL https://github.com/registrystack/registry-stack/releases/latest/download/casework-install.sh | bash
```

```sh
casework --version
caseworkctl --version
```

```text test-expect
casework <version>
caseworkctl <version>
```

## Create and check the project

```sh
mkdir -p tutorial-work
caseworkctl init tutorial-work/casework --template standalone-decision
```

```json test-excerpt
{
  "command": "init",
  "data": {
    "created": "tutorial-work/casework",
    "next": "Run caseworkctl check, test and types, then caseworkctl dev start.",
    "template": "standalone-decision"
  }
}
```

This tutorial's token issuer listens on port 8183. Point the trusted producer at it:

```diff test-edit title="tutorial-work/casework/casework.yaml"
-issuer: http://127.0.0.1:8093
+issuer: http://127.0.0.1:8183
```

```sh
caseworkctl check tutorial-work/casework
caseworkctl test tutorial-work/casework
```

```json test-excerpt
{
  "policyBindings": [
    {"digest": "sha256:<digest>", "id": "decision", "version": "1"}
  ]
}
```

The project declares one [ReviewPolicy](../../reference/glossary/#review-policy), `decision`:
who may ask, which team answers, and the outcomes allowed. The check pins it to a digest, and
the test runs its offline fixture.

## Start the development session

```sh
caseworkctl dev start tutorial-work/casework \
  --casework-port 8182 --issuer-port 8183 --database-port 55473
```

```json test-excerpt
{
  "caseworkUrl": "http://127.0.0.1:8182",
  "directory": {"revision": 1, "teams": 1},
  "state": "ready"
}
```

PostgreSQL and a token issuer run in Docker, with one staff team seeded.
`tutorial-work/casework/.casework/dev/` holds private credentials; keep it out of version
control. Get five-minute tokens for the producer (`requester`) and for `staff`:

```sh
caseworkctl dev token requester tutorial-work/casework
caseworkctl dev token staff tutorial-work/casework
casework_url=http://127.0.0.1:8182
headers=tutorial-work/casework/.casework/dev/secrets
sed 's/: .*/: <redacted>/' "$headers/requester.header"
```

```text test-excerpt
Authorization: <redacted>
Registry-Casework-Profile: <redacted>
Registry-Review-Profile: <redacted>
```

Each header file carries a token and the caller's profiles.

## Submit a ReviewRequest

Fetch the policy, then build and send a request that pins it and carries a digested snapshot:

```sh
curl --fail-with-body --silent --show-error \
  --header @"$headers/requester.header" \
  --output tutorial-work/policy.json \
  "$casework_url/v1/review-policies/decision"
python3 - <<'PYREQUEST'
import hashlib
import json
from pathlib import Path

snapshot = {"reference": "LIC-2026-0041", "summary": "Review licence batch LIC-2026-0041"}
content = json.dumps(snapshot, sort_keys=True, separators=(",", ":")).encode()
request = {
    "policy": json.loads(Path("tutorial-work/policy.json").read_text())["identity"],
    "subject": {
        "source": "standalone", "type": "batch", "id": "LIC-2026-0041", "version": "1",
        "digest": "sha256:" + hashlib.sha256(content).hexdigest(),
    },
    "requesterReference": "LIC-2026-0041",
    "context": {"mode": "submitted", "snapshot": snapshot},
}
Path("tutorial-work/request.json").write_text(json.dumps(request))
PYREQUEST
curl --fail-with-body --silent --show-error \
  --header @"$headers/requester.header" \
  --header 'Idempotency-Key: tutorial-review-1' \
  --header 'Content-Type: application/json' \
  --data-binary @tutorial-work/request.json \
  --output tutorial-work/requested.json --write-out 'HTTP %{http_code}\n' \
  "$casework_url/v1/review-requests"
python3 -m json.tool tutorial-work/requested.json
request_id="$(python3 -c 'import json; print(json.load(open("tutorial-work/requested.json"))["requestId"])')"
```

```json test-excerpt
{
  "requestId": "<id>",
  "policy": {"id": "decision", "version": "1", "digest": "sha256:<digest>"},
  "submissionDigest": "<digest>"
}
```

The same body under the same key returns this request again, not a second one.

## Read the ReviewTask

The request opened a [ReviewTask](../../reference/glossary/#review-task). List it as staff:

```sh
curl --fail-with-body --silent --show-error \
  --header @"$headers/staff.header" \
  --output tutorial-work/tasks.json \
  "$casework_url/v1/review-tasks?limit=25"
task_id="$(python3 -c 'import json; print(json.load(open("tutorial-work/tasks.json"))["items"][0]["taskId"])')"
task_revision="$(python3 -c 'import json; print(json.load(open("tutorial-work/tasks.json"))["items"][0]["revision"])')"
```

Try it as the producer:

```sh
curl --silent --show-error \
  --header @"$headers/requester.header" \
  --output tutorial-work/refused.json --write-out 'HTTP %{http_code}\n' \
  "$casework_url/v1/review-tasks/$task_id"
python3 -m json.tool tutorial-work/refused.json
```

```json test-excerpt
{"code": "operation.not-authorized", "status": 403, "title": "Operation not authorized"}
```

A producer may read its result, never the human task.

{/* Evidence: crates/registry-casework/src/http.rs, get_review_task. */}

## Claim and decide

[Claim](../../reference/glossary/#claim) the task at the revision you read:

```sh
curl --fail-with-body --silent --show-error --request POST \
  --header @"$headers/staff.header" \
  --header "If-Match: \"$task_revision\"" \
  --header 'Idempotency-Key: tutorial-claim-1' \
  --output tutorial-work/claimed.json \
  "$casework_url/v1/review-tasks/$task_id/claim"
python3 -m json.tool tutorial-work/claimed.json
claimed_revision="$(python3 -c 'import json; print(json.load(open("tutorial-work/claimed.json"))["revision"])')"
```

```json test-excerpt
{
  "revision": 2,
  "state": {"held": {"holder": {"issuer": "http://127.0.0.1:8183", "subject": "<subject>"}}}
}
```

You hold the task at revision 2. Decide it with a declared outcome:

```sh
curl --fail-with-body --silent --show-error --request POST \
  --header @"$headers/staff.header" \
  --header "If-Match: \"$claimed_revision\"" \
  --header 'Idempotency-Key: tutorial-answer-1' \
  --header 'Content-Type: application/json' \
  --data '{"decision":{"type":"answer","outcome":"confirmed"}}' \
  --output /dev/null --write-out 'HTTP %{http_code}\n' \
  "$casework_url/v1/review-tasks/$task_id/decisions"
```

```text test-expect
HTTP 204
```

## Read the ReviewResult

```sh
curl --fail-with-body --silent --show-error \
  --header @"$headers/requester.header" \
  --output tutorial-work/result.json --write-out 'HTTP %{http_code}\n' \
  "$casework_url/v1/review-requests/$request_id/result"
python3 -m json.tool tutorial-work/result.json
```

```json test-excerpt
{"status": "answered", "outcome": "confirmed", "availableUntil": "<instant>"}
```

The [ReviewResult](../../reference/glossary/#review-result) repeats the request's policy, subject
and submission digest. It names no reviewer and is kept until `availableUntil`.

## Leave the session running

The next pages use this project. Stopping the session keeps its database:

```sh
caseworkctl dev stop tutorial-work/casework
```

`caseworkctl dev start tutorial-work/casework`, without flags, restarts it on the same ports.
