You will submit one ReviewRequest as a producer, decide it as staff, and read the answer as the
producer. The request carries its own snapshot, so no source registry is needed.

## Install casework and caseworkctl

`casework` is the review service and [`caseworkctl`](../../reference/cli/caseworkctl/) its tool. The
installer checks the checksums on the
[releases page](https://github.com/registrystack/registry-stack/releases/latest) and puts both
in `~/.local/bin`; keep it on your `PATH`.

{/* Evidence: crates/registry-casework/install.sh, CASEWORK_INSTALL_DIR. */}

```sh test-skip="downloads a release; the gate uses binaries built from this checkout"
curl -fsSL https://github.com/registrystack/registry-stack/releases/latest/download/casework-install.sh | bash
```

```sh
casework --version
caseworkctl --version
```

```text test-expect
casework <version>
caseworkctl <version>
```

## Create the project

Create a project from the standalone template and work inside it:

```sh
mkdir -p tutorial-work
caseworkctl init tutorial-work/casework --template standalone-decision
cd tutorial-work/casework
```

```json test-excerpt
    "created": "tutorial-work/casework",
    "next": "Run caseworkctl check, test and types, then caseworkctl dev start.",
    "template": "standalone-decision"
  }
}
```

## Check what the policy allows

The project declares one [ReviewPolicy](../../reference/glossary/#review-policy), `decision`: who
may ask, which team answers, and the outcomes allowed. Check it offline and run its fixture:

```sh
caseworkctl check .
caseworkctl test .
```

```json test-excerpt
{
  "policyBindings": [
    {"digest": "sha256:<digest>", "id": "decision", "version": "1"}
  ]
}
```

The digest pins the policy's behavior. To read what that behavior is, explain it:

```sh
caseworkctl explain .
```

```json test-excerpt
{
  "contextCustody": "admitted bounded snapshot",
  "refusals": [
    "untrusted producer",
    "policy binding mismatch",
    "concealed source",
    "changed subject or contract",
    "stale task revision",
    "ineligible reviewer"
  ]
}
```

Casework keeps the snapshot the producer sends and refuses each listed case.

## Start the development session

```sh
caseworkctl dev start
```

```json test-excerpt
{
  "caseworkUrl": "http://127.0.0.1:8092",
  "directory": {"revision": 1, "teams": 1},
  "state": "ready"
}
```

PostgreSQL and a token issuer run in Docker, with one staff team seeded. `.casework/dev/` holds
private credentials; keep it out of version control. Get tokens for the producer (`requester`)
and for `staff`:

```sh
caseworkctl dev token requester
caseworkctl dev token staff
casework_url=http://127.0.0.1:8092
headers=.casework/dev/secrets
```

```json test-excerpt
{"headerFile": "<path>"}
```

Each header file carries a token and the caller's profiles. Tokens last five minutes; when a call
answers `401`, run `dev token` again.

{/* Evidence: crates/registry-caseworkctl/src/dev/mod.rs, start, the dev token report, header_file. */}

## Submit a ReviewRequest

Save the request. It names the policy, the subject under review, and the snapshot a reviewer will
read:

```json title="request.json" test-file
{
  "policy": {"id": "decision"},
  "subject": {
    "source": "standalone",
    "type": "batch",
    "id": "LIC-2026-0041",
    "version": "1",
    "digest": "sha256:6a3167d79ae3308448b24f2c9c0b9ac1cf116a7ad8be0c167c7e8660e43662bb"
  },
  "requesterReference": "LIC-2026-0041",
  "context": {
    "mode": "submitted",
    "snapshot": {"reference": "LIC-2026-0041", "summary": "Review licence batch LIC-2026-0041"}
  }
}
```

The subject digest is the producer's own fingerprint of the version it asks about, here the
SHA-256 of the snapshot's compact JSON; Casework binds the request and its result to it. Send it:

```sh
curl --fail-with-body --silent --show-error \
  --header @"$headers/requester.header" \
  --header 'Idempotency-Key: tutorial-review-1' \
  --header 'Content-Type: application/json' \
  --data-binary @request.json --output accepted.json \
  "$casework_url/v1/review-requests"
jq . accepted.json
request_id="$(jq -r .requestId accepted.json)"
```

```json test-excerpt
{
  "requestId": "<id>",
  "policy": {"id": "decision", "version": "1", "digest": "sha256:<digest>"},
  "submissionDigest": "<digest>"
}
```

The request named only the policy ID, so Casework bound it to the active version and the digest
`check` printed. The same body under the same key returns this request, not a second one.

## Read the ReviewTask

The request opened a [ReviewTask](../../reference/glossary/#review-task). List it as staff:

```sh
curl --fail-with-body --silent --show-error \
  --header @"$headers/staff.header" --output tasks.json \
  "$casework_url/v1/review-tasks?limit=25"
task_id="$(jq -r '.items[0].taskId' tasks.json)"
task_revision="$(jq -r '.items[0].revision' tasks.json)"
```

Try to read it as the producer:

```sh
curl --silent --show-error \
  --header @"$headers/requester.header" \
  "$casework_url/v1/review-tasks/$task_id" | jq .
```

```json test-excerpt
{"code": "operation.not-authorized", "status": 403, "title": "Operation not authorized"}
```

A producer may read its result, never the human task.

{/* Evidence: crates/registry-casework/src/http.rs, review_tasks, get_review_task. */}

## Claim and decide

[Claim](../../reference/glossary/#claim) the task at the revision you read, so no one else decides
it while you work:

```sh
curl --fail-with-body --silent --show-error --request POST \
  --header @"$headers/staff.header" \
  --header "If-Match: \"$task_revision\"" \
  --header 'Idempotency-Key: tutorial-claim-1' \
  --output claimed.json \
  "$casework_url/v1/review-tasks/$task_id/claim"
jq . claimed.json
claimed_revision="$(jq -r .revision claimed.json)"
```

```json test-excerpt
{
  "revision": 2,
  "state": {"held": {"holder": {"issuer": "http://127.0.0.1:8093", "subject": "<subject>"}}}
}
```

You hold the task at revision 2. Decide it with one of the policy's outcomes:

```sh
curl --fail-with-body --silent --show-error --request POST \
  --header @"$headers/staff.header" \
  --header "If-Match: \"$claimed_revision\"" \
  --header 'Idempotency-Key: tutorial-answer-1' \
  --header 'Content-Type: application/json' \
  --data '{"decision":{"type":"answer","outcome":"confirmed"}}' \
  --output /dev/null --write-out 'HTTP %{http_code}\n' \
  "$casework_url/v1/review-tasks/$task_id/decisions"
```

```text test-expect
HTTP 204
```

## Read the ReviewResult

Back as the producer, fetch the answer:

```sh
curl --fail-with-body --silent --show-error \
  --header @"$headers/requester.header" \
  "$casework_url/v1/review-requests/$request_id/result" | jq .
```

```json test-excerpt
{"status": "answered", "outcome": "confirmed", "availableUntil": "<instant>"}
```

The [ReviewResult](../../reference/glossary/#review-result) repeats the request's policy, subject
and submission digest. It names no reviewer and is kept until `availableUntil`.
