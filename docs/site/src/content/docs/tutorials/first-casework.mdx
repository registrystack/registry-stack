If you are evaluating Registry Casework, submit one immutable snapshot, answer its task as a human,
and read the result as the producer. You will also verify that the producer cannot read the human task.
This starter runs without a source provider or external registry.

## Check your binaries

Use both binaries from the release your docset describes, or from one source checkout for the
unreleased development docset. A released binary may implement an earlier pre-1.0 model.
The [Registry Stack releases](https://github.com/registrystack/registry-stack/releases/latest)
provide release artifacts and installation instructions.

```sh
casework --version
caseworkctl --version
```

If a source-built binary cannot load its runtime library on macOS, follow the repository's build
instructions before starting this journey. A failure before the command starts is not a development
session failure.

## Create the project

Create and check the standalone starter:

```sh
mkdir -p tutorial-work
caseworkctl init tutorial-work/casework --template standalone-decision
caseworkctl check tutorial-work/casework
caseworkctl test tutorial-work/casework
```

`init` refuses an existing destination. Choose a fresh directory rather than overwriting retained work.
The starter declares the `decision` ReviewPolicy, submitted context, one answer stage, two outcomes,
and a trusted requester. The local fixture check is synthetic; the HTTP steps establish the running
service behavior.

## Choose separate local ports

Use separate ports so this tutorial can run beside another local project.
Before the first start, edit the trusted producer's issuer in
`tutorial-work/casework/casework.yaml` to match the tutorial issuer port:

```diff test-edit title="tutorial-work/casework/casework.yaml"
-issuer: http://127.0.0.1:8093
+issuer: http://127.0.0.1:8183
```

This changes an authority binding, so the issuer URL must match the issuer that signs the requester's
token. If one of these tutorial ports is occupied, choose another before starting and keep the issuer
binding, start flags, and service URL consistent. A retained session keeps its first-start ports.

:::caution[Use synthetic data only]
The session keeps records in its Docker volume and private credentials in
`tutorial-work/casework/.casework/dev/`. Keep that directory out of version control and support reports.
:::

```sh
caseworkctl dev start tutorial-work/casework \
  --casework-port 8182 --issuer-port 8183 --database-port 55473
caseworkctl dev token requester tutorial-work/casework
caseworkctl dev token staff tutorial-work/casework
casework_url=http://127.0.0.1:8182
headers=tutorial-work/casework/.casework/dev/secrets
```

Start returns after readiness and seeds the team serving the `decisions` queue.
The token commands write owner-only header files containing both the bearer token and selected
Casework profile. If start fails, inspect the named private logs and run
`caseworkctl dev doctor tutorial-work/casework` before changing retained state.

## Discover the exact policy

Fetch the compiled policy as the producer. This tutorial submits its complete `identity` to pin
the exact version and digest. Your integration can instead select a policy by ID and retain the
concrete binding Casework returns at acceptance:

```sh
curl --fail-with-body --silent --show-error \
  --header @"$headers/requester.header" \
  --output tutorial-work/policy.json \
  "$casework_url/v1/review-policies/decision"
```

Create the request from that identity. For this synthetic subject, the content digest covers the
compact, sorted JSON snapshot; your producer uses its actual subject's immutable content digest.
The submission digest returned by Casework is a separate binding over the complete review round.

```sh
python3 - <<'PYREQUEST'
import hashlib
import json
from pathlib import Path

snapshot = {"reference": "LIC-2026-0041", "summary": "Review licence batch LIC-2026-0041"}
content = json.dumps(snapshot, sort_keys=True, separators=(",", ":")).encode()
request = {
    "policy": json.loads(Path("tutorial-work/policy.json").read_text())["identity"],
    "subject": {
        "source": "standalone", "type": "batch", "id": "LIC-2026-0041", "version": "1",
        "digest": "sha256:" + hashlib.sha256(content).hexdigest(),
    },
    "requesterReference": "LIC-2026-0041",
    "context": {"mode": "submitted", "snapshot": snapshot},
}
Path("tutorial-work/request.json").write_text(json.dumps(request))
PYREQUEST
curl --fail-with-body --silent --show-error \
  --header @"$headers/requester.header" \
  --header 'Idempotency-Key: tutorial-review-1' \
  --header 'Content-Type: application/json' \
  --data-binary @tutorial-work/request.json \
  --output tutorial-work/requested.json --write-out 'HTTP %{http_code}\n' \
  "$casework_url/v1/review-requests"
request_id="$(python3 -c 'import json; print(json.load(open("tutorial-work/requested.json"))["requestId"])')"
```

Creation returns HTTP `201`. Repeating the exact file and key recovers that request; changing the body
under the same key is refused. Keep the request ID and original key for recovery.

## Read the task and verify the boundary

List tasks as Staff and select the first task with the revision the service returned:

```sh
curl --fail-with-body --silent --show-error \
  --header @"$headers/staff.header" \
  --output tutorial-work/tasks.json \
  "$casework_url/v1/review-tasks?limit=25"
task_id="$(python3 -c 'import json; print(json.load(open("tutorial-work/tasks.json"))["items"][0]["taskId"])')"
task_revision="$(python3 -c 'import json; print(json.load(open("tutorial-work/tasks.json"))["items"][0]["revision"])')"
```

Try reading the same task with the producer's credential:

```sh
curl --silent --show-error \
  --header @"$headers/requester.header" \
  --output tutorial-work/refused.json --write-out 'HTTP %{http_code}\n' \
  "$casework_url/v1/review-tasks/$task_id"
```

The response is HTTP `403`. Producer authority permits result access, not human task disclosure.
A refusal contains a fixed problem and trace ID, not the submitted snapshot.

## Claim and answer

Claim the displayed revision, then take the next revision from the claim response:

```sh
curl --fail-with-body --silent --show-error --request POST \
  --header @"$headers/staff.header" \
  --header "If-Match: \"$task_revision\"" \
  --header 'Idempotency-Key: tutorial-claim-1' \
  --output tutorial-work/claimed.json \
  "$casework_url/v1/review-tasks/$task_id/claim"
claimed_revision="$(python3 -c 'import json; print(json.load(open("tutorial-work/claimed.json"))["revision"])')"
curl --fail-with-body --silent --show-error --request POST \
  --header @"$headers/staff.header" \
  --header "If-Match: \"$claimed_revision\"" \
  --header 'Idempotency-Key: tutorial-answer-1' \
  --header 'Content-Type: application/json' \
  --data '{"decision":{"type":"answer","outcome":"confirmed"}}' \
  --output /dev/null --write-out 'HTTP %{http_code}\n' \
  "$casework_url/v1/review-tasks/$task_id/decisions"
```

The terminal decision returns HTTP `204`. If a revision changed, read the task again and decide
whether another action is still appropriate; do not replace the revision merely to force the write.

## Read the result

Fetch the answer with the original producer credential and request ID:

```sh
curl --fail-with-body --silent --show-error \
  --header @"$headers/requester.header" \
  --output tutorial-work/result.json --write-out 'HTTP %{http_code}\n' \
  "$casework_url/v1/review-requests/$request_id/result"
python3 -m json.tool tutorial-work/result.json
```

The retained result returns HTTP `200`, status `answered`, and outcome `confirmed`.
Its policy, subject, and submission digest correlate the answer with the accepted round.
It contains no raw reviewer identity, private reason, or draft and authorizes no external mutation.
While pending, the result endpoint returns `202`; after result expiry, it returns `410`.

## Stop and remove the tutorial

Stop preserves the database for a later restart:

```sh
caseworkctl dev stop tutorial-work/casework
```

:::caution[Removal discards the tutorial database and local audit]
When you no longer need this synthetic review, remove only this project's owned development resources.
Export anything you need first; removal also clears its local audit directory.
:::

```sh
caseworkctl dev stop tutorial-work/casework --remove
```
