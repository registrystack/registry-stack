You wrote the assertion definitions in `adult-status`, the project from
[Get your first Evidence Gateway assertion](../first-evidence-assertion/). Here you prove every
definition against synthetic cases offline, read the trace of one case, and leave the project
ready to package.

## Find each definition's fixture

Enter the project:

```sh test-cwd="first-evidence-assertion"
cd adult-status
```

Each assertion definition in `evidence.yaml` names its fixture, the file of synthetic cases that
proves it. The `adult-status` definition ends with:

```yaml title="evidence.yaml" test-excerpt="evidence.yaml"
observationTimezone: Asia/Bangkok
fixtures: fixtures/adult-status.yaml
```

The project holds four assertion definitions and four fixtures under `fixtures/`. A fixture
states inputs and expected outcomes only; the definition keeps its source, function, outputs, and
grant ceiling.

## Run every fixture

```sh
evidencectl test . --target local-target.yaml --deny-warnings
```

```text test-expect
PASS: check
PASS: fixtures/adult-status.yaml (10 cases)
PASS: fixtures/legal-parent-relationship.yaml (9 cases)
PASS: fixtures/professional-licence-status.yaml (10 cases)
PASS: fixtures/residence-region.yaml (9 cases)
5 passed, 0 failed (38 cases evaluated)
Proof: offline synthetic fixture evaluation; no live dependency readiness was checked
```

Each fixture holds cases: a case supplies one synthetic source response and the result it must
produce. The fixture grammar is closed, so an unknown key, unsupported expectation, or real-data
marker refuses evaluation; the
[fixture contract](https://github.com/registrystack/registry-stack/blob/main/products/evidence/reference/request-adapter/deployment-projects/FIXTURES.md)
lists the case forms.

Each case runs through the matching `evidence` binary, from source extraction to an offline-verified
signature. The `Proof:` line states the boundary: every case supplies its own source response, so
no live source, credential, or token issuer takes part.

Treat a failed case, warning, or unknown field as a failed build input, and never turn a real
failure into an ignored case. For CI, `--format json` prints the same report as one JSON document.

{/* Evidence: crates/registry-evidencectl/src/fixtures.rs:322;
    crates/registry-evidencectl/src/fixtures.rs:816;

## Explain one case

Select one fixture and one case, and ask for the trace:

```sh
evidencectl test . --target local-target.yaml \
  --fixture fixtures/adult-status.yaml \
  --case boundary-at-bangkok-midnight \
  --explain --deny-warnings
```

The trace lists every stage the case reached. Two of them read:

```text test-excerpt
{
  "note": "fact keys [\"address-canary\", \"birth-date\", \"residence-region\"]",
  "stage": "extract",
  "status": "ok"
},
{
  "note": "the derivation script produced 1 value(s)",
  "stage": "derive",
  "status": "ok"
},
```

The trace names fact keys and counts, never a response, fact, derived value, or selector value.
A failed case stops at the stage that ended it and adds its finding codes, so read the last stage
first.
