In about fifteen minutes you will have a registry running on your machine with one test contact
in it, readable by your own staff and hidden from staff elsewhere. You write no code: you create
the registry, describe two test callers, start it, and read back the contact that start adds.

## Install Registry Stack

Download one exact `rstack-vX.Y.Z-install.sh` and the verification material from the same Registry
Stack release. Follow the
[release verification procedure](https://github.com/registrystack/registry-stack/blob/main/release/VERIFY.md)
before running the installer. From the verified release directory, install the `breg` component:

```sh test-skip="uses a downloaded, independently verified release installer"
tag="vX.Y.Z"
bash "rstack-${tag}-install.sh" breg
rstack breg --version
```

The managed installation exposes `rstack` on your `PATH`. The `breg` component supplies the
Base Registry Engine runtime and its command-line tools from the same release.

## Create a project

```sh
mkdir -p tutorial-work
rstack breg init tutorial-work/project
cd tutorial-work/project
```

```text test-excerpt
  registry.yaml
  runtime.example.yaml
  tests/journeys.yaml
```

A [project](../../reference/glossary/#registry-project) is a directory of YAML files that
describes one registry. `registry.yaml` holds what the registry stores and who may read and change
it, and `tests/journeys.yaml` holds the checks the registry must pass before it serves requests. Run
the remaining commands from this directory.

## Check the project

```sh
rstack breg check .
```

```text test-expect
Authoring check passed; registry revision sha256:<digest>.
0 errors, 0 warnings in 3 files
```

Open `registry.yaml`. It declares one [Record type](../../reference/glossary/#record-type),
`contact`, with three fields. Each contact you store is a
[Record](../../reference/glossary/#registry-record) of that type.

```yaml title="registry.yaml" test-excerpt="registry.yaml"
recordTypes:
  - id: contact
    route: contacts
    primaryDataset: directory
    mutationMode: mutable
    display: {label: Contact, description: A named institutional contact.}
    fields:
      - {id: name, type: string, required: true, minimumLength: 1, maximumLength: 160, classification: internal}
      - {id: email, type: string, required: true, minimumLength: 1, maximumLength: 254, classification: internal}
      - {id: jurisdiction, type: string, required: true, minimumLength: 1, maximumLength: 40, classification: internal}
```

Further down, an [access profile](../../reference/glossary/#access-profile) says who may read and
change contacts. A caller needs the `registry:directory:write` scope, may create, read, list and
change contacts, and only reaches contacts whose `jurisdiction` equals the `jurisdiction` claim in
its token:

```yaml title="registry.yaml" test-excerpt="registry.yaml"
accessProfiles:
  - id: directory-editor
    default: true
    principalClaim: registry_principal
    requiredScopes: ["registry:directory:write"]
    requiredPurposes: [directory-administration]
    permissions:
      records:
        - recordType: contact
          operations: [create, get, list, patch]
          readableFields: [name, email, jurisdiction]
          writableFields: [name, email, jurisdiction]
          rowBoundaries:
            - {field: jurisdiction, claim: jurisdiction, operator: equals}
```

## Describe the test callers

`rstack dev` runs the project on your machine from a development plan. The plan lists the products
to run and the synthetic people who call them, with the claims each person's test token carries.
Create `dev.yaml`. It gives the test caller `editor` the claim `zone-a` and `foreign-editor` the
claim `zone-b`:

```yaml title="dev.yaml" test-file
apiVersion: id.registrystack.org/formats/rstack/dev/v1alpha1
kind: RStackDev
issuer: https://identity.directory.example.test
products:
  - {product: breg, project: ., audience: "urn:example:local-directory"}
people:
  editor:
    subject: synthetic-directory-editor
    client: directory-editor
    grants:
      breg:
        profile: directory-editor
        scopes: ["registry:directory:write"]
        claims:
          registry_actor_kind: human
          registry_purpose: directory-administration
          jurisdiction: zone-a
  foreign-editor:
    subject: synthetic-foreign-editor
    client: directory-editor
    grants:
      breg:
        profile: directory-editor
        scopes: ["registry:directory:write"]
        claims:
          registry_actor_kind: human
          registry_purpose: directory-administration
          jurisdiction: zone-b
# Both people match the profile, so each journey step names its person.
schemaTestPeople:
  directory-contact:
    create-contact: editor
    read-contact: editor
    conceal-contact-outside-jurisdiction: foreign-editor
    obtain-email-condition: editor
    update-contact-email: editor
    read-updated-contact: editor
    start-registration: editor
    submit-registration: editor
scenarioFile: dev/scenarios.yaml
```

The plan also names a scenario file: requests that `rstack dev` sends once the registry is running.
It sits in `dev/` because the registry reads every file under `tests/` as one of its own checks.
This scenario adds one contact in `zone-a` as `editor` and reads it back:

```sh
mkdir dev
```

```yaml title="dev/scenarios.yaml" test-file
apiVersion: id.registrystack.org/formats/rstack/scenarios/v1alpha1
kind: RStackScenarios
scenarios:
  - id: directory-contact
    steps:
      - id: create-contact
        product: breg
        as: editor
        method: POST
        path: /v1/records/contacts
        headers: {Idempotency-Key: create-contact}
        body: {data: {name: Example contact, email: contact@example.test, jurisdiction: zone-a}}
        expect: {status: 201}
        capture: {contact: {type: pointer, pointer: /data/recordIdentifier}}
      - id: read-contact
        product: breg
        as: editor
        method: GET
        path: "/v1/records/contacts/{{contact}}"
        expect:
          status: 200
          json: {/data/domainData/name: Example contact}
```

Check the plan:

```sh
rstack dev check .
```

```text test-expect
Development plan is valid
0 errors, 0 warnings in 1 file
```

## Start the registry

```sh
rstack dev start . --ttl 4h | tee dev-run.txt
```

```text test-expect
Run <run-id> ready
  breg http://127.0.0.1:<port>
  Scenario directory-contact passed
  Logs <logs-directory>
  rstack dev token <run-id> --as editor
  rstack dev token <run-id> --as foreign-editor
```

`rstack dev` started a PostgreSQL server in Docker for this run, ran the project's tests, started
the registry at the `breg` address, and sent the scenario, which added the test contact. The first
start downloads the PostgreSQL image and takes longer. Each run gets a free port of its own, so your
address differs. The run ends after four hours, or when you stop it, and removes its database, test
keys and files with it.

## Read the contact as two callers

Keep the run ID and the registry address from the report. `token` writes a short-lived header file
for a test caller, and `rstack breg api` sends one request with it. List the contacts as `editor`:

```sh
RUN="$(awk '$1 == "Run" {print $2}' dev-run.txt)"
BREG_URL="$(awk '$1 == "breg" {print $2}' dev-run.txt)"
EDITOR_HEADERS="$(rstack dev token "$RUN" --as editor | awk '$2 == "headers" {print $3}')"
rstack breg api /v1/records/contacts --url "$BREG_URL" --header @"$EDITOR_HEADERS"
```

```json test-expect
{
  "items": [
    {
      "domainData": {
        "email": "contact@example.test",
        "jurisdiction": "zone-a",
        "name": "Example contact"
      },
      "recordIdentifier": "<record-id>",
      "revisionIdentifier": "1"
    }
  ],
  "meta": {
    "datasetIdentifier": "directory",
    "recordTypeIdentifier": "contact",
    "registryIdentifier": "local-directory"
  },
  "pageInfo": {
    "nextCursor": null
  }
}
```

The Record carries a stable identifier and a revision number beside the fields. Tokens last five
minutes: when a request is refused with status 401, run the `token` command again. Now list the same
contacts as `foreign-editor`, whose token says `zone-b`:

```sh
FOREIGN_HEADERS="$(rstack dev token "$RUN" --as foreign-editor | awk '$2 == "headers" {print $3}')"
rstack breg api /v1/records/contacts --url "$BREG_URL" --header @"$FOREIGN_HEADERS"
```

```json test-expect
{
  "items": [],
  "meta": {
    "datasetIdentifier": "directory",
    "recordTypeIdentifier": "contact",
    "registryIdentifier": "local-directory"
  },
  "pageInfo": {
    "nextCursor": null
  }
}
```

The registry applied the access profile: the contact exists, and `foreign-editor` cannot see it.

## Leave the registry running

The next tutorial continues with this project, and its first step restarts the run. When you are
finished with the registry, run `rstack dev stop "$RUN"` to stop it and delete its data. A run you
forget ends by itself after its time to live.
