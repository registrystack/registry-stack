You have a candidate from `evidencectl package` that signs through a Transit proxy, and you run
containers with Docker Compose. Run that candidate unchanged, with the runtime, secrets, Transit
socket, and audit storage each mounted separately; the package digest stays the same as on a host
deployment.

## What you need

- The candidate directory, holding `bundle/`, `runtime.yaml`, and `compiled-authority.yaml`.
- A reviewed Registry Evidence image, pinned by digest.
- A running Transit proxy whose socket directory you can mount, set up as in
  [Configure Transit signing for Registry Evidence](../move-evidence-to-production-signing/).
- An owner-only secret directory and storage that UID and GID `65532` can write.
- The Compose adapter from your release's source archive,
  `https://github.com/registrystack/registry-stack/archive/refs/tags/v<version>.tar.gz`, where
  `<version>` is the version `evidencectl --version` prints. The archive unpacks to
  `registry-stack-<version>/`, and the adapter is its `docker/` directory. Copy that directory to
  `evidence-compose/`, your operator-owned copy, and run every command from inside it.

## Set the Compose adapter inputs

The Compose file is `compose/docker-compose.yaml` in `evidence-compose/`. You own it;
`evidencectl package` does not write it. It reads five variables:

```sh test-skip="needs the reader's candidate, secrets, Transit proxy, and reviewed image"
export EVIDENCE_CANDIDATE_DIR='<candidate>/bundle'
export EVIDENCE_RUNTIME_FILE='<container-runtime.yaml>'
export EVIDENCE_SECRET_ROOT='<secret-root>'
export EVIDENCE_TRANSIT_SOCKET_DIR='<transit-socket-directory>'
export EVIDENCE_IMAGE='<reviewed-evidence-image-by-digest>'
docker compose -f compose/docker-compose.yaml config
```

`EVIDENCE_CANDIDATE_DIR` is the candidate's `bundle/` directory, the one holding `SHA256SUMS`,
not the whole candidate. The adapter mounts it read-only at `/etc/registry-evidence/bundle`, and
the runtime's `package.root` must name that directory. The adapter mounts the container runtime
file at `/etc/registry-evidence/runtime.yaml` and the secret root at
`/run/secrets/registry-evidence`, both read-only, the Transit socket directory read-only at
`/run/registry-evidence`, and the `evidence-audit` named volume at `/var/lib/registry-evidence`,
its only writable mount.

The service runs as `65532:65532` with `read_only`, `cap_drop: [ALL]`, `no-new-privileges`, and a
read-only `/dev/shm` tmpfs. Registry Evidence receives the proxy socket, never a provider token.

## Write the container runtime file

Start the container runtime file from `compose/runtime.docker.yaml`. It already names the
container paths the adapter mounts, binds `0.0.0.0:8080` under
`networkExposure: container-private`, and selects a Transit signer. Set `signer.keyName` and `signer.keyVersion` to the values in your
candidate's `runtime.yaml`; the adapter's copy pins key version 1.

A packaged candidate is refused until its target authority is activated, and the adapter's runtime
file carries no `authority` block. Add one yourself. Keep its `root` inside the audit volume,
because the maintained preflight accepts only one writable mount, and set `target` to the `id` in
your `target.yaml`:

```yaml
authority:
  root: /var/lib/registry-evidence/authority
  target: <target-id>
```

## Bind SQLite extracts

Skip this step unless a source in your bundle has `type: sqlite-extract`. Each such source names
an `extractProfile`, and the candidate's `runtime.yaml` carries a `sourceExtracts` binding for
each one, with host paths. Carry every binding into the container runtime file under the same
names, pointing at container paths:

```yaml
sourceExtracts:
  <extract-profile>:
    path: /etc/registry-evidence/extracts/<extract-file>.sqlite
```

The names must match the bundle's `extractProfile` names exactly: the container check and startup refuse a missing one as
`evidence.runtime.source-extract-unbound` and an extra one as
`evidence.runtime.source-extract-unused`. Then mount each extract file read-only at its path, in
the `evidence` service's `volumes` in your copy of the adapter:

```yaml
      - <host-extract-file>:/etc/registry-evidence/extracts/<extract-file>.sqlite:ro
```

The file must be readable by UID `65532`. Evidence opens an extract as immutable and refuses a
symbolic link or a writable file; the read-only mount satisfies the second, and the preflight
refuses a writable mount under `/etc`. Keep extracts out of `/var/lib/registry-evidence`:
that is the audit volume, the one writable mount. Publish a replacement extract as a new file and
restart, never by changing the mounted one.

## Activate the target authority

Run the activation inside the container, so the authority store is created and owned by the service
identity. Mount the candidate's `compiled-authority.yaml` for this run only:

```sh
docker compose -f compose/docker-compose.yaml run --rm \
  -v "<candidate>/compiled-authority.yaml:/etc/registry-evidence/compiled-authority.yaml:ro" \
  evidence authority activate \
  --runtime-config /etc/registry-evidence/runtime.yaml \
  --document /etc/registry-evidence/compiled-authority.yaml
```

```text test-expect
ACTIVATED sha256:<authority-revision> sha256:<authority-digest> sequence=<n>
```

The activation persists in the volume, so later runs and `up` read the same authority. See
[`evidence authority activate`](../../reference/cli/evidence/authority/activate/).

{/* Evidence: crates/registry-evidence/src/authority.rs, activate, check_root */}

## Check in the container

Start the Transit proxy first, then run the check in the container:

```sh
docker compose -f compose/docker-compose.yaml run --rm evidence \
  check --runtime-config /etc/registry-evidence/runtime.yaml \
  --require-runtime-dependencies \
  --require-audit-under /var/lib/registry-evidence
```

```text test-expect
Evidence package <package-digest> passed check (<count> requirements)
0 errors, 0 warnings in <count> files
```

`--require-runtime-dependencies` validates the mounted secrets and signs a self-test message
through the proxy, so a missing socket fails with `evidence.deployment.signing-unavailable`.
`--require-audit-under` refuses an audit path that does not resolve inside the volume. See
[`evidence check`](../../reference/cli/evidence/check/).

The adapter's preflight also checks the image pin, the mounts, and the service posture, then runs
the same native check:

```sh test-skip="needs Docker Compose and the reader's adapter inputs"
python3 runtime-preflight.py \
  --compose-file compose/docker-compose.yaml \
  --service evidence=evidence
```

Changing only the container runtime file leaves the package digest unchanged, so fixtures need not
run again; [Build and deploy a Registry Evidence project](../build-and-deploy-evidence-project/)
explains the digests.

## Start the service

```sh test-skip="needs Docker Compose and the reader's adapter inputs"
docker compose -f compose/docker-compose.yaml up -d
docker compose -f compose/docker-compose.yaml logs evidence
```

The image's default command is `serve --runtime-config /etc/registry-evidence/runtime.yaml`, so
`up` needs no arguments. The log carries an `evidence service listening` record once every listener
is bound; if it is missing, the log names the startup failure. The adapter publishes no port, so
reach the listener from another service on the Compose network and put TLS termination ahead of it.
To read the audit log, see [Operate the Registry Evidence audit log](../../operate/evidence-audit/).

{/* Evidence: release/docker/Dockerfile.evidence; crates/registry-evidence/src/server.rs */}

## Stop without deleting the audit history

`docker compose down` removes the containers and the network and keeps named volumes, so the audit
log and the activated authority survive.

:::danger
`docker compose down -v` deletes the `evidence-audit` volume. Unless you shipped the audit files to
append-only storage first, the history is gone and cannot be reconstructed.
:::
