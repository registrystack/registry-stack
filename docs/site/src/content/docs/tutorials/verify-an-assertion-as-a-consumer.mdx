application kept, then see a changed response refused. You continue the project from
[Request Evidence from your application](../request-evidence-from-an-application/); nothing needs
to be running.

## What the application kept

```sh test-cwd="first-evidence-assertion"
cd adult-status
```

The application wrote three files:

- `adult-status.retained.json`, the retained verification: the pinned keys and every expectation,
  fixed before the response existed. It holds no disclosed values.
- `adult-status.response.jws`, the exact response bytes, still untrusted input.
- `adult-status.verified-at.txt`, the decision instant in Unix seconds.

## Replay the decision and refuse a change

`verify_retained` judges a response against the current time. `verify_retained_as_of` asks whether
the response was acceptable at the recorded instant, so a replay still holds after the assertion
expires.

```python title="replay_adult_status.py" test-file
import json
from pathlib import Path

from registry_client.evidence import VerificationError, verify_retained_as_of

context = Path("adult-status.retained.json").read_bytes()
response = Path("adult-status.response.jws").read_bytes()
decided_at = int(Path("adult-status.verified-at.txt").read_text())

replayed = verify_retained_as_of(context, response, decided_at)
value = replayed.evidence["supportedValues"][0]["value"]
print(f"REPLAYED adult={json.dumps(value)}")

document = json.loads(response)
payload = document["payload"]
document["payload"] = ("A" if payload[0] != "A" else "B") + payload[1:]
try:
    verify_retained_as_of(context, json.dumps(document).encode(), decided_at)
except VerificationError as error:
    print(f"REFUSED {error.code}")
```

The second call changes one character of the signed payload and keeps the keys, expectations, and
instant. Run it:

```sh
python3 replay_adult_status.py
```

```text test-expect
REPLAYED adult=true
REFUSED signature
```

The replay opens no connection. `error.code` names the verifier's reason; branch on it, never on
the message.

### Node

`verifyRetainedAsOf` takes the instant in milliseconds, so the recorded seconds are scaled:

```js title="replay-adult-status.js"
const { readFileSync } = require('node:fs')
const { evidence } = require('@registrystack/client')

const replayed = evidence.verifyRetainedAsOf(
  readFileSync('adult-status.retained.json'),
  readFileSync('adult-status.response.jws'),
  Number(readFileSync('adult-status.verified-at.txt', 'utf8')) * 1000,
)
console.log(`REPLAYED adult=${replayed.evidence.supportedValues[0].value}`)
```

## If the replay is refused

A refusal of the unchanged files means the retained trust no longer matches the response, usually
after a key rotation or a changed trusted key set. That is the verifier's own trust input; see
[Manage verifier trust](../manage-evidence-verifier-trust/).
