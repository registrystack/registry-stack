If you are authoring reviewed Base Registry Engine (BReg) changes, inspect a
complete native Proposal Action before connecting an external authority. You
will check its frozen review binding and its separate start, management, and
application grants without starting services.

<QuickstartMeta
  outcome="A checked Proposal Action and an inspected authority boundary."
  time="About 15 minutes"
  level="Offline authoring"
  prerequisites={['Matching bregctl binary', 'A shell and an editor']}
/>

## Create the complete project

```sh
mkdir -p tutorial-work
bregctl init tutorial-work/facility --template facility-registry
bregctl check tutorial-work/facility
```

Open `tutorial-work/facility/registry.yaml`. Find `correct-address` under
`actions`. Its execution mode is `proposal`, its plan calls `correct-address-plan`,
and its review requirement names `casework` with the policy ID `facility-address-review`.
The review authority resolves that ID and freezes the concrete policy version and
digest when it accepts a submission. Add both `version` and `digest` if your registry
requires an exact independently compiled policy binding.

## Inspect the compiled boundary

```sh
bregctl --format json explain actions tutorial-work/facility
bregctl --format json explain proposals tutorial-work/facility
```

Check the Action identity, typed inputs, write ceiling, commit guards, review
binding, retention, and application mode. Omitting an explicit application mode
selects automatic application by the restricted built-in executor. No executor
client or self-HTTP endpoint is configured.

Find `facility.mutationPolicy.patch: proposal-required`. This rule refuses a
direct Patch or immediate Action even if a profile grants a write. The
`register-facility` Action remains immediate; `deactivate-facility` shows explicit
manual application without external review.

## Review the grants

```sh
bregctl --format json explain access tutorial-work/facility
```

Compare `facility-correction-author`, `facility-correction-applier`,
`proposal-reviewer`, and `casework-review-status`. Start and Proposal transitions
are separate grants. Review context and review status are separate disclosures.
A review authority decides policy; BReg alone applies the exact frozen plan.
External recovery of automatic work needs a verified human with an explicit grant.

These commands prove that the configuration compiles and can be inspected. They
make no external review decision and apply no records. If a diagnostic appears,
repair its named member and rerun `check` before adding service configuration.
No cleanup command is needed because this exercise starts no services.
