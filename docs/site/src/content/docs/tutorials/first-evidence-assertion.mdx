If other services need a yes-or-no answer from records your institution holds, this tutorial
shows you what Evidence Gateway gives them. You run it over a synthetic source, ask whether one
test person is an adult, and read `"value": true` from a verified response with no birth date.

## Confirm the toolset

`evidencectl` refuses an `evidence` binary from another release.

```sh
evidence --version
evidencectl --version
```

```text test-expect
evidence <version>
evidencectl <version>
```

## Copy the project

From the archive root, copy the standalone example out of the tree, because the next commands
write keys and responses into it.

```sh
mkdir first-evidence-assertion
cp -R products/evidence/examples/standalone first-evidence-assertion/adult-status
cd first-evidence-assertion/adult-status
```

Generate disposable owner-only keys and secrets:

```sh
umask 077
evidencectl keygen signing --output-dir .generated/secrets
evidencectl keygen secret --output .generated/secrets/audit-hmac-key
evidencectl keygen secret --output .generated/secrets/subject-binding-hmac-key
evidencectl keygen token --output .generated/secrets/synthetic-source-token
```

## Check and explain the project

```sh
evidencectl check . --target local-target.yaml
```

```text test-expect
Evidence project check: complete
Project: .
Target: local-target.yaml
0 errors, 0 warnings
```

`check` compiled `evidence.yaml` against `local-target.yaml`, which holds the local ports, keys,
and source address. Ask what the project answers:

```sh
evidencectl explain . --target local-target.yaml
```

```text test-excerpt
Definition adult-status: urn:example:requirement:adult-status:v1
  Acquisition: {"source":"person-record","type":"single"}; derive: "derive-adult-status"
  Outputs: {"adult":{"concept":"urn:example:concept:adult-status:v1","type":"boolean"}}; grant ceiling: {"actorKinds":["service"],"audiences":["urn:example:audience:standalone-app"],"authorities":["organizational"],"valueOrigins":["request"]}
```

`adult-status` is an assertion definition: one fixed question, named by its
[Requirement URI](../../reference/glossary/#requirement). It reads the source `person-record`
and may return one output, the Boolean `adult`. The report goes on to three other definitions.

Run the fixture cases offline:

```sh
evidencectl test . --target local-target.yaml
```

```text test-excerpt
PASS: fixtures/adult-status.yaml (10 cases)
```

Register the caller you will send the request as:

```sh
evidencectl access client add tutorial-client \
  --access-profile standalone-service \
  --generate-local-key
```

```text test-expect
Added client tutorial-client with access profile standalone-service.
```

## Start the synthetic source

In a second terminal, in the same directory, start the source that stands in for your system:

```sh test-cwd="first-evidence-assertion/adult-status" test-background="http://127.0.0.1:8081/healthz"
python3 serve-source.py \
  --port 8081 \
  --token-file .generated/secrets/synthetic-source-token
```

It serves records only to the token `local-target.yaml` gives Evidence. Leave it running.

{/* Evidence: products/evidence/examples/standalone/serve-source.py, healthz. */}

## Start Evidence Gateway

Port `18080` avoids a clash with any service on the default `8080`. `dev start` also runs a token issuer in
Docker; the first start pulls its image.

```sh
evidencectl dev start . \
  --target local-target.yaml \
  --evidence-port 18080 \
  --issuer-port 8082
```

```text test-excerpt
Evidence ready at http://127.0.0.1:18080
Issuer ready at http://127.0.0.1:8082
```

If a port is in use, stop what holds it and start again.

{/* Evidence: crates/registry-evidencectl/src/dev.rs, prepare_and_start. */}

## Prepare, send, and verify one request

`request prepare` gets a token from the issuer and sends nothing to Evidence Gateway. It fixes
what a valid answer must match before any response exists.

```sh
evidencectl request prepare adult-status \
  --client tutorial-client \
  --purpose age-check \
  --subject subject:record-id=adult \
  --name adult-status
```

```text test-expect
Prepared request: .evidence/requests/adult-status/request.json
Prepared verification context: .evidence/requests/adult-status/verification.json
Prepared authorization: .evidence/requests/adult-status/authorization.curl
```

Send it. `authorization.curl` holds the token; keep it out of logs.

```sh
curl --silent --show-error --fail-with-body \
  --config .evidence/requests/adult-status/authorization.curl \
  --request POST \
  --url http://127.0.0.1:18080/v1/evidence \
  --header 'Content-Type: application/json' \
  --header 'Accept: application/jose+json' \
  --data-binary @.evidence/requests/adult-status/request.json \
  --output adult-status.jws.json
```

Verify the response offline, recording when, so you can re-verify it at that instant later:

```sh
umask 077
verified_at="$(date -u +%Y-%m-%dT%H:%M:%SZ)"
evidencectl verify adult-status.jws.json \
  --context .evidence/requests/adult-status/verification.json \
  --output adult-status.verified.json
printf '%s\n' "$verified_at" > .evidence/requests/adult-status/verified-at.txt
```

```text test-expect
VERIFIED
```

On failure `verify` writes nothing and exits non-zero. Read the answer:

```sh
jq '{supportsRequirement, supportedValues}' adult-status.verified.json
```

```json test-expect
{
  "supportsRequirement": "urn:example:requirement:adult-status:v1",
  "supportedValues": [
    {
      "providesValueFor": "urn:example:concept:adult-status:v1",
      "value": true
    }
  ]
}
```

This [assertion](../../reference/glossary/#assertion) answers the Requirement URI with one value
for the `adult` output's concept. The source holds a birth date for record `adult`; the
assertion carries only `true`.

## Inspect the audit and stop

`audit show` reads only a stopped session:

```sh
evidencectl dev stop .
evidencectl audit show --last-operation
```

```text test-excerpt
ACCESS AUTHORIZED adult-status age-check requester=<pseudonym>
DISCLOSURE RELEASED adult
```

A pseudonymous requester was authorized for `adult-status` and `age-check`, and `adult` was
released. The value is not shown.

Remove the stopped session's generated state. The project, its clients, and its audit stay:

```sh
evidencectl dev clean .
```

```text test-expect
Removed stopped local Evidence state
```

Press `Ctrl+C` in the source's terminal. Keep the project: the next tutorial continues from it.
