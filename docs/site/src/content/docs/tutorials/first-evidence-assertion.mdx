Answer one specific question, "Is this person an adult?", without returning the person's name or
date of birth. You will connect Evidence to a small registry, make a real HTTP request, and verify
the signed answer before reading it.

<QuickstartMeta
  outcome="A verified assertion containing an adult-status answer, but not the source record."
  time="About 15 minutes"
  level="Local development with synthetic data"
  prerequisites={['Python 3', 'A shell with curl', 'Linux or macOS']}
/>

## Install Evidence

Install the latest Evidence toolset:

```sh
curl -fsSL https://github.com/registrystack/registry-stack/releases/latest/download/evidencectl-install.sh | bash
```

## Start a small registry

Create a working directory and save the server as `registry.py`:

```sh
mkdir first-evidence-assertion
cd first-evidence-assertion
```

```python
import json
from http.server import BaseHTTPRequestHandler, ThreadingHTTPServer

PERSON = {
    "person_id": "person-123",
    "name": "Amina Example",
    "date_of_birth": "2000-01-01",
}
OPENAPI = {
    "openapi": "3.1.0",
    "info": {"title": "Tutorial registry", "version": "1.0.0"},
    "servers": [{"url": "http://127.0.0.1:8000"}],
    "paths": {"/people/{person_id}": {"get": {
        "operationId": "getPerson",
        "parameters": [{"name": "person_id", "in": "path", "required": True,
                        "schema": {"type": "string"}}],
        "responses": {"200": {
            "description": "A person record",
            "content": {"application/json": {
                "schema": {
                    "type": "object",
                    "required": list(PERSON),
                    "properties": {key: {"type": "string"} for key in PERSON},
                },
            }},
        }},
    }}},
}

class Registry(BaseHTTPRequestHandler):
    def do_GET(self):
        if self.path == "/openapi.json":
            return self.send_json(OPENAPI)
        if self.path == "/people/person-123":
            return self.send_json(PERSON)
        self.send_error(404)

    def send_json(self, value):
        body = json.dumps(value).encode()
        self.send_response(200)
        self.send_header("Content-Type", "application/json")
        self.send_header("Content-Length", str(len(body)))
        self.end_headers()
        self.wfile.write(body)

print("Registry listening on http://127.0.0.1:8000", flush=True)
ThreadingHTTPServer(("127.0.0.1", 8000), Registry).serve_forever()
```

In one terminal, start the registry and leave it running:

```sh
python3 registry.py
```

The server publishes its OpenAPI description at `/openapi.json` and one synthetic person record at
`/people/person-123`.

In another terminal, return to `first-evidence-assertion` and inspect the source record:

```sh
curl -s http://127.0.0.1:8000/people/person-123 | python3 -m json.tool
```

The registry returns an identifier, a name, and a date of birth. The verified assertion will contain
none of those source values.

## Create the Evidence project

Create a local project from the registry's OpenAPI description:

```sh
evidencectl new adult-status \
  --openapi http://127.0.0.1:8000/openapi.json \
  --profile local \
  --generate-keys
cd adult-status
```

`--profile local` creates a loopback-only development project, not a production deployment.
`--generate-keys` creates owner-only local keys for signing, subject binding, and audit integrity.
OpenAPI describes the source, but you still decide the question and what the answer may disclose.

### `questions/adult-status.yaml`

Create the question definition:

```yaml
id: adult-status
question: Is the person at least 18 years old?
purpose: age-check
subject:
  role: person
  selector: person_id
source:
  operation: getPerson
  facts: [date_of_birth]
answers:
  - concept: is_adult
    type: boolean
derivation: derivations/adult-status.rhai
disclosure:
  allow: [is_adult]
```

`operation` connects the question to `getPerson` in OpenAPI. `selector` identifies which path
parameter selects the person. `facts` limits what reaches the derivation to `date_of_birth`; it does
not change what the registry itself returns. The purpose must match future requests, and the answer
and disclosure fields permit one boolean named `is_adult`. A question can declare up to 16
governed answers. The disclosure list must name exactly the answers that the derivation returns.

### `derivations/adult-status.rhai`

Create the answer logic:

```rhai
fn answer(facts, selectors, context) {
    let born = parse_date(required(facts.date_of_birth, "date_of_birth_missing"));
    let adult_on = add_calendar_years(born, 18);
    #{is_adult: compare_dates(context.legal_local_date, adult_on) >= 0}
}
```

The derivation receives the selected fact and the evaluation context. `context.legal_local_date` is
the date against which the eighteenth birthday is compared. The function returns a map keyed by
the declared answer name. Evidence validates each value against its declared form before signing.

Start Evidence and Registry Mint:

```sh
evidencectl dev --detach
```

```text
Evidence ready at http://127.0.0.1:8080
Mint ready at http://127.0.0.1:8081
```

This command starts Evidence and Mint only. The Python registry remains the process you started in
the first terminal.

## Request an assertion

Prepare the request, local access, and verification expectations:

```sh
evidencectl request prepare adult-status \
  --purpose age-check \
  --subject person_id=person-123 \
  --name first-assertion
```

Preparation asks the local Mint for short-lived authorization and records the verification
expectations before a response exists. It does not send the request to Evidence or contact the
registry. It creates exactly these owner-only artifacts:

```text
Prepared request: .evidence/requests/first-assertion/request.json
Prepared verification context: .evidence/requests/first-assertion/verification.json
Prepared authorization: .evidence/requests/first-assertion/authorization.curl
```

The curl configuration contains only the Authorization header. Send the request yourself:

```sh
curl --silent --show-error \
  --config .evidence/requests/first-assertion/authorization.curl \
  --request POST \
  --url http://127.0.0.1:8080/v1/evidence \
  --header 'Content-Type: application/json' \
  --header 'Accept: application/jose+json' \
  --data-binary @.evidence/requests/first-assertion/request.json \
  --output assertion.jws.json
```

`curl` called Evidence, Evidence called the registry, and the HTTP response is a signed flattened
JSON Web Signature (JWS). A successful HTTP response is not yet a trusted assertion.

## Verify before reading

Verify the response against the expectations recorded before the request:

```sh
evidencectl verify assertion.jws.json \
  --context .evidence/requests/first-assertion/verification.json \
  --output verified.json
```

```text
VERIFIED
```

Only after the command prints `VERIFIED`, inspect the verified payload:

```sh
python3 -m json.tool verified.json
```

The verified document contains generated identifiers, timestamps, and a pseudonymous subject
binding. The fields relevant to this question look like this excerpt:

```json
{
  "assuranceProfile": "local",
  "purpose": "age-check",
  "subjects": [
    {
      "binding": "urn:evidence:subject:v1_…",
      "role": "person"
    }
  ],
  "supportedValues": [
    {
      "providesValueFor": "urn:registrystack:evidence:local:concept:adult-status:is_adult",
      "value": true
    }
  ],
  "supportsRequirement": "urn:registrystack:evidence:local:requirement:adult-status"
}
```

The verified payload does not include `person_id`, `name`, or `date_of_birth`. The assertion
answers the authored question without becoming another copy of the registry record.

## Stop the local services

Stop Evidence and Mint before reading the completed audit chain:

```sh
evidencectl dev stop
```

```text
Local Evidence stopped
```

## Inspect the audit entry

Verify the completed audit chain and show its last operation:

```sh
evidencectl audit show --last-operation
```

```text
ACCESS AUTHORIZED adult-status age-check requester=<pseudonym>
DISCLOSURE RELEASED is_adult
```

The requester value changes on each fresh project. The view identifies the question, purpose,
requester pseudonym, authorization decision, and disclosed concept. It does not repeat the source
record or access token.

## Clean up

Return to the first terminal and press `Ctrl+C` to stop the registry.
