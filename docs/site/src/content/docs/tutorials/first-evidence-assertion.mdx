Run the reviewed standalone project that ships with the same Registry Stack release as your
`evidence` and `evidencectl` binaries. You will start a synthetic source, request one adult-status
assertion, verify it offline, and inspect the privacy-safe audit view.

## Confirm the toolset

Run both binaries from one release. `evidencectl` refuses to compile or start a project with an
`evidence` binary from another version.

```sh
evidence --version
evidencectl --version
```

The two commands print the same version.

## Copy the normalized project

From the root of the matching Registry Stack source archive, copy the standalone example into a
writable tutorial directory. The copy keeps generated keys, client credentials, requests, and
responses out of the source tree.

```sh
mkdir first-evidence-assertion
cp -R products/evidence/examples/standalone first-evidence-assertion/adult-status
cd first-evidence-assertion/adult-status
```

The project has one normalized `evidence.yaml`, named Functions under `functions/`, a disposable
`local-target.yaml`, and complete local grants in `dev-authority.yaml`. The project file fixes
assertion semantics and source behavior. The target binds local ports, keys, secrets, and source
connections. The authority grants one complete request shape at a time.

Generate disposable local material, then prove the project and its synthetic fixtures.

```sh
umask 077
evidencectl keygen signing --output-dir .generated/secrets
evidencectl keygen secret --output .generated/secrets/audit-hmac-key
evidencectl keygen secret --output .generated/secrets/subject-binding-hmac-key
evidencectl keygen token --output .generated/secrets/synthetic-source-token
evidencectl check . --target local-target.yaml
evidencectl test . --target local-target.yaml
evidencectl access client add tutorial-client \
  --access-profile standalone-service \
  --generate-local-key
```

`check` compiles the normalized project and target without contacting the source. `test` exercises
the fixed source, extraction, derivation, output, and privacy boundaries with synthetic fixtures.
The client command assigns an existing complete access profile; client registration does not create
authority.

## Start the synthetic source

In another terminal, run the bounded synthetic source from the project directory:

```sh test-cwd="first-evidence-assertion/adult-status" test-background="http://127.0.0.1:8081/healthz"
python3 serve-source.py \
  --port 8081 \
  --token-file .generated/secrets/synthetic-source-token
```

Leave this terminal running. Its public health route exposes no record data. Every record route
requires the bearer token referenced by the target. The source authenticates Evidence Gateway but
does not decide who may request an assertion.

## Start Evidence Gateway

Use port `18080` because another local service may already own the default Evidence port. The
issuer remains on the example's configured port `8082`.

```sh
evidencectl dev start . \
  --target local-target.yaml \
  --evidence-port 18080 \
  --issuer-port 8082
```

```text test-excerpt
Evidence ready at http://127.0.0.1:18080
Issuer ready at http://127.0.0.1:8082
```

`dev start` retains one generated package and authority snapshot. A later edit takes effect only in
a new generation.

## Prepare, send, and verify one request

Preparation closes the request nonce, expected definition, signing keys, configuration revision,
subject binding, and output form before the response exists. It sends nothing.

```sh
evidencectl request prepare adult-status \
  --client tutorial-client \
  --purpose age-check \
  --subject subject:record-id=adult \
  --name adult-status
```

Send the prepared body with the owner-only authorization file:

```sh
curl --silent --show-error --fail-with-body \
  --config .evidence/requests/adult-status/authorization.curl \
  --request POST \
  --url http://127.0.0.1:18080/v1/evidence \
  --header 'Content-Type: application/json' \
  --header 'Accept: application/jose+json' \
  --data-binary @.evidence/requests/adult-status/request.json \
  --output adult-status.jws.json
```

Verify the exact response offline before reading its value:

```sh
evidencectl verify adult-status.jws.json \
  --context .evidence/requests/adult-status/verification.json \
  --output adult-status.verified.json
```

```text test-expect
VERIFIED
```

The verified assertion contains one Boolean adult-status output. It excludes the birth date,
residence, source token, and address canary used by the synthetic source.

## Inspect the audit and clean up

Stop the retained generation before reading its audit view:

```sh
evidencectl dev stop .
evidencectl audit show --last-operation
evidencectl dev clean .
```

The view names the requester pseudonym, definition, purpose, and released output. It does not print
selector values, source facts, tokens, or the returned Boolean. `dev clean` removes generated runtime
state while preserving the editable project, registered client, and request artifacts.

The tutorial runner stops the synthetic source. If you started it by hand, press `Ctrl+C` in its
terminal.
