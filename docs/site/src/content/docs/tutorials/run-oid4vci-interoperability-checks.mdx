You deployed `evidence-oid4vci` on [Deliver to a wallet](../../configure/evidence-oid4vci/). Now
replay the wallet profile it was checked against on your own source build, and watch the runner
print each stage of a wallet flow. Every value in the run is synthetic and discarded on exit.

## Write the adapter configuration

From the checkout root, create an owner-only directory for the runtime file. The client key the
runner generates reaches its processes only through the environment, never this directory:

```sh
umask 077
mkdir -p .tutorial/oid4vci-adopter
```

Copy this file exactly, because the runner refuses a copy that differs from its fixture:

```yaml title=".tutorial/oid4vci-adopter/oid4vci.yaml" test-file
apiVersion: id.registrystack.org/formats/evidence/oid4vci-runtime/v1alpha1
kind: EvidenceOid4vciRuntimeConfig
validationMode: supervised-local-development
credentialIssuer: http://127.0.0.1:18440
listener:
  bind: 127.0.0.1:18440
metricsListener:
  bind: 127.0.0.1:18441
secretProviders:
  environment: {}
evidence:
  baseUrl: http://127.0.0.1:18442
tokenClient:
  tokenEndpoint: http://127.0.0.1:18442/token
  clientId: evidence-oid4vci-tutorial
  privateKeyRef: secret:env/EVIDENCE_OID4VCI_CLIENT_JWK
offers:
  issuer: http://127.0.0.1:18442
  jwksUri: http://127.0.0.1:18442/.well-known/jwks.json
  audiences: ["http://127.0.0.1:18440"]
  algorithms: [ES256]
  authorizedClients: [tutorial-operator]
  requiredScopes: unrestricted
store:
  maximumOffers: 256
  offerLifetimeSeconds: 300
  accessTokenLifetimeSeconds: 300
  nonceLifetimeSeconds: 120
  maximumTransactionCodeAttempts: 3
```

Three keys differ from production, each explained on
[Deliver to a wallet](../../configure/evidence-oid4vci/):
`validationMode: supervised-local-development` admits plain HTTP on `127.0.0.1`,
`secretProviders.environment` reads the key from the environment, and every origin is loopback,
with the runner's synthetic Evidence and token service on 18442.

## Replay the profile

Run the check against your file:

```sh
EVIDENCE_OID4VCI_ADOPTER_ROOT="$PWD/.tutorial/oid4vci-adopter" \
  products/evidence/scripts/compat/inji-oid4vci.sh
```

A successful run ends with:

```text test-excerpt
PASS: sanitized Inji OID4VCI profile and Registry-side interoperability tests
```

That sanitized profile is the interoperability profile, a fixture of the wallet's expected
metadata and wire shapes. The runner asserts it and its upstream receipt, compares the rendered
OpenAPI document with the tracked one when `EVIDENCE_OID4VCI_BIN` names a built binary, then runs
the crate's interoperability test, which prints:

```text test-excerpt
CONFIG CHECKED: complete delivery configuration is valid
METADATA INSPECTED: derived holder-bound batch ceiling is 4
SERVICE READY: health and readiness are available on the delivery listener
METRICS PRIVATE: metrics exist only on the separate loopback listener
TASK GRANT REFUSED: deferred wallet state was not created
PRESENTATION VERIFIED: public wallet flow returned holder-bound Evidence
CLEANUP COMPLETE: generated private material was removed
```

Each line is a milestone: `check` accepted your file; `inspect` published a batch ceiling of four;
`serve` answered `/health` and `/ready` publicly and `/metrics` only on the metrics listener; a task-bound offer
token was refused; a wallet flow driven by the published metadata returned a credential verified as
holder-bound Evidence; and the generated keys were dropped. Any failed case stops the run before
`PASS:`.

for [OID4VCI](/reference/glossary/#oid4vci) states, a pass is bounded evidence for those

## Run the pinned upstream clients

The upstream runner is opt-in: it runs only with `EVIDENCE_INJI_OID4VCI=1` on macOS, builds those
Inji revisions from clean checkouts, and ends with the line `receipt.json` records.

```sh test-skip="the upstream runner needs macOS with Xcode and the iOS Simulator, Java, the Android SDK, and network access"
EVIDENCE_INJI_OID4VCI=1 products/evidence/scripts/compat/inji-oid4vci-upstream.sh
```

## Clean up

A completed run removes its private material. Remove the copied file and its empty directories:

```sh
rm -f .tutorial/oid4vci-adopter/oid4vci.yaml
rmdir .tutorial/oid4vci-adopter .tutorial 2>/dev/null || true
```

After an interrupted run, remove only `.tutorial/oid4vci-adopter`.

## Troubleshooting

The runners name any missing tool or opt-in themselves. Two messages need more:

| Message | Meaning | Recovery |
| --- | --- | --- |
| `the reader-gated configuration must stay identical to the executable fixture` | Your file differs from the fixture. | Copy it again, unchanged. |
| `bind the synthetic Evidence and Mint support listener` or `the real delivery binary did not become ready` | A port from 18440 to 18442 is taken. | Free the port rather than change it, because the file must match the fixture. |
