You run a candidate that signs through a Transit signer, as in
[Configure Transit signing for Evidence Gateway](../move-evidence-to-production-signing/). Move it
to a successor key version without a gap in verification, then retire the predecessor.

## Publish the successor

Rotate the Transit key, read its metadata, and convert the successor key version's public PEM:

```sh test-skip="needs an authenticated Vault or OpenBao operator session"
vault write -f transit/keys/evidence-signing/rotate
vault read -format=json transit/keys/evidence-signing > "<operator-review-path>/evidence-key.json"
```

```sh
jq -r '.data.keys["<successor-version>"].public_key' "<operator-review-path>/evidence-key.json" \
  | evidencectl jwk from-pem - --output-dir "<target>/public-keys"
```

```text test-expect
wrote <target>/public-keys/<successor-thumbprint>.jwk.json (kid <successor-thumbprint>)
```

Keep the predecessor's file. A deployment target cannot author a published-key overlap or a
signing-key denylist (the bundle carries `publishedPublicJwkFiles: []` and `revokedKeyIds: []`), so
rotation relies on overlap trust that consumers hold, set up as in
[Manage verifier trust](../manage-evidence-verifier-trust/). Give consumers both keys as one set:

```sh
evidencectl jwks --output "<overlap.jwks.json>" \
  "<target>/public-keys/<predecessor-thumbprint>.jwk.json" \
  "<target>/public-keys/<successor-thumbprint>.jwk.json"
```

```text test-expect
wrote <overlap.jwks.json>
```

Confirm every consumer trusts the successor before you switch the signer.

## Build and activate the successor

In `target.yaml`, set `signer.keyVersion` to the successor key version and `signer.publicJwkFile`
to the successor's file. Allow both versions in the proxy policy, for example
`"key_version" = [12, 13]`, and keep `min_encryption_version` at or below the predecessor while
replicas still sign with it. Then package; `package` runs the fixtures:

```sh
evidencectl package "<project>" --target "<target>/target.yaml" --output "<successor-candidate>"
```

```text test-excerpt
Package digest: sha256:<package-digest>
Package: <successor-candidate>/bundle
```

Install the bundle at the runtime's `package.root`, then activate the authority and check:

```sh
evidence authority activate --runtime-config "<successor-candidate>/runtime.yaml" \
  --document "<successor-candidate>/compiled-authority.yaml"
evidence check --runtime-config "<successor-candidate>/runtime.yaml" --require-runtime-dependencies
```

```text test-excerpt
ACTIVATED sha256:<authority-revision> sha256:<authority-digest> sequence=<n>
Evidence package sha256:<package-digest> passed check (<count> requirements)
```

Restart every replica, confirm readiness, and verify one synthetic response against the overlap
trust set. Missing or mismatched signing material refuses startup.

{/* Evidence: crates/registry-evidencectl/src/build.rs, prepare_candidate, run_bundle_fixture; crates/registry-evidence/src/authority.rs, activate */}

## Retire the predecessor

Wait for the longest assertion validity plus verifier clock skew after the last instant any replica
could sign with the predecessor. Then remove the old version from the proxy policy and raise the
key's `min_encryption_version` to the successor; the runtime refuses a pinned version below it:

```sh test-skip="needs an authenticated Vault or OpenBao operator session"
vault write transit/keys/evidence-signing/config min_encryption_version=<successor-version>
```

:::caution
Raising `min_encryption_version` stops every replica still pinned to the predecessor. Confirm all
replicas run the successor first.
:::

Ask consumers to drop the predecessor from their trust set.

{/* Evidence: crates/registry-platform-crypto/src/lib.rs, TransitSigner, min_encryption_version */}

## Revoke a compromised version

Raise `min_encryption_version` past the compromised version, or remove the proxy identity's sign
capability, at once. Distribute its thumbprint through the emergency channel so consumers deny it,
then deploy a checked successor or keep the service unavailable. Do not edit bundle bytes to add a
denylist.

For a compromised caller-token issuer key, add its `kid` to `authentication.oidc.revokedKeyIds` in
`target.yaml`, package, and restart.
