Use this procedure after [configuring Transit signing](../move-evidence-to-production-signing/).
Evidence Gateway signs with one active ES256 P-256 key whose `kid` is its RFC 7638 thumbprint.
The normalized target binds that key through `signer.publicJwkFile` and `signer.keyVersion`.
Coordinate new verification trust with consumers before replacing the signer.

## Prepare the successor

You need an approved strict deployment, provider authority to rotate its named Transit key, and a
consumer trust rollout that accepts both generations during the assertion validity window.
Publishing a JWK does not make an independent consumer trust it.

Create a new version of the non-exportable P-256 Transit key. Keep export and plaintext backup
disabled. Read the successor's public PEM and convert it with `evidencectl jwk from-pem`, as in
[publish the exact public projections](../move-evidence-to-production-signing/#publish-the-exact-public-projections).
Commit only the public JWK under `public-keys/<thumbprint>.jwk.json`. Do not overwrite the active file.

:::caution
The private Transit key stays with its provider. Do not export it or replace it with a disposable
local key. A version whose private material has left provider custody must be replaced.
:::

Distribute the successor public key, provider identity, `kid` and activation window through the
approved onboarding channel. Consumers retain the predecessor and add the successor to their
reviewed trust set. Confirm this rollout before activating the signer. The current normalized
target selects one service key; it does not author a second published key set for a JWKS overlap.
Consumers that rely only on cached service JWKS need a coordinated refresh or a cutover window.

## Build and activate the successor

Set the successor's exact public-key reference and provider version together in `target.yaml`:

```yaml
signer:
  type: transit
  algorithm: ES256
  publicJwkFile: public-keys/<next-thumbprint>.jwk.json
  unixSocketPath: /run/registry-evidence/transit-proxy.sock
  mount: transit
  keyName: evidence-signing
  keyVersion: <next-nonzero-version>
  attemptTimeoutMilliseconds: 2000
```

Allow both old and new versions in the proxy policy during the rollout, and keep the provider's
`min_encryption_version` low enough for replicas still pinned to the predecessor.
Build a new candidate and run its fixtures:

```sh
evidencectl package "<deployment-repository>/shared/evidence-project" \
  --target "<deployment-repository>/environments/<environment>/evidence" \
  --output "<new-candidate-directory>"
evidencectl test "<deployment-repository>/shared/evidence-project" \
  --target "<deployment-repository>/environments/<environment>/evidence"
```

Install the exact `bundle/` at the emitted runtime's `package.root`, retain its runtime and compiled
authority separately, and activate the complete authority before the target-host check:

```sh
evidence authority activate --runtime-config "<candidate>/runtime.yaml" \
  --document "<candidate>/compiled-authority.yaml"
evidence check --require-runtime-dependencies --runtime-config "<candidate>/runtime.yaml"
```

Restart every replica to adopt the checked successor. Confirm readiness, send an authorized synthetic
request, and verify the response with the consumer's approved overlap trust set. Missing or
mismatched signing material refuses startup; signing never falls back to an unsigned success.
Target signing changes do not alter a definition's `configurationRevision`.

## Retire the predecessor

Count the longest assertion validity plus accepted verifier clock skew from the last instant any
replica could sign with the predecessor. Keep its public key in consumer trust for at least that
window, and longer when consumers must reverify retained decisions.

After every replica uses the successor and the window has elapsed, remove the old version from the
proxy policy and raise `min_encryption_version` to the successor. Coordinate removal of the old
public key from consumer trust. Keep prior approved candidates and audit history according to the
operator's retention policy.

## Revoke a compromised version

Disable provider signing for the compromised version immediately, using `min_encryption_version`
or removing the proxy identity's signing capability. Distribute its thumbprint through the emergency
onboarding channel so every consumer denies it before resuming decisions. Deploy a checked successor
or keep the service unavailable. The current normalized target does not author a service signing-key
denylist; do not invent a target field or edit immutable bundle bytes to add one.

For a compromised caller-token issuer key, use `authentication.oidc.revokedKeyIds` in `target.yaml`,
build a new candidate and restart Evidence Gateway. This changes token acceptance, not an Evidence
credential-status or lifecycle feature.
