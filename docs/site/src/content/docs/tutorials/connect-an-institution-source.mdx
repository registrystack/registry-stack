Connect an institution source by adapting the normalized project used in
[Return your first Evidence assertion](../first-evidence-assertion/). That journey covers a
synthetic HTTP source, complete local grants, fixtures, caller credentials, and independent
verification. Keep that working boundary while replacing its synthetic source with your reviewed
institution endpoint.

## Keep each decision with its owner

An OpenAPI description identifies transport operations and data shapes. It does not decide the
assertion's purpose, the facts to disclose, the subject mapping, or who may request an answer.
The source owner and assertion provider must review those choices before deployment.

Author named Sources and Functions inside `evidence.yaml`. A Source fixes its request, selector
inputs, bounded response and private fact projection. A definition selects that Source and a
named derivation Function, then governs its purpose, subjects, Outputs and grant ceiling. The
separate target supplies source connections and credentials; its authority supplies complete
caller grants within the project ceilings. Source access never grants caller authority.

## Adapt and prove the project

Use [Configure Registry Evidence](../../configure/evidence/) to edit the owning document and
check the selected target. The [configuration reference](../../reference/evidence-configuration/)
provides accepted key shapes. `evidencectl source suggest` can help draft Source configuration
from an OpenAPI description; review its output as authoring input, then supply assertion meaning
and caller grants yourself.

For a Base Registry Engine (BReg) source, follow [Compose BReg sources with an offline Evidence project](../evidence-from-breg/)
for the export/import boundary. Importing a Source does not supply assertion definitions or caller
authority.

Add synthetic cases for unique matches, missing and ambiguous subjects, invalid source responses,
and refused caller shapes. Run the project checks and fixtures before
[building and deploying a candidate](../build-and-deploy-evidence-project/). Keep real identifiers,
source responses, private keys and credential values out of authored files and test logs.
