In about fifteen minutes you will give two applications access profiles of their own, send the
same region request as each, and see one answered and the other refused. You continue in the project from
[Return a governed value](../return-a-governed-value/), with the source and the run still going.

For the local commands in this tutorial, declare development in your shell.
`rstack dev` sets this value for the processes it starts.

```bash
export REGISTRY_STACK_POSTURE=development
```

## See who may ask today

In `first-evidence-assertion/adult-status`, list the people the run knows:

```sh test-cwd="first-evidence-assertion/adult-status"
jq -c .people run.json
```

```text test-expect
["caller"]
```

A person is one caller's identity: a subject, and a requester tag its token carries. `caller` carries
`standalone-service`, a tag the project's `dev-authority.yaml` admits. That profile grants every
question the project defines, so `caller` may ask them all.

A deployment names who may ask in its target authority. Give two applications a profile with one
grant each. Add these profiles to the end of `dev-authority.yaml`, at the same indentation as
`standalone-service`:

```yaml title="dev-authority.yaml" test-append
  age-checker-service:
    authority: organizational
    actorKind: service
    requesterTags:
    - age-checker-service
    grants:
    - definition: adult-status
      purpose: age-check
      audienceFrom: authenticated-requester
      representations:
      - signed-jws
      subjectBinding: audience-scoped
      subjects:
      - role: subject
        selectorProfile: record-by-id
        valueOrigin: request
  region-router-service:
    authority: organizational
    actorKind: service
    requesterTags:
    - region-router-service
    grants:
    - definition: residence-region
      purpose: residence-check
      audienceFrom: authenticated-requester
      representations:
      - signed-jws
      subjectBinding: audience-scoped
      subjects:
      - role: subject
        selectorProfile: record-by-id
        valueOrigin: request
```

`requesterTags` lists the tags a caller's token must carry to act under the profile. Check that
each grant stays inside its definition's grant ceiling:

```sh
rstack evidence check . --target local-target.yaml
```

```text test-excerpt
warning[evidence.posture.local-assurance] local-target.yaml /assuranceProfile
  local assurance permits locally held signing keys; production refuses it
  next: Build a production or evidence-grade package with a Transit signer.
0 errors, 1 warning in 1 file
```

takes effect after you restart the run.

## Add a person for each profile

Add one person per application to `dev.yaml`. Each token carries its profile's tag:

```diff lang="yaml" title="dev.yaml" test-edit
         claims: {evidence_audience: "urn:example:audience:standalone-app"}
+  age-checker:
+    subject: "urn:registrystack:evidence:local:client:age-checker"
+    client: age-checker
+    grants:
+      evidence:
+        profile: age-checker-service
+        scopes: ["evidence:request"]
+        claims: {evidence_audience: "urn:example:audience:standalone-app"}
+  region-router:
+    subject: "urn:registrystack:evidence:local:client:region-router"
+    client: region-router
+    grants:
+      evidence:
+        profile: region-router-service
+        scopes: ["evidence:request"]
+        claims: {evidence_audience: "urn:example:audience:standalone-app"}
 scenarioFile: tests/scenarios.yaml
```

In a new terminal, read the run back from `run.json` and redefine the helper that fetches a token
header file:

```sh test-cwd="first-evidence-assertion/adult-status"
run_id="$(jq -r .run_id run.json)"
evidence_url="$(jq -r .products.evidence run.json)"
runtime_config="$(jq -r .runtimeConfigs.evidence run.json)"
headers_for() {
  rstack dev token "$run_id" --as "$1" | awk '$1 == "evidence" && $2 == "headers" {print $3}'
}
```

A run takes its people when it starts, so stop it and start a new one. The source keeps running:

```sh
rstack dev stop "$run_id"
rstack dev check .
rstack --format json dev start . --ttl 2h > run.json
run_id="$(jq -r .run_id run.json)"
evidence_url="$(jq -r .products.evidence run.json)"
runtime_config="$(jq -r .runtimeConfigs.evidence run.json)"
jq -c .people run.json
```

```text test-excerpt
["age-checker","caller","region-router"]
```

## Ask for a purpose the definition does not declare

`adult-status` declares only the purpose `age-check`. Ask under another:

```sh test-exit="1"
rstack evidence request prepare adult-status \
  --evidence-url "$evidence_url" \
  --header @"$(headers_for caller)" \
  --runtime-config "$runtime_config" \
  --purpose residence-check \
  --subject subject:record-id=adult \
  --name adult-wrong-purpose
```

```text test-expect
evidencectl: purpose does not match the published definition
```

Preparation refuses it, so nothing reaches Registry Evidence.

## Send the region request as each person

Preparation checks the request against the definitions the service publishes, not against the
caller's grants. Prepare the region request once:

```sh
rstack evidence request prepare residence-region \
  --evidence-url "$evidence_url" \
  --header @"$(headers_for caller)" \
  --runtime-config "$runtime_config" \
  --purpose residence-check \
  --subject subject:record-id=adult \
  --name region-request
```

Send it as `region-router`; Registry Evidence applies the grants the profile for its tag admits,
and `region-router-service` grants `residence-region`:

```sh
rstack evidence api /v1/evidence \
  --url "$evidence_url" \
  --header @"$(headers_for region-router)" \
  --input .evidence/requests/region-request/request.json \
  --accept application/jose+json \
  --output region-by-router.response
```

Send the same request as `age-checker`. `age-checker-service` grants only `adult-status`, so the
API writes the refusal body and exits 1 for the HTTP 403 response:

```sh test-exit="1"
rstack evidence api /v1/evidence \
  --url "$evidence_url" \
  --header @"$(headers_for age-checker)" \
  --input .evidence/requests/region-request/request.json \
  --accept application/jose+json \
  --output region-by-age-checker.response
```

Read the refusal `age-checker` received:

```sh
jq . region-by-age-checker.response
```

```json test-expect
{
  "type": "https://id.registrystack.org/problems/registry-evidence/evidence/denied",
  "title": "Evidence request is not permitted",
  "status": 403,
  "detail": "the Evidence request is not permitted",
  "code": "evidence.denied",
  "traceId": "<trace-id>"
}
```

`evidence.denied` does not name the missing grant.
[Evidence problems](../../reference/evidence-problems/) lists every code.

Leave the source and the run going; the next tutorial continues with them.
