## Define complete access profiles

Enter the copied project:

```sh test-cwd="first-evidence-assertion"
cd adult-status
```

The existing `standalone-service` profile keeps the earlier tutorials composable. Add two narrow
profiles for these applications to the end of `dev-authority.yaml`, at the same indentation as
`standalone-service`:

```yaml title="dev-authority.yaml" test-append
  age-checker-service:
    authority: organizational
    actorKind: service
    requesterTags:
    - age-checker-service
    grants:
    - definition: adult-status
      purpose: age-check
      audienceFrom: authenticated-requester
      representations:
      - signed-jws
      subjectBinding: audience-scoped
      subjects:
      - role: subject
        selectorProfile: record-by-id
        valueOrigin: request
  region-router-service:
    authority: organizational
    actorKind: service
    requesterTags:
    - region-router-service
    grants:
    - definition: residence-region
      purpose: residence-check
      audienceFrom: authenticated-requester
      representations:
      - signed-jws
      subjectBinding: audience-scoped
      subjects:
      - role: subject
        selectorProfile: record-by-id
        valueOrigin: request
```

Each grant repeats the complete authorized request shape. The target compiler checks it against the
project's grant ceiling. A profile cannot widen the definition's allowed authority, actor kind,
value origin, audience, subject binding, or representation.

Check the edited target, then register each application under one profile:

```sh
evidencectl check . --target local-target.yaml
evidencectl access client add age-checker \
  --access-profile age-checker-service \
  --generate-local-key
evidencectl access client add region-router \
  --access-profile region-router-service \
  --generate-local-key
evidencectl access client list
```

Client registration binds an identity to reviewed target authority. It does not copy grant fields
into a separate policy document.

## Start the protected service

In another terminal, start the synthetic source:

```sh test-cwd="first-evidence-assertion/adult-status" test-background="http://127.0.0.1:8081/healthz"
python3 serve-source.py \
  --port 8081 \
  --token-file .generated/secrets/synthetic-source-token
```

Back in the project terminal, start one generation containing the project, target, authority, and
client registry:

```sh
evidencectl dev start . \
  --target local-target.yaml \
  --evidence-port 18080 \
  --issuer-port 8082
```

```text test-excerpt
Evidence ready at http://127.0.0.1:18080
```

## Prove the age checker's grant

Prepare the request that `age-checker-service` grants:

```sh
evidencectl request prepare adult-status \
  --client age-checker \
  --purpose age-check \
  --subject subject:record-id=adult \
  --name age-allowed
```

Send and verify it:

```sh
curl --silent --show-error --fail-with-body \
  --config .evidence/requests/age-allowed/authorization.curl \
  --request POST \
  --url http://127.0.0.1:18080/v1/evidence \
  --header 'Content-Type: application/json' \
  --header 'Accept: application/jose+json' \
  --data-binary @.evidence/requests/age-allowed/request.json \
  --output age-allowed.jws.json \
  --write-out 'HTTP %{http_code}\n'

evidencectl verify age-allowed.jws.json \
  --context .evidence/requests/age-allowed/verification.json \
  --output age-allowed.verified.json
```

```text test-expect
HTTP 200
VERIFIED
```

## Cross the authorization boundary

Prepare a valid region request as `region-router`. Preparation sends nothing to Evidence Gateway:

```sh
evidencectl request prepare residence-region \
  --client region-router \
  --purpose residence-check \
  --subject subject:record-id=adult \
  --name region-prepared
```

Now send that region body with `age-checker`'s valid authorization. The token is authentic, but its
profile grants only `adult-status`:

```sh
curl --silent --show-error \
  --config .evidence/requests/age-allowed/authorization.curl \
  --request POST \
  --url http://127.0.0.1:18080/v1/evidence \
  --header 'Content-Type: application/json' \
  --header 'Accept: application/jose+json' \
  --data-binary @.evidence/requests/region-prepared/request.json \
  --output region-denied.json \
  --write-out 'HTTP %{http_code}\n'
```

```text test-expect
HTTP 403
```

The public problem is `evidence.denied`. It does not reveal the missing grant, source facts,
selector, or credentials. Evidence Gateway refuses the request before source access.

```sh
evidencectl dev stop .

evidencectl dev clean .
```
