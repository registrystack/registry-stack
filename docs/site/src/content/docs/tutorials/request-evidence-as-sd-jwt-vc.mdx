You will permit SD-JWT VC in both the project ceiling and the target's complete grant, request one
credential, verify it, and prove that a changed disclosure is refused.

## Permit the representation twice

Enter the copied project:

```sh test-cwd="first-evidence-assertion"
cd adult-status
```

The definition's representation list is the governed package ceiling. Add `sd-jwt-vc` to
`adult-status` while keeping signed JWS:

```diff lang="yaml" title="evidence.yaml" test-edit
    subjectBinding: audience-scoped
    representations:
    - signed-jws
+   - sd-jwt-vc
    observationTimezone: Asia/Bangkok
```

The target grant must also permit the representation. Add it to the complete `adult-status` grant
in `dev-authority.yaml`:

```diff lang="yaml" title="dev-authority.yaml" test-edit
    - definition: adult-status
      purpose: age-check
      audienceFrom: authenticated-requester
      representations:
      - signed-jws
+     - sd-jwt-vc
      subjectBinding: audience-scoped
```

The project ceiling says what this definition may emit. The target grant says what this requester
profile may receive. Both must include the format; a client cannot widen either list.

Prove the edited project and target, then create a client for this tutorial against the changed
profile digest. The first tutorial's client keeps its registration against the earlier digest:

```sh
evidencectl check . --target local-target.yaml
evidencectl test . --target local-target.yaml
evidencectl access client add wallet-client \
  --access-profile standalone-service \
  --generate-local-key
```

## Start the local boundary

In another terminal, start the synthetic source:

```sh test-cwd="first-evidence-assertion/adult-status" test-background="http://127.0.0.1:8081/healthz"
python3 serve-source.py \
  --port 8081 \
  --token-file .generated/secrets/synthetic-source-token
```

Back in the project terminal, start a fresh generation:

```sh
evidencectl dev start . \
  --target local-target.yaml \
  --evidence-port 18080 \
  --issuer-port 8082
```

```text test-excerpt
Evidence ready at http://127.0.0.1:18080
```

## Request and verify SD-JWT VC

Record the required response format before a response exists:

```sh
evidencectl request prepare adult-status \
  --client wallet-client \
  --purpose age-check \
  --subject subject:record-id=adult \
  --response-format sd-jwt-vc \
  --name adult-status-vc
```

Send the request with the SD-JWT VC media type:

```sh
curl --silent --show-error --fail-with-body \
  --config .evidence/requests/adult-status-vc/authorization.curl \
  --request POST \
  --url http://127.0.0.1:18080/v1/evidence \
  --header 'Content-Type: application/json' \
  --header 'Accept: application/dc+sd-jwt' \
  --data-binary @.evidence/requests/adult-status-vc/request.json \
  --output adult-status.sd-jwt-vc \
  --write-out 'HTTP %{http_code}\n'
```

```text test-expect
HTTP 200
```

Verify before decoding or reading a disclosure:

```sh
evidencectl verify adult-status.sd-jwt-vc \
  --context .evidence/requests/adult-status-vc/verification.json \
  --output adult-status-vc.verified.json
```

```text test-expect
VERIFIED
```

The verified payload contains the same Boolean adult-status output as signed JWS. The response
format changes serialization, not the source, derivation, authorization, audience, or subject
binding.

## Prove tampering is refused

Change one encoded disclosure byte in a copy:

```sh
python3 - <<'PY'
from pathlib import Path

parts = Path("adult-status.sd-jwt-vc").read_text().strip().split("~")
assert len(parts) >= 3 and parts[1]
parts[1] = ("A" if parts[1][0] != "A" else "B") + parts[1][1:]
Path("adult-status-tampered.sd-jwt-vc").write_text("~".join(parts) + "\n")
PY
```

Verification fails without publishing trusted output:

```sh test-exit="1"
evidencectl verify adult-status-tampered.sd-jwt-vc \
  --context .evidence/requests/adult-status-vc/verification.json \
  --output adult-status-tampered.verified.json
```

```text test-expect
evidencectl: Evidence response verification failed
```

The issuer signature covers the disclosure digest. Changing the disclosure breaks that verified
relationship.

## Clean up

```sh
evidencectl dev stop .
evidencectl access client revoke wallet-client
evidencectl audit show --last-operation
evidencectl dev clean .
```

The tutorial runner stops the source. If you started it by hand, press `Ctrl+C` in its terminal.
