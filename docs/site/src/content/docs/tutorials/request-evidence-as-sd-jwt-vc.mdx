If your relying parties expect a Selective Disclosure JWT Verifiable Credential (SD-JWT VC),
permit that representation for `adult-status`, then request and verify one. You continue in the
project from [Assert a role-bound relationship](../assert-a-role-bound-relationship/), with the
source and Evidence Gateway still running, and finish by stopping both and reading the audit.

## Permit the representation

Evidence Gateway reads the project only as it starts. In `first-evidence-assertion/adult-status`,
stop it while you change the project; the source keeps running:

```sh test-cwd="first-evidence-assertion/adult-status"
evidencectl dev stop .
```

```text test-expect
Local Evidence stopped
```

A definition's `representations` lists the encodings it may emit. Add `sd-jwt-vc` to
`adult-status`:

```diff lang="yaml" title="evidence.yaml" test-edit
    subjectBinding: audience-scoped
    representations:
    - signed-jws
+   - sd-jwt-vc
    observationTimezone: Asia/Bangkok
```

Add it to the `adult-status` grant too:

```diff lang="yaml" title="dev-authority.yaml" test-edit
    - standalone-service
    grants:
    - definition: adult-status
      purpose: age-check
      audienceFrom: authenticated-requester
      representations:
      - signed-jws
+     - sd-jwt-vc
      subjectBinding: audience-scoped
```

Both lists must name it. The grant belongs to the `standalone-service` profile, so every client
on that profile, `tutorial-client` and `example-caller` alike, may now ask for the SD-JWT VC
representation. Check the project:

```sh
evidencectl check . --target local-target.yaml
```

```text test-excerpt
0 errors, 0 warnings
```

## Start Evidence Gateway with the change

Start Evidence Gateway again with the same ports, so it loads the changed definition and grant:

```sh
evidencectl dev start . \
  --target local-target.yaml \
  --evidence-port 18080 \
  --issuer-port 8082
```

```text test-excerpt
Evidence ready at http://127.0.0.1:18080
```

## Request and verify an SD-JWT VC

Name the representation with `--response-format`, send the SD-JWT VC media type, and verify the
response:

```sh
evidencectl request prepare adult-status \
  --client tutorial-client \
  --purpose age-check \
  --subject subject:record-id=adult \
  --response-format sd-jwt-vc \
  --name adult-status-vc
curl --silent --show-error --fail-with-body \
  --config .evidence/requests/adult-status-vc/authorization.curl \
  --request POST \
  --url http://127.0.0.1:18080/v1/evidence \
  --header 'Content-Type: application/json' \
  --header 'Accept: application/dc+sd-jwt' \
  --data-binary @.evidence/requests/adult-status-vc/request.json \
  --output adult-status.sd-jwt-vc \
  --write-out 'HTTP %{http_code}\n'
evidencectl verify adult-status.sd-jwt-vc \
  --context .evidence/requests/adult-status-vc/verification.json \
  --output adult-status-vc.verified.json
```

```text test-excerpt
HTTP 200
VERIFIED
```

Print the value as you did for the signed JWS:

```sh
jq '{supportsRequirement, supportedValues}' adult-status-vc.verified.json
```

```json test-expect
{
  "supportsRequirement": "urn:example:requirement:adult-status:v1",
  "supportedValues": [
    {
      "providesValueFor": "urn:example:concept:adult-status:v1",
      "value": true
    }
  ]
}
```

The representation changes the encoding, not the answer.

## Prove a changed disclosure is refused

Each claim travels as a disclosure after a `~`, and the signature covers its digest. Change one
byte of the first disclosure in a copy:

```sh
python3 - <<'PY'
from pathlib import Path

parts = Path("adult-status.sd-jwt-vc").read_text().strip().split("~")
parts[1] = ("A" if parts[1][0] != "A" else "B") + parts[1][1:]
Path("adult-status-tampered.sd-jwt-vc").write_text("~".join(parts) + "\n")
PY
```

Verification refuses the copy:

```sh test-exit="1"
evidencectl verify adult-status-tampered.sd-jwt-vc \
  --context .evidence/requests/adult-status-vc/verification.json \
  --output adult-status-tampered.verified.json
```

```text test-expect
evidencectl: Evidence response verification failed
```

{/* Evidence: crates/registry-platform-sdjwt/src/lib.rs, issue_disclosure. */}

## Stop and read the audit

Evidence Gateway wrote an audit event before it read the source and another before the response
left. `evidencectl audit show` reads them only from a stopped session, so stop it and show the last
operation, your SD-JWT VC request:

```sh
evidencectl dev stop .
evidencectl audit show --last-operation
```

```text test-excerpt
ACCESS AUTHORIZED adult-status age-check requester=<pseudonym>
DISCLOSURE RELEASED adult
```

A pseudonymous requester was authorized for `adult-status` under `age-check`, and the `adult`
output was released. The value is not shown.

`dev clean` removes the stopped session's generated state, including those audit files. The
project, its keys, and its clients stay:

```sh
evidencectl dev clean .
```

```text test-expect
Removed stopped local Evidence state
```

Press `Ctrl+C` in the source's terminal to stop the source.
