permit that representation for `adult-status`, then request and verify one. You continue in the
project from [Assert a role-bound relationship](../assert-a-role-bound-relationship/), with the
source and the run still going, and finish with the run still going.

## Permit the representation

A run reads the project only as it starts. In `first-evidence-assertion/adult-status`, stop the
run while you change the project; the source keeps running:

In a new terminal, read the run back from `run.json` and redefine the helper that fetches a token
header file:

```sh test-cwd="first-evidence-assertion/adult-status"
run_id="$(jq -r .run_id run.json)"
evidence_url="$(jq -r .products.evidence run.json)"
runtime_config="$(jq -r .runtimeConfigs.evidence run.json)"
headers_for() {
  rstack dev token "$run_id" --as "$1" | awk '$1 == "evidence" && $2 == "headers" {print $3}'
}
```

```sh test-cwd="first-evidence-assertion/adult-status"
rstack dev stop "$run_id"
```

```text test-expect
Run <run-id> stopped
```

A definition's `representations` lists the encodings it may emit, and a grant in
`dev-authority.yaml` lists the ones it admits. Add `sd-jwt-vc` to `adult-status`:

```diff lang="yaml" title="evidence.yaml" test-edit
    subjectBinding: audience-scoped
    representations:
    - signed-jws
+   - sd-jwt-vc
    observationTimezone: Asia/Bangkok
```

Add it to the `adult-status` grant too:

```diff lang="yaml" title="dev-authority.yaml" test-edit
    - standalone-service
    grants:
    - definition: adult-status
      purpose: age-check
      audienceFrom: authenticated-requester
      representations:
      - signed-jws
+     - sd-jwt-vc
      subjectBinding: audience-scoped
```

Both lists must name it, and the grant keeps `signed-jws`, so the run's own scenario still
passes. The grant belongs to the `standalone-service` profile, so every caller
on that profile may ask for the SD-JWT VC representation once a deployment applies it. Check the
project:

```sh
# rstack dev sets this for the processes it starts.
export REGISTRY_STACK_POSTURE=development
rstack evidence check . --target local-target.yaml
```

```text test-excerpt

  local assurance permits locally held signing keys; production refuses it
  next: Build a production or evidence-grade package with a Transit signer.
0 errors, 1 warning in 1 file
```

## Start a run with the change

Start a run again, so it loads the changed definition:

```sh
rstack dev check .
rstack --format json dev start . --ttl 2h > run.json
run_id="$(jq -r .run_id run.json)"
evidence_url="$(jq -r .products.evidence run.json)"
runtime_config="$(jq -r .runtimeConfigs.evidence run.json)"
```

## Request and verify an SD-JWT VC

Name the representation with `--response-format`, send the SD-JWT VC media type, and verify the
response:

```sh
rstack evidence request prepare adult-status \
  --evidence-url "$evidence_url" \
  --header @"$(headers_for caller)" \
  --runtime-config "$runtime_config" \
  --purpose age-check \
  --subject subject:record-id=adult \
  --response-format sd-jwt-vc \
  --name adult-status-vc
rstack evidence api /v1/evidence \
  --url "$evidence_url" \
  --header @"$(headers_for caller)" \
  --input .evidence/requests/adult-status-vc/request.json \
  --accept application/dc+sd-jwt \
  --output adult-status.sd-jwt-vc
rstack evidence verify adult-status.sd-jwt-vc \
  --context .evidence/requests/adult-status-vc/verification.json \
  --output adult-status-vc.verified.json
```

```text test-excerpt
VERIFIED
```

Print the value as you did for the signed JWS:

```sh
jq '{supportsRequirement, supportedValues}' adult-status-vc.verified.json
```

```json test-expect
{
  "supportsRequirement": "urn:example:requirement:adult-status:v1",
  "supportedValues": [
    {
      "providesValueFor": "urn:example:concept:adult-status:v1",
      "value": true
    }
  ]
}
```

The representation changes the encoding, not the answer.

## Prove a changed disclosure is refused

Each claim travels as a disclosure after a `~`, and the signature covers its digest. Change one
byte of the first disclosure in a copy:

```sh
python3 - <<'PY'
from pathlib import Path

parts = Path("adult-status.sd-jwt-vc").read_text().strip().split("~")
parts[1] = ("A" if parts[1][0] != "A" else "B") + parts[1][1:]
Path("adult-status-tampered.sd-jwt-vc").write_text("~".join(parts) + "\n")
PY
```

Verification refuses the copy:

```sh test-exit="1"
rstack evidence verify adult-status-tampered.sd-jwt-vc \
  --context .evidence/requests/adult-status-vc/verification.json \
  --output adult-status-tampered.verified.json
```

```text test-expect
evidencectl: Evidence response verification failed
```
