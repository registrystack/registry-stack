Registry Stack helps institutions manage controlled access to authoritative data.
Evidence Gateway signs the answer to a bounded question, Registry Relay publishes selected
records from an existing source, and the Registry Server source preview provides a
configuration-defined writable registry backed by PostgreSQL.

## Answer a bounded question with Evidence Gateway

Use Evidence Gateway when the caller needs to learn only a fact, not to read a record.
It answers one bounded question about one subject and signs the answer,
releasing the answer rather than the row behind it. For example, a licensing authority can
answer whether a professional licence is active. Requirements and their permitted outputs
come from reviewed configuration.

[Evidence Gateway overview](start/evidence-quickstart/) explains the source, assertion,
verification, and audit boundaries. Continue with
[your first Evidence Gateway assertion](tutorials/first-evidence-assertion/) to see the
boundary in one verified request. When local authoring is complete,
[build and deploy an Evidence Gateway project](tutorials/build-and-deploy-evidence-project/) creates a
reviewed candidate without promoting local development state. Registry Mint remains an optional
token issuer for deployments without a suitable identity provider.

## Publish selected records with Registry Relay

Use Relay when the caller needs to read specific records or fields. The
institution exposes a reviewed read-only SQLite view, a data publisher writes
one contract naming the resources, operations, access profiles, and disclosure
rules, and `relayctl` compiles, tests, and seals that contract into a package
the `relay` service verifies before it opens a listener. Database tables and
columns never become routes by convention.

[Publish a governed SQLite registry](tutorials/publish-governed-sqlite-registry/)
runs the supplied synthetic business Registry end to end in about 20 minutes.
Continue with [author a Registry Relay project](configure/relay/) to bind an
institution-owned view, then [operate Registry Relay](operate/relay/) for
sources, token issuers, audit retention, and revision replacement.

## Build a writable registry with Registry Server

Use Server when you need a system of record, including create and update operations.
Your project defines entities, relationships, constraints, and caller permissions; the compiler
generates the storage and REST contract. Holdings, plots, businesses, and assets are configured
models, not built-in server types. Server is currently documented as an unreleased source preview.

Start with the [Registry Server overview](explanation/configuration-defined-registry/), then
[create and query your first registry](tutorials/first-registry-server/). Continue with
[configure your registry](configure/registry-server/) to extend the model and prepare a tested
deployment handoff.

Follow [review changes before updating records](tutorials/review-registry-changes/) to configure
change requests, approval stages, and controlled writes.

Use [query a spatial registry from QGIS](tutorials/query-a-spatial-registry-from-qgis/) to start
the supplied PostGIS fixture, connect a protected Point layer, and verify a map refresh after an
authenticated write.

Use [modeling patterns](explanation/registry-modeling-patterns/) to choose identifier, relationship,
declaration, provenance, and document-reference structures for your registry.

Follow [configure webhooks](configure/registry-server-webhooks/) to notify another service.
Use the [configuration reference](reference/registry-server-configuration/) to look up keys,
defaults, and constraints.
Use the [history reference](reference/registry-server-history/) for saved snapshots,
effective-time queries, correction context, and retained-history erasure, and the
[events and webhooks reference](reference/registry-server-events/) for the receiver contract,
signatures, and delivery behavior.

## Keep the product boundaries clear

Registry Relay owns source access and protected record surfaces.
Evidence Gateway owns bounded question answering, signing, and minimum disclosure, and
runs independently of Relay against its own configured authoritative sources.
The caller receives only the output authorized for that service.

The products have separate adopter tooling and deployment contracts, while reusing shared
Registry Platform primitives. A Relay deployment is
one sealed package per process, authored with `relayctl` and served by `relay`.
Evidence Gateway has its own toolset and deployment project shape, covered by the
[Evidence Gateway overview](start/evidence-quickstart/). Relay responses are not
signed: portable signed minimum disclosure is what Evidence Gateway is for.
Server owns its PostgreSQL records; it does not automatically publish them through Relay or
configure Evidence Gateway on your behalf.
