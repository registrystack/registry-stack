Registry Stack helps an institution expose protected, read-only registry APIs
and return bounded evidence without giving callers direct access to the source
system.

## Start with the HTTP project

The Registry Stack 1.0 beginner path creates the maintained HTTP project,
executes its fixtures offline, and runs the real Registry Relay and Registry
Notary path in a disposable development environment.

[Build and run an HTTP registry project](tutorials/author-registry-project/)
is the one current first-success path.
It uses released artifacts and does not require a source checkout.

## Choose an initialization template

Registryctl provides two public templates:

- `http` for a bounded HTTP source and a reviewed response projection
- `spreadsheet` for one strictly described workbook

OAuth-backed Rhai is an adaptation of the HTTP project, not another template
or runtime.
The [Connect your data overview](configure/) routes each source pattern to its
current guidance.

## Keep the workflow boundaries visible

`test` is always offline.
`dev` owns disposable local runtime actions.
`review`, `trust`, and `deploy` prepare independently approved product lanes
for an operator, but they do not activate a deployment.

The [validation guide](verify/) separates those checks.
The [generated files guide](generated-artifacts/) identifies which outputs
Registryctl may replace.
