If you are preparing a Registry Casework candidate, keep reviewed policy and
deployment-owned bindings separate. Authors control queues, profiles, hosted
kinds, routing, and clocks. Operators control PostgreSQL credentials, identity,
secrets, source endpoints, the listener, and the active package.

Registry Casework is not in a published release yet. Build `caseworkctl` from
the same reviewed source revision as the runtime before following this procedure.

## Start an authored project

Create a source-free project when an integration service needs a bounded human
decision:

```sh
caseworkctl init ./casework --template standalone-decision
caseworkctl check ./casework
caseworkctl explain ./casework
caseworkctl test ./casework
```

`init` refuses an existing destination. If the destination already exists,
choose a new directory or review the existing project rather than overwriting it.
The starter creates `casework.yaml`, synthetic fixtures, and
`runtime.example.yaml`. Copy the runtime example to `runtime.yaml`; keep the
runtime file and its secrets out of the policy package.

For work from Base Registry Engine (BReg), start with
`--template professional-review`, then preview
the exact source changes before applying them:

```sh
caseworkctl source add ./registry \
  --project ./casework --source-id professional-register
caseworkctl source add ./registry \
  --project ./casework --source-id professional-register --apply
caseworkctl check ./casework
caseworkctl test ./casework
```

The apply step changes reviewed local authoring inputs. It does not activate a
production package or grant a person source authority.

`check`, `explain`, and `test` are offline. An authoring check can succeed with
visible findings when a declared source description has not been imported. Add
`--deny-findings` to refuse any finding, or `--production` to require complete
deployment policy. `test` reports the same authoring status and findings before
evaluating synthetic fixtures, so fixtures may pass while authoring remains
incomplete. Its proof boundary is offline and synthetic; it does not establish
production closure, source reachability, or a completed human and source-system
journey.

Caseworkctl prints human-readable reports by default. Add the global `--format
json` option for structured output. It exits `0` on success, `1` for a domain
refusal or denied finding, `2` for command-line usage, and `3` for an
operational failure.

## Bind the runtime configuration

Set `package.root` to the absolute path of the selected package directory. The
runtime loads `casework.yaml` from that root and verifies the adjacent package
manifest for production. The required `listener` block selects its bind,
TLS-termination, and network-exposure boundary. `secretProviders` explicitly
enables the optional file provider, environment provider, or both; a file
provider root is absolute, and an environment secret reference is valid only
when the environment provider is enabled. Configure separate runtime and
migration database URL references, the OpenID Connect (OIDC) issuer and
audience, the human-identity assertion, and absolute `audit.path` with its
`hashKeyRef`. The runtime `sources` map is keyed by the exact source IDs
declared in policy. A standalone project has no source bindings.

The runtime document starts with
`apiVersion: registry.registrystack.org/casework-runtime/v1alpha1` and
`kind: CaseworkRuntimeConfig`. Operated resource paths are absolute. The
development listener defaults to `127.0.0.1:8100`; set another private address
explicitly when the deployment requires it.

Production uses `listener.tlsTermination: operator-controlled-upstream`. Put a TLS proxy
or ingress in front of the private listener. Use `listener.networkExposure:
container-private` only for a wildcard listener confined to a private container
network. Direct plaintext development uses `development-loopback` with a
loopback listener and `private-address` exposure.

Configure the issuer to reserve the Staff, Supervisor, and Administrator scopes
for interactive human sessions carrying the exact human assertion. Each
`accessProfiles[]` entry selects its own `principalClaim`; there is no runtime
wide `authentication.oidc.principalClaim`. Issue the Requester scope to service
clients. Directory membership remains a second, runtime-controlled authority
check. A source-backed operation also requires the caller to select a separate
source profile, which Casework passes to the source under that caller's token.

## Package reviewed policy

Package the exact policy and imported source descriptions into a new directory:

```sh
caseworkctl package ./casework --output ./casework-policy-package
```

The command refuses an existing output directory. Review
`casework.package.json`, then set the production runtime file's `package.root`
to the package directory's absolute path. Production startup verifies the
manifest's policy digest, file digests, and byte counts. Install and select the
reviewed directory atomically before restarting or rolling out Casework.

Run `caseworkctl --help` for the complete current command surface.
