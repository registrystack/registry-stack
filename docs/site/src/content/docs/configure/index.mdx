Start from the tested HTTP project, prove its synthetic contract, then
introduce one reviewed institution-owned registry source.
Registry Stack does not infer access policy, safe fields, or evidence claims
from source data.

## Start from the HTTP project

Use the `http` template when the source already exposes an HTTP API.
It contains one bounded synthetic interaction that you can replace with a
reviewed HTTP or Rhai integration.

Domain systems such as OpenCRVS, DHIS2, and Fast Healthcare Interoperability
Resources (FHIR) remain authored integrations.
They are not public templates or privileged runtime connector types.

## Keep authored and generated files separate

You own the project, integration, entity, fixture, and environment files.
Registryctl owns files under `.registry-stack/` and may replace them.

Fixtures contain synthetic interactions and expected minimized results.
They never authorize a live network request.
`registryctl test` remains offline for every source pattern.
