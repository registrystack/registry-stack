A ReviewTask waits in a queue until someone eligible picks it up. Which people that is lives in
the [directory](../../reference/glossary/#directory), not in the policy. You continue in
`tutorial-work/casework`, with the `rstack dev` run you restarted in
[Author a Casework policy](../casework/) still going.

## What the directory holds

The policy declares the [queues](../../reference/glossary/#queue) and, for each
[team](../../reference/glossary/#team) it names, the profiles its members and supervisors must
hold. The directory is runtime state: each team's staff and supervisors, as an issuer and a
subject, and the queues the team serves, under one directory revision. A person reaches a queue's
tasks only as a member of a team that serves it, while holding a profile that may decide the stage.
Changing who is in a team needs no new package.

Only an [access profile](../../reference/glossary/#access-profile) with the `administrator` role may read or change the directory.

## Seed it for the development run

A new directory is empty. The run's scenario, `tests/scenarios.yaml`, seated the team with the same
bootstrap call a deployment uses, as the plan's `administrator` person:

```yaml title="tests/scenarios.yaml" test-excerpt="tutorial-work/casework/tests/scenarios.yaml"
body:
  teamId: decisions-team
  staff: [{issuer: https://identity.standalone.example.test, subject: staff}]
  supervisors: []
  queueId: decisions
```

The body names one team and the one declared queue it serves. Its staff and supervisors are an
issuer and a subject each, here the issuer and subject `staff` signs in with in `dev.yaml`.

## Read the directory

Find the run you left going. The start report you saved in `run.json` names it:

```sh test-cwd="tutorial-work/casework"
run_id="$(jq -r .run_id run.json)"
casework_url="$(jq -r .products.casework run.json)"
headers_for() {
  rstack dev token "$run_id" --as "$1" | awk '$1 == "casework" && $2 == "headers" {print $3}'
}
```

Read the directory as the administrator to confirm every queue has a team:

```sh test-cwd="tutorial-work/casework"
curl -sS --fail-with-body --header @"$(headers_for administrator)" "$casework_url/v1/directory" | jq .
```

```json test-excerpt
{"revision": 1}
```

```json test-excerpt
{"id": "decisions-team", "servedQueues": ["decisions"]}
```

## Bootstrap a deployment's directory

A deployment's first administrator creates the first team with one call, naming directory revision `0` and an idempotency key so a retry cannot create it twice:

```json title="directory-bootstrap.json"
{
  "teamId": "decisions-team",
  "queueId": "decisions",
  "staff": [
    {"issuer": "https://identity.example.test/realms/registry", "subject": "<staff subject>"}
  ],
  "supervisors": [
    {"issuer": "https://identity.example.test/realms/registry", "subject": "<supervisor subject>"}
  ]
}
```

```sh test-skip="the run's scenario already seeded its directory, so revision 0 is refused"
curl -sS --fail-with-body --header @"$(headers_for administrator)" \
  --header 'Content-Type: application/json' \
  --header 'If-Match: "0"' \
  --header 'Idempotency-Key: directory-bootstrap-1' \
  --data @directory-bootstrap.json "$casework_url/v1/directory/bootstrap"
```

Casework refuses a queue the active package does not declare. Later changes go through
`PUT /v1/directory/teams/{teamId}` with the team's `staff`, `supervisors` and `servedQueues`, each
under the directory revision you last read, so two administrators cannot overwrite each other.
The [Casework API reference](../../reference/apis/registry-casework/) lists every directory
operation.
