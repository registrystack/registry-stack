If you run an Evidence Gateway and a wallet must receive its holder-bound
[SD-JWT VC](/reference/glossary/#sd-jwt-vc) responses over
[OID4VCI](/reference/glossary/#oid4vci), run `evidence-oid4vci` beside it. It speaks the wallet
protocol Evidence Gateway does not, and turns each response into the credential the wallet stores.
It never signs, never holds a holder private key, and adds no Evidence semantics, so
[how Evidence works](/explanation/how-evidence-works/) still describes every decision.

{/* Evidence: crates/registry-evidence-oid4vci/src/lib.rs; AGENTS.md. */}

## What you need

- A definition with `subjectBinding: holder-bound` that permits `sd-jwt-vc`, as
  [Enable SD-JWT VC](../enable-sd-jwt-vc/) sets up. The front end offers only
  [holder-bound](/reference/glossary/#holder-bound) definitions.
- A running Evidence Gateway, as
  [Build and deploy an Evidence project](../../tutorials/build-and-deploy-evidence-project/) leaves
  you.
- A TLS proxy that publishes the front end's public HTTPS origin.
- The `evidence-oid4vci` binary, which the
  [same installer](../../tutorials/build-and-deploy-evidence-project/#what-you-need) installs beside
  `evidence` and `evidencectl`, or the image `ghcr.io/registrystack/evidence-oid4vci:<tag>` from the
  [latest release](https://github.com/registrystack/registry-stack/releases/latest). The image runs
  as the distroless `nonroot` user (uid 65532), exposes port 8090, and runs
  `serve --runtime-config /etc/registry-evidence-oid4vci/runtime.yaml`. Mount the runtime file and
  the token client key read-only; the image has no shell, so your platform owns the probes.

## Write the runtime file

The runtime file names the front end's public origin, the Evidence Gateway it fronts, the token
client it calls that gateway with, and who may create a credential offer. Start from this one and
replace every origin with your own:

```yaml title="runtime.yaml" test-file
# yaml-language-server: $schema=https://id.registrystack.org/schemas/evidence/oid4vci-runtime/oid4vci-runtime.v1alpha1.schema.json
apiVersion: id.registrystack.org/formats/evidence/oid4vci-runtime/v1alpha1
kind: EvidenceOid4vciRuntimeConfig
credentialIssuer: https://wallet.example.org
listener:
  bind: 127.0.0.1:8090
secretProviders:
  file:
    root: /run/secrets/evidence-oid4vci
evidence:
  baseUrl: https://evidence.example.org
tokenClient:
  tokenEndpoint: https://mint.example.org/token
  clientId: evidence-oid4vci
  privateKeyRef: secret:file/delivery-client.jwk.json
  resource: https://evidence.example.org
offers:
  issuer: https://mint.example.org
  jwksUri: https://mint.example.org/.well-known/jwks.json
  audiences: ["https://wallet.example.org"]
  authorizedClients: [adopter-front-end]
  requiredScopes: [oid4vci:offer]
store:
  maximumOffers: 4096
```

`credentialIssuer` is the public origin your TLS proxy publishes, which wallets see.
`listener.bind` is the private address the proxy forwards to: keep a loopback or private address
on a non-zero port such as `8090`, not the public origin's `443`. The listener speaks plain HTTP.

`privateKeyRef` follows the [secret reference grammar](../../reference/environment-variables/#secret-references).
The key file must be a regular file owned by the service user, mode `0400` or `0600`, with a single
link. The runtime configuration table below gives every key, its bounds, and its default. `check` adds the rules a schema cannot hold:

- `store.nonceLifetimeSeconds` must not exceed `store.accessTokenLifetimeSeconds`.
- The listener port must be non-zero.
- `metricsListener.bind` must be a loopback or private address on a non-zero port the delivery
  listener does not use.
- A reference must name a provider the file enables, and `secretProviders.file.root` must be
  absolute.

## Check offline

Check the file before the service reads it:

```sh
evidence-oid4vci check --runtime-config runtime.yaml
```

```text test-expect
0 errors, 0 warnings in 1 file
```

`check` reads that one file and nothing else, so it does not prove that the client key resolves
or parses; `inspect` and `serve` prove that when they start. See
[`evidence-oid4vci check`](/reference/cli/evidence-oid4vci/check/).

{/* Evidence: crates/registry-evidence-oid4vci/src/main.rs, check. */}

## Inspect what wallets will read

With the key in place, `inspect` loads the service, reads the Evidence Gateway's definitions, and
prints the metadata it would publish:

```sh test-skip="needs a reachable Evidence Gateway and token issuer"
evidence-oid4vci inspect --runtime-config runtime.yaml
```

It prints one JSON document: the profile marker `registry.evidence.oid4vci-profile/v1`, the
credential issuer and authorization server metadata, and a `deployment` block stating one replica,
that a restart invalidates outstanding exchanges, and whether metrics are enabled. If the gateway
cannot be reached, it exits 1 and logs that the credential source is unavailable. The wire behavior
follows the
[frozen OID4VCI profile](https://github.com/registrystack/registry-stack/blob/main/products/evidence/contracts/oid4vci-profile.yaml),
which also lists what the front end does not support.

{/* Evidence: crates/registry-evidence-oid4vci/src/service.rs, inspect;
    crates/registry-evidence-oid4vci/src/issuer.rs, IssuanceError, Unavailable;

## Serve

Render the HTTP contract your own front end and the wallet will call, then start the service:

```sh
evidence-oid4vci openapi --output evidence-oid4vci.openapi.json
```

```sh test-skip="starts a long-running service against a reachable Evidence Gateway"
evidence-oid4vci serve --runtime-config runtime.yaml
```

Your front end creates a credential offer at `/offers` with an access token the `offers` block
admits; the wallet calls the two `/.well-known` metadata routes, `/token`, `/nonce`, and
`/credential`. The [wallet delivery API reference](../../reference/apis/evidence-oid4vci/) renders
the same document. `/health` answers `{"status":"ok"}` while the process runs, and `/ready`
answers `{"status":"ready"}` from what the process holds, never from the state of the gateway or
token issuer.

Run exactly one replica: offers, codes, and tokens live in process memory, and a restart
invalidates every outstanding exchange. A change to the gateway's bundle or batch ceiling needs a
coordinated restart: stop `evidence-oid4vci`, change or restart the gateway, then start
`evidence-oid4vci` again so its first catalog comes from the new gateway.

## Check wallet interoperability

Before you put a new `evidence-oid4vci` binary behind your proxy, check it against the wallet it
was tested with. The checks replay a sanitized profile of Inji Wallet, its expected metadata and
wire shapes, through a real process of your binary, with synthetic keys and data discarded on
exit. They run from a source checkout of the release you deploy, with its Rust toolchain, Bash,
and Python 3, and need loopback ports 18440 to 18442 free:

```sh test-skip="the runner starts in a copy of this checkout"
git clone --depth 1 --branch v<version> https://github.com/registrystack/registry-stack.git
cd registry-stack
```

Point `EVIDENCE_OID4VCI_BIN` at the binary you deploy, so the checks drive it and compare the
contract it renders with the release's. The first run builds the test, which takes several minutes:

```sh
EVIDENCE_OID4VCI_BIN="$(command -v evidence-oid4vci)" \
  products/evidence/scripts/compat/inji-oid4vci.sh
```

Each stage prints a milestone as it passes, from checking a delivery file to a wallet flow that
returns a credential verified as holder-bound Evidence:

```text test-excerpt
CONFIG CHECKED: complete delivery configuration is valid
METADATA INSPECTED: derived holder-bound batch ceiling is 4
SERVICE READY: health and readiness are available on the delivery listener
METRICS PRIVATE: metrics exist only on the separate loopback listener
TASK GRANT REFUSED: deferred wallet state was not created
PRESENTATION VERIFIED: public wallet flow returned holder-bound Evidence
CLEANUP COMPLETE: generated private material was removed
```

```text test-excerpt
PASS: sanitized Inji OID4VCI profile and Registry-side interoperability tests
```

A run that stops before `PASS:` failed at the stage after the last milestone it printed. A `cmp`
difference before any milestone means your binary renders a different contract from the release
you checked out. A message that names a listener or readiness usually means one of the ports is
taken. A pass is bounded evidence for the Inji revisions the
[pinned profile](https://github.com/registrystack/registry-stack/blob/main/products/evidence/fixtures/interoperability/inji-oid4vci/profile.json)
names, tested on 2026-08-09, not certification.

To rebuild those Inji revisions and rerun their own client tests, run the opt-in upstream check
on macOS with Git, npm, Java 17, Android SDK platform 34 with Build Tools 33.0.1, full Xcode, and
an iPhone 15 simulator. It ends with the line the pinned receipt records:

```sh test-skip="the upstream check needs macOS with Xcode and the iOS Simulator, Java, the Android SDK, and network access"
EVIDENCE_INJI_OID4VCI=1 products/evidence/scripts/compat/inji-oid4vci-upstream.sh
```

## Troubleshooting

| Code | Meaning | Recovery |
| --- | --- | --- |
| `platform.runtime-config.unavailable` | The runtime file could not be read. | Check that the file exists and that the runtime user can read it. |
| `evidence.oid4vci.https-required` | An origin is not `https` in strict mode. | Write an `https` URL, or set `validationMode: supervised-local-development` for a loopback process group. |
| `evidence.oid4vci.listener-port` | The listener port is zero. | Bind the listener to a non-zero private port your TLS proxy forwards to. |
| `evidence.oid4vci.nonce-lifetime` | The nonce outlives the access token. | Lower `store.nonceLifetimeSeconds` to at most `store.accessTokenLifetimeSeconds`. |
| `evidence.oid4vci.secret-file-root` | The file provider root is relative. | Write `secretProviders.file.root` as an absolute directory path. |
| `evidence.oid4vci.secret-provider-disabled` | The key reference names a provider the file does not enable. | Declare that provider under `secretProviders`, or reference the key through an enabled one. |
| `evidence.oid4vci.metrics-shared-binding` | The metrics listener shares the delivery binding. | Bind the metrics listener to a port the delivery listener does not use. |
| `evidence.oid4vci.wildcard-spelled-item` | An `offers` list item spells `*` or `unrestricted`, which matches only itself (a warning). | Write `unrestricted` in place of the list, or remove the item. |
