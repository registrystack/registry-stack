You run an Evidence Gateway and need a wallet to receive its holder-bound
[SD-JWT VC](/reference/glossary/#sd-jwt-vc) responses over
[OID4VCI](/reference/glossary/#oid4vci). This page gets you a running `evidence-oid4vci` delivery
front end beside your Evidence Gateway, checked offline before it serves.

Evidence Gateway does not speak the wallet protocol; `evidence-oid4vci` does, and turns each
response into the credential the wallet stores. It never signs, never holds a holder private key,
and adds no Evidence semantics, so [how Evidence works](/explanation/how-evidence-works/) still
describes every decision.

{/* Evidence: crates/registry-evidence-oid4vci/src/lib.rs; AGENTS.md. */}

## What you need

- A definition with `subjectBinding: holder-bound` that permits `sd-jwt-vc`, as
  [Enable SD-JWT VC](../enable-sd-jwt-vc/) sets up. The front end offers only
  [holder-bound](/reference/glossary/#holder-bound) definitions.
- A running Evidence Gateway candidate, as
  [Build and deploy an Evidence project](../../tutorials/build-and-deploy-evidence-project/) leaves
  you.
- The `evidence-oid4vci` binary, which the
  [same installer](../../tutorials/build-and-deploy-evidence-project/#what-you-need) installs beside
  `evidence` and `evidencectl`. Or the image `ghcr.io/registrystack/evidence-oid4vci:<tag>` from the
  [latest release](https://github.com/registrystack/registry-stack/releases/latest): it runs
  as the distroless `nonroot` user (uid 65532) from `/var/lib/registry-evidence-oid4vci`, exposes
  port 8090, and runs `serve --runtime-config /etc/registry-evidence-oid4vci/runtime.yaml`. Mount
  the runtime file and the token client key read-only; the image has no shell, so your platform
  owns the probes.

## Write the runtime file

The runtime file tells `evidence-oid4vci` its public origin, the Evidence Gateway it fronts, the
token client it uses to call that gateway, and who may create a credential offer. This one is
copied from `products/evidence/examples/oid4vci-runtime/runtime.yaml`; replace every origin with
your own:

```yaml title="runtime.yaml" test-file
# yaml-language-server: $schema=https://id.registrystack.org/schemas/evidence/oid4vci-runtime/oid4vci-runtime.v1alpha1.schema.json
# A minimal Evidence OID4VCI delivery runtime configuration: the file
# `evidence-oid4vci serve --runtime-config` and `inspect --runtime-config` read, and
# `evidence-oid4vci check --runtime-config` checks offline. Replace every origin with
# this deployment's own, and place the delivery client's private JWK at
# secretProviders.file.root, named as tokenClient.privateKeyRef names it.
apiVersion: id.registrystack.org/formats/evidence/oid4vci-runtime/v1alpha1
kind: EvidenceOid4vciRuntimeConfig
credentialIssuer: https://wallet.example.org
listener:
  bind: 127.0.0.1:8090
secretProviders:
  file:
    root: /run/secrets/evidence-oid4vci
evidence:
  baseUrl: https://evidence.example.org
tokenClient:
  tokenEndpoint: https://mint.example.org/token
  clientId: evidence-oid4vci
  privateKeyRef: secret:file/delivery-client.jwk.json
  resource: https://evidence.example.org
offers:
  issuer: https://mint.example.org
  jwksUri: https://mint.example.org/.well-known/jwks.json
  audiences: ["https://wallet.example.org"]
  authorizedClients: [adopter-front-end]
  requiredScopes: [oid4vci:offer]
store:
  maximumOffers: 4096
```

`privateKeyRef` follows the [secret reference grammar](../../reference/environment-variables/#secret-references).
The key file must be a regular file owned by the service user, mode `0400` or `0600`, with a single
link. The table below gives every key, its bounds, and its default. `check` adds the rules a schema
cannot hold:

- `store.nonceLifetimeSeconds` must not exceed `store.accessTokenLifetimeSeconds`.
- The listener port must be non-zero, because the published origin names it.
- `metricsListener.bind` must be a loopback or private address on a non-zero port the delivery
  listener does not use.
- A reference must name a provider the file enables, and `secretProviders.file.root` must be
  absolute.

## Check offline

```sh
evidence-oid4vci check --runtime-config runtime.yaml
```

```text test-expect
0 errors, 0 warnings in 1 file
```

`check` reads that one file and nothing else, so it does not prove that the client key resolves
or parses; `inspect` and `serve` prove that when they start. See
[`evidence-oid4vci check`](/reference/cli/evidence-oid4vci/check/) for its flags and exit codes.

{/* Evidence: crates/registry-evidence-oid4vci/src/main.rs, check. */}

## Inspect

With the key in place, `inspect` loads the service, reads the Evidence Gateway's definitions, and
prints the metadata it would publish:

```sh test-skip="needs a reachable Evidence Gateway and token issuer"
evidence-oid4vci inspect --runtime-config runtime.yaml
```

Against the example origins, which nothing answers, it exits 1 and logs that the credential
source cannot be reached. Against a reachable gateway it prints one JSON document: the profile
marker `registry.evidence.oid4vci-profile/v1`, the credential issuer and authorization server
metadata the wallet will read, and a `deployment` block that states one replica, that a restart
invalidates outstanding exchanges, and whether metrics are enabled.

The wire behavior follows the
[frozen OID4VCI profile](https://github.com/registrystack/registry-stack/blob/main/products/evidence/contracts/oid4vci-profile.yaml),
which also lists what the front end does not support. See
[`evidence-oid4vci inspect`](/reference/cli/evidence-oid4vci/inspect/).

## Render the contract

```sh
evidence-oid4vci openapi --output evidence-oid4vci.openapi.json
```

The command prints nothing and writes a document byte-identical to the tracked
[`registry-evidence-oid4vci.openapi.json`](https://github.com/registrystack/registry-stack/blob/main/products/evidence/generated/registry-evidence-oid4vci.openapi.json).
Your own front end creates a credential offer at `/offers` with an access token the `offers` block
admits; the wallet calls the two `/.well-known` metadata routes, `/token`, `/nonce`, and `/credential`. See [`evidence-oid4vci openapi`](/reference/cli/evidence-oid4vci/openapi/).

{/* Evidence: crates/registry-evidence-oid4vci/src/main.rs, openapi;
    crates/registry-evidence-oid4vci/src/authorizer.rs;

## Serve

```sh test-skip="starts a long-running service against a reachable Evidence Gateway"
evidence-oid4vci serve --runtime-config runtime.yaml
```

`/health` answers `{"status":"ok"}` while the process runs. `/ready` answers `{"status":"ready"}`
from what the process holds, never from the state of the gateway or token issuer. See
[`evidence-oid4vci serve`](/reference/cli/evidence-oid4vci/serve/).

{/* Evidence: crates/registry-evidence-oid4vci/src/service.rs, HEALTH_PATH, READY_PATH, health, ready. */}

## Operational limits

The listener speaks plain HTTP, and `credentialIssuer` must be `https`, so front it with a TLS
proxy that publishes that origin. Run exactly one replica: offers, codes, and tokens live in
process memory, single use holds per process, and a restart invalidates every outstanding
exchange. A change to the Evidence Gateway's bundle or batch ceiling needs a coordinated restart:
stop `evidence-oid4vci`, change or restart the gateway, then start `evidence-oid4vci` again so its
first catalog comes from the new gateway.

## Metrics

Set `metricsListener.bind` to serve Prometheus text at `/metrics` on a private address:

| Metric | What it counts |
| --- | --- |
| `evidence_oid4vci_http_requests_total` | Delivery requests by closed outcome class |
| `evidence_oid4vci_http_request_duration_seconds` | Delivery request latency |
| `evidence_oid4vci_outcomes_total` | Protocol and upstream outcomes |
| `evidence_oid4vci_store_entries` | Entries in the fullest bounded offer, ledger, or token keyspace |
| `evidence_oid4vci_store_capacity` | Refusal threshold for each bounded keyspace |
| `evidence_oid4vci_cleanup_expired_total` | Expired in-memory entries released by cleanup |

The outcome vocabulary is closed: every label value is one variant of `Outcome::ALL`.

## Troubleshooting

| Code | Meaning | Recovery |
| --- | --- | --- |
| `platform.runtime-config.unavailable` | The runtime file could not be read. | Check that the file exists and that the runtime user can read it. |
| `evidence.oid4vci.https-required` | An origin is not `https` in strict mode. | Write an `https` URL, or set `validationMode: supervised-local-development` for a loopback process group. |
| `evidence.oid4vci.listener-port` | The listener port is zero. | Bind the listener to the port the credential issuer origin names. |
| `evidence.oid4vci.nonce-lifetime` | The nonce outlives the access token. | Lower `store.nonceLifetimeSeconds` to at most `store.accessTokenLifetimeSeconds`. |
| `evidence.oid4vci.secret-file-root` | The file provider root is relative. | Write `secretProviders.file.root` as an absolute directory path. |
| `evidence.oid4vci.secret-provider-disabled` | The key reference names a provider the file does not enable. | Declare that provider under `secretProviders`, or reference the key through an enabled one. |
| `evidence.oid4vci.metrics-shared-binding` | The metrics listener shares the delivery binding. | Bind the metrics listener to a port the delivery listener does not use. |
| `evidence.oid4vci.wildcard-spelled-item` | An `offers` list item spells `*` or `unrestricted`, which matches only itself (a warning). | Write `unrestricted` in place of the list, or remove the item. |
