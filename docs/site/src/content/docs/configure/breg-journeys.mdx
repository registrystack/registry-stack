If you are verifying a Base Registry Engine (BReg) project, compile it offline,
inspect the derived contract, and run its journeys against an isolated database
with real credentials before packaging it.

## Check the project

```sh
bregctl check ./my-registry
bregctl check ./my-registry --production
```

Check reports diagnostics at the document and member that needs repair. An error
refuses the candidate. An advisory describes a decision to review. Use
`--deny-warnings` when your reviewed warning policy requires it; do not assume
that an example always emits a fixed number of warnings.

The command also validates declared local clients and journey files against the
project. Fix renamed Record type IDs, profile IDs, and operation bindings there
when changing the model. Unknown or retired keys fail rather than becoming grants.

## Explain what the compiler derived

```sh
bregctl --format json explain model ./my-registry
bregctl --format json explain routes ./my-registry
bregctl --format json explain access ./my-registry
bregctl --format json explain actions ./my-registry
bregctl --format json explain proposals ./my-registry
```

Inspect exact fields, routes, grants, Action mode, plans, guards, and Proposal
review/application requirements. These commands read no target records and make
no review decision. They establish the compiled contract, not runtime success.

## Generate application artifacts

```sh
bregctl generate --help
```

Choose the needed artifact family and a fresh output directory. Generated JSON
Schema, OpenAPI, metadata, and project types derive from the same model. Review
the authored source when a generated contract is wrong; do not hand-edit a copy.
Every Action input includes its compiler-emitted schema, which the clients and
MCP gateway use exactly.

## Declare a journey

Start from the generated `tests/journeys.yaml`. It declares
`apiVersion: id.registrystack.org/formats/breg/journeys/v1` and `kind: BRegJourneys`.
Each step identifies the Record type or Action, selected access profile, synthetic
expected claims, request, expected outcome, and optional capture for later steps.
Use `recordType` for a record step.

The default directory journey creates a contact, reads it with the editor's
jurisdiction, then expects a concealed `404 resource.not_found` when a caller
from another jurisdiction reads that same record. Keep both the success and the
refusal. Add a regression that represents the user-visible invariant your edit
changes, rather than a second copy of every configuration member.

Function planning has a separate bounded offline loop:

```sh
bregctl project action-test ./my-registry --action <action-id> \
  --input /path/to/input.json --expect /path/to/expected.json
```

This uses logical input IDs without an HTTP envelope. It can check effects or a
declared refusal; it cannot prove target authority, current guards, or a database
transaction.

## Run with real credentials

Prepare a separate TLS schema-test database and runtime file with migration and
runtime roles. Bind protected steps to real short-lived credentials whose verified
claims match the fixture. The fixture's synthetic claims do not authenticate a
running server. Keep credentials outside the project and version control.

```sh
bregctl test ./my-registry --runtime-config /path/to/runtime-test.yaml \
  --credentials /path/to/credentials.yaml --output /path/to/test-receipt.json
```

A successful result writes a receipt for the exact candidate and measured catalog.
A refused step identifies the failure; repair the cause and rerun into a fresh
receipt path. Package accepts that exact successful receipt and refuses changed
inputs. [Build a production candidate](../../tutorials/build-a-breg-production-candidate/)
connects the test and package steps.

For local evaluation, `bregctl dev start` prepares the isolated rehearsal and
binds the authored local clients. `bregctl examples run` serves resumable example
scenarios against the retained session. A scenario is an adopter exercise;
compiler checks and database journeys remain separate proof levels.
