If you provide assertions and your relying parties want an
[SD-JWT VC](../../reference/glossary/#sd-jwt-vc) response, this page settles what a holder may
disclose and whom the response is bound to. [Request evidence as an SD-JWT VC](../../tutorials/request-evidence-as-sd-jwt-vc/)
already permits and requests one; you continue in its project, with `dev` stopped.

## Choose what a holder can disclose

```sh test-cwd="first-evidence-assertion"
cd adult-status
```

Try declaring a field projection on `adult`, a boolean output:

```diff lang="yaml" title="evidence.yaml" test-edit
      adult:
        concept: urn:example:concept:adult-status:v1
        type: boolean
+       sdJwtVc:
+         claim: adult
+         disclosure: top-level
```

```sh test-exit="1"
evidencectl check . --target local-target.yaml
```

```text test-excerpt
error[evidence.project.output-projection-type] ./evidence.yaml:276:11 /assertionDefinitions/adult-status/outputs/adult/sdJwtVc
  SD-JWT VC field projection requires a reviewed structured value
```

Each value travels as a disclosure, a salted claim the holder may keep or drop. An output without
`sdJwtVc` is one disclosure named by its concept URI. Only a `reviewed-structured-value` output
may declare `sdJwtVc`: it then appears under `claim`, a unique name of at most 64 characters, and
each direct field becomes its own disclosure; a nested object stays one. `top-level` is the only
`disclosure` value.

Remove the block again:

```diff lang="yaml" title="evidence.yaml" test-edit
        type: boolean
-       sdJwtVc:
-         claim: adult
-         disclosure: top-level
```

## Bind adult-status to the holder

`adult-status` declares `subjectBinding: audience-scoped`: the response means something only to
the relying party that requested it. Declare [`holder-bound`](../../reference/glossary/#holder-bound) instead, and keep only `sd-jwt-vc`,
because a holder-bound definition has no other representation:

```diff lang="yaml" title="evidence.yaml" test-edit
-   subjectBinding: audience-scoped
+   subjectBinding: holder-bound
    representations:
-   - signed-jws
    - sd-jwt-vc
```

```sh test-exit="1"
evidencectl check . --target local-target.yaml
```

```text test-excerpt
error[evidence.authority.ceiling] ./dev-authority.yaml:62:7 /accessProfiles/age-checker-service/grants/0
  each complete grant must stay inside every definition ceiling
```

Both `adult-status` grants still ask for an audience-scoped JWS. Narrow each one in
`dev-authority.yaml`:

```diff lang="yaml" title="dev-authority.yaml" test-edit
      representations:
-     - signed-jws
      - sd-jwt-vc
-     subjectBinding: audience-scoped
+     subjectBinding: holder-bound
```

```diff lang="yaml" title="dev-authority.yaml" test-edit
    - age-checker-service
    grants:
    - definition: adult-status
      purpose: age-check
      audienceFrom: authenticated-requester
      representations:
-     - signed-jws
-     subjectBinding: audience-scoped
+     - sd-jwt-vc
+     subjectBinding: holder-bound
```

```sh
evidencectl check . --target local-target.yaml
```

```text test-expect
Evidence project check: complete
Project: .
Target: local-target.yaml
0 errors, 0 warnings
```

`adult-status` no longer answers as signed JWS. A request now carries `holderKeys`, and each key
becomes the `cnf` claim of its response and scopes the subject binding; the response carries no
audience. The relying party checks the holder's key-binding JWT against that `cnf` key with
[`evidence verify-presentation`](/reference/cli/evidence/verify-presentation/).

## Keep the boundary and verifier trust

An SD-JWT VC response is a second encoding of the same stateless assertion: one authorization,
source call, derivation, and audit, then serialization. Evidence Gateway keeps no issuance session,
status list, or revocation. The frozen [SD-JWT VC profile](https://github.com/registrystack/registry-stack/blob/main/products/evidence/contracts/sd-jwt-vc-profile.yaml)
pins RFC 9901 and SD-JWT VC draft 18.

Relying parties verify against keys they pinned themselves, with
[`evidence verify`](/reference/cli/evidence/verify/) for a stored response; neither command opens
a network connection. `/.well-known/jwt-vc-issuer` is discovery, not a trust anchor. A deployment
target may cap formats with `responseFormats`; see the
[configuration reference](/reference/evidence-configuration/).
