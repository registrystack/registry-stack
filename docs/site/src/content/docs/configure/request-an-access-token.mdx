If your code must present a bearer access token to Evidence Gateway, Base Registry Engine (BReg),
or another Registry Stack service, you get it from the deployment's OAuth issuer with the
client-credentials grant, authenticating with a signed client assertion instead of a secret.

## Before you start

Get these values from the issuer administrator:

- The HTTPS token endpoint
- Your registered client identifier
- Your client's private JWK
- The client-assertion audience, if not the token endpoint URL
- The RFC 8707 resource identifier of the service you call
- Your approved scopes

Keep the private key in a secret store, and never fall back to a client secret.

## With the Evidence client

A client built with `EvidenceClient.from_profile`, as in
[Request Evidence from your application](../../tutorials/request-evidence-from-an-application/),
needs no token code: the client profile drives the exchange. The explicit constructor takes it as
`token=`:

```python
client = EvidenceClient(
    base_url, trusted_jwks, revoked_key_ids,
    token={"private_key_jwt": private_key_jwt},
)
```

`private_key_jwt` holds `token_endpoint`, `client_id`, `client_key`, and optionally `audience`,
`resource`, and `scopes`; the [client API reference](../../reference/client-api/#token-configurations)
has the rest.

## Without the client

Any other caller, BReg callers included, posts this form to the token endpoint:

```text
grant_type=client_credentials
client_id=<client-id>
client_assertion_type=urn:ietf:params:oauth:client-assertion-type:jwt-bearer
client_assertion=<signed-client-assertion>
resource=<resource-identifier>
scope=<scopes>
```

The client assertion is a JWT signed with your private key: `iss` and `sub` are your client
identifier, and `aud` defaults to the token endpoint URL. For an Evidence client profile,
`--client-assertion-audience` names another audience "when the issuer expects one other than the
token endpoint URL". Give every assertion a fresh `jti`, because a replay-checking issuer refuses a
repeated one. Keep `resource` and `scope` fixed for the client's lifetime, so a cached token never
serves another service.

`resource` is a registered identifier, not a URL to fetch. Every shipped Evidence target requires
the scope `evidence:request`.

## Troubleshooting

| Symptom | Check |
| --- | --- |
| The issuer returns `invalid_client` | Client identifier, key `kid`, assertion audience, clock, `jti` |
| The service rejects the token | Token issuer, resource, required scopes |
