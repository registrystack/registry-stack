Use this checklist after product configuration is valid and before exposing a deployment to callers.

## Before you start

- Record the exact source revision, package digest, runtime configuration, and operator approval.
- Use the product's production check and keep the report with the deployment record.
- Identify every secret owner, source owner, audit owner, and recovery owner.
- Test recovery with non-production data.

## Keys and credentials

- Resolve secrets from the product's supported secret-reference boundary.
- Restrict secret files and environment injection to the service identity.
- Give signing, source, and caller credentials separate rotation schedules.
- Keep previous verification keys only for the documented verification window.
- Refuse startup when required credentials or trust material cannot be loaded.

## Network boundary

- Terminate TLS at a reviewed edge where the product deployment guide requires it.
- Bind internal listeners to private interfaces and restrict direct access.
- Pin outbound destinations, methods, paths, trust roots, timeouts, and response limits.
- Keep health probes free of credentials and sensitive source diagnostics.

## Authorization and disclosure

- Review scopes, access profiles, source requests, and disclosure rules as governed input.
- Exercise missing, expired, wrongly issued, and insufficiently scoped credentials.
- Confirm a denied request reaches no protected source.
- Confirm configuration cannot widen access through an unknown or ignored field.

## Audit and retention

- Place audit output on durable operator-controlled storage.
- Treat an unavailable required audit sink as a release-blocking failure.
- Document retention, access, integrity monitoring, backup, restoration, and deletion.
- Verify audit records contain identifiers needed for accountability without copying protected values.

## Package and source integrity

- Deploy only the reviewed package and record its digest.
- Keep mutable runtime bindings outside governed packages where the product contract requires it.
- Restrict source credentials to the exact operations the adapter needs.
- Test schema or contract drift and confirm the product refuses an incompatible source.

## Verify

Before handoff, record:

1. production configuration and package checks;
2. authenticated and unauthenticated request results;
3. audit failure behavior;
4. source timeout and size-limit behavior;
5. backup and restore evidence; and
6. the rollback trigger and responsible operator.
