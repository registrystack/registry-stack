Registry Evidence is built so that a caller cannot turn it into a fact-query engine, splice
permissions across grants, redirect source access, learn from an absence, or receive an
unauthenticated response, and so that its configuration cannot change underneath a request. The
operator keeps the duties no service-side control can hold.

## What the runtime guarantees

A caller cannot turn the service into a fact-query engine. It evaluates only
requirements, each pinned by a requirement revision, and the request schema is
closed: no thresholds, expressions, scripts, paths, headers, source fields, or
response projections. The complete enabled package is reviewed as one
disclosure surface, because several safe definitions together can reconstruct a
protected value.

A caller cannot splice permissions. Principals and attributes come only from
configured, validated authentication sources, and missing data denies rather
than falling back to another claim. One authorization decision binds the
requester, client, requirement revision, purpose, every subject role and
selector profile, authority, and audience, so partial matches across grants
never add up to access. Selector values are lookup inputs, never proof of
authority. Every authorization refusal is durably audited before the generic
`403`; if that audit fails, the caller receives the generic `503`. Refusals
decided before authorization, for a failed authentication, a malformed
request, an invalid selector, or a rate limit, write no native audit entry, so
watch for them in operational logs and metrics instead.

Source access cannot be redirected. Source calls are fixed by trusted
configuration and executed by the core alone, which closes off SSRF, credential
forwarding, and script-directed networking. Rhai returns one closed lookup
result and declared typed values; the core validates them and assembles the
public evidence itself.

Absence does not leak. Missing facts, script failures, audit failures, and
evaluation failures fail closed. Raw source responses are never persisted or
logged, and selector, source, and disclosed values never reach logs or audit.
No-match, ambiguous, and missing-fact outcomes collapse to one public problem
status and body, and the runtime removes the timing differences it can avoid.
It does not pad responses to a constant time, so a source that answers a
no-match faster than a match can still leak membership through latency; measure
that at your source before you expose a definition to callers who should not
learn it. Audience-scoped subject bindings derive from the audience and the
purpose, so one subject is not linkable across relying parties. A holder-bound
requirement binds to the holder key's thumbprint and the purpose instead: a
holder who presents the same key to several verifiers is linkable across them
for that purpose, and the wallet, not Registry Evidence, decides whether to use
a fresh key.

The response is authenticated. A signed flattened JWS is the default, unsigned
output exists only where the package and the matched grant both permit it, and
failed signing never falls back to unsigned evidence. Private signing material
stays with the core, out of package values, Rhai, logs, audit, and errors. The
exact response bytes exist before the disclosure-release audit is durably
accepted and are the bytes released. A signature authenticates the provider and
the payload; it does not assert legal-signature status or source truth.

Configuration cannot change underneath a request. The package, runtime file,
and active target authority are immutable for the life of the process, and one
process serves one operator-controlled trust domain with one signer and one
audit boundary. Operational telemetry is off by default and served only on a
separate private listener with closed labels. Public responses carry a W3C
trace identifier but never the internal audit operation identifier, and
`tracestate` is not echoed.

## How the guarantees are held

The [invariant matrix](https://github.com/registrystack/registry-stack/blob/main/products/evidence/contracts/security-invariant-matrix.yaml)
holds the complete, normative text: numbered invariants and named cross-cutting controls, each
with its rule, threat, enforcement, and negative test, including those for holder-bound responses,
request batches, and the OID4VCI front end. An invariant the matrix adds is binding from the change
that adds it. Every invariant is held by a named test; the
[traceability contract](https://github.com/registrystack/registry-stack/blob/main/products/evidence/contracts/security-test-traceability.yaml)
links them, and the build fails when an invariant drops its test.

## What the operator must uphold

The matrix describes what the `evidence` binary enforces.
The [operator contract](https://github.com/registrystack/registry-stack/blob/main/products/evidence/OPERATOR-CONTRACT.md)
holds the duties no service-side control can hold for you:

- Keep every secret file below `secretProviders.file.root` a regular,
  non-symlink file owned by the service identity with mode `0400` or `0600`;
  the file provider refuses anything else.
- Generate the audit and subject-binding masters independently, at least 32
  bytes each, under distinct references. The runtime refuses equal references
  or equal bytes.
- Mount the package and `runtime.yaml` read-only and unwritable by the service
  process. There is no upload, reload, or override: a change is a new
  candidate.
- Pass source credentials and signing material only through secret
  references, never in YAML values, Rhai, command arguments, logs, or
  snapshots.
- Sign production and evidence-grade deployments through a workload-local
  Transit key that stays non-exportable, and retire signing keys as
  [Rotate Registry Evidence signing keys](../../tutorials/rotate-evidence-signing-keys/)
  shows.
- Ship the audit log to append-only storage and rotate its master as
  [Operate the Registry Evidence audit log](../../operate/evidence-audit/)
  shows.

## Report a vulnerability

Suspected Registry Evidence vulnerabilities, including credential disclosure,
authentication bypass, audit redaction failure, source connector data
leakage, and signing-key handling bugs, go through the private disclosure
process in [SECURITY.md](https://github.com/registrystack/registry-stack/blob/main/SECURITY.md),
never a public issue or pull request. See
[Report a vulnerability](../report-a-vulnerability/) for the complete in-scope
list and reporting steps.
