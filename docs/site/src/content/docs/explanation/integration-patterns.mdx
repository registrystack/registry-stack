Choose the smallest product boundary that answers the integration need.

## Governed system of record

Use Base Registry Engine (BReg) when the institution needs to create, update, review, and audit
records in a PostgreSQL-backed registry. Applications call BReg's own record API. Casework can coordinate
review while BReg retains mutation authority.

## Bounded evidence

Use Evidence Gateway when a relying service needs a signed answer to a predefined question. Configure
one fixed source request, bounded derivation, entitlement, and output contract. The relying service
verifies the assertion and makes its own decision.

## Static metadata publication

Use Registry Manifest when an integrator needs portable catalog, schema, service, policy, or
evidence-offering metadata. Render and host the artifacts as static files. Metadata describes the
service but does not grant access.

## Provider discovery

Use Registry Discovery to publish a curated index of Evidence Gateway descriptions. The application
searches, explicitly selects, validates, and locally accepts a provider before constructing the
native Evidence client.

## Workflow orchestration

Workflow engines such as OpenFn can call maintained product APIs. Keep credentials and product
policy in the owning boundary. A workflow may coordinate calls, but it does not become the
authorization source or system of record.
