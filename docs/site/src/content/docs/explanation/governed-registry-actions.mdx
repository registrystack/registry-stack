If you are choosing a write model for Base Registry Engine (BReg), an Action
provides typed inputs and an ordered bounded plan. Immediate execution commits
that plan atomically; Proposal execution retains it as durable work before later
application.

## When a Function earns its place

Use a fixed plan when input-to-field mappings are constant. Use `commitGuards`
for current facts and revision conditions that must hold under the commit lock.
A named Function earns its place when it computes a value, selects effect slots,
or returns a declared business refusal. The Function's runtime, source, entrypoint,
ABI, capabilities, and limits are governed assets. Its Action declares the inputs,
write ceiling, and refusals.

Rhai uses `registry.action-plan/v1` and `ctx.inputs`. It computes effects within the
ceiling and cannot invent authority, review policy, or an accepted review result.
Effects use authored order and explicit dependencies. A reference to an earlier
created effect preserves identity without allowing script-supplied raw references.
Aliased writes fold into one revision; conflicts and dependency cycles refuse.

## Admission and commit

Every existing reference target needs current Action authority, including a target
that only supplies a link. Omission of a function effect suppresses its write,
not input admission or target authority. Guards remain unconditional for the
operation. Effects, revisions, audit, receipt, and outbox commit together.

A Record type can require Proposals independently of grants. An immediate Action
cannot bypass that rule. The caller cannot select execution mode or turn a durable
operation into immediate execution.

## Frozen work and review

Proposal submission freezes the exact inputs, Action revision, targets and
revisions, effects and digest, attachments, and review binding. External review
owns the decision. BReg applies that exact plan under current commit guards and
required fresh approval, without rerunning changed code.

Automatic application is the default under a restricted built-in system grant.
Manual application is an explicit independent authority choice. A safe blocked
reason and current promoted transitions support recovery; an older submission
never silently follows a revised or rebased successor.

## Declared Evidence

An Action can declare a bounded Evidence capability and operator-configured trust.
Plan-time resolution can inform effects within the declared ceiling. Commit-time
Evidence checks frozen requirements and cannot change approved effects. Endpoint,
credentials, keys, and trust binding stay deployment inputs. BReg inherits no
Evidence authorization.

Retained accepted assertions and verification context have a separate bounded
retention scope. Exact receipt replay does not replan or reacquire Evidence.
A required unavailable provider refuses its dependent operation without affecting
unrelated CRUD or Actions. Unsupported backend/capability combinations refuse
rather than silently losing a requirement.
