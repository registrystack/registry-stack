Use these checks after you change a project, integration, environment, script,
snapshot, or fixture.
Run them from the project directory.

## Test authored behavior offline

```sh
registryctl test
```

The command executes synthetic fixtures through the production evaluation
semantics without contacting a live source.
Use `--trace` to include the bounded synthetic interaction trace or `--watch`
to rerun after authored files change.

## Review the effective plan

```sh
registryctl check --environment local --explain
registryctl review compare --environment local
```

`check` validates authored intent and prints a redacted effective plan.
An initial `review compare` reports every required product lane as needing
approval.
For an update, pass the current approved set with `--against`.

Both commands are read-only.
They do not resolve secrets, contact a source, or start Docker.

## Build unsigned product inputs

```sh
registryctl build --environment local
```

The build writes deterministic review material and lane-specific signing
inputs under `.registry-stack/build/local/`.
Do not edit generated product configuration.

## Check development prerequisites

```sh
registryctl doctor --environment local
```

Doctor reports host, released-artifact, Docker Compose, and project
prerequisites without changing the project.
It does not start the runtime.

## Exercise the local product path

```sh
registryctl dev --detach
registryctl dev status
registryctl dev smoke
registryctl dev logs
registryctl dev down
```

`dev` rebuilds stale inputs and owns the disposable development environment.
The nested commands inspect, exercise, or remove that same bound environment.
Development credentials, trust material, and state are not production inputs.

## What these checks do not prove

Local fixture and development success do not prove source interoperability,
operator acceptance, or production readiness.
The operator still reviews, signs, assembles, generates, verifies, and
activates the governed deployment through separate product and operator
boundaries.
