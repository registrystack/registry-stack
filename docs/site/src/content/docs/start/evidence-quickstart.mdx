Evidence answers one bounded question about one subject and signs the answer,
without releasing the record the answer came from. A relying service asks
whether a person meets a condition and receives a signed assertion carrying
the answer, not the row that settled it.

The current `evidencectl new` command starts an incomplete authoring workspace
from an OpenAPI document. It does not create a runnable deployment. This page
maps the current authoring, operation, and verification material without
presenting that workspace as a completed first-assertion workflow.

## Four questions, none of them privileged

Adult status, residence region, professional licence status, and legal-parent
relationship are coequal acceptance definitions. None is a built-in type, a
special route, or a first phase that the others follow. Whichever one your
institution needs, you author it the same way. The tutorials switch between
them deliberately: the source tutorial answers a legal-parent relationship,
and the authoring tutorial covers all four.

An acceptance definition is a reviewed artifact, not code you ship. Evidence
compiles the definition at startup from an immutable bundle, and refuses to
start if the definition does not compile.

## The current path

- [Evaluate Evidence](../evaluate-evidence/) explains the complete deployment
  layout and its runtime dependencies.
- [Configure Evidence](../../configure/evidence/) documents the governed
  bundle, runtime file, authorization, source, signing, and audit contracts. It
  also records exactly what `evidencectl new` does and does not generate.
- [Verify an assertion as a consumer](../../tutorials/verify-an-assertion-as-a-consumer/)
  re-verifies a stored synthetic response offline against retained state and a
  pinned key set.
- [Move to production signing](../../tutorials/move-evidence-to-production-signing/)
  applies after an operator already has a complete deployment project.

The in-repository docs do not connect the incomplete `evidencectl new`
workspace to a runnable first assertion. The scaffold-dependent authoring,
source, and serving tutorials remain unpublished until their commands match
the supported product flow.
