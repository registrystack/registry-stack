If another service needs to check something your institution's records settle, such as whether a
person is an adult, [Evidence Gateway](../../reference/glossary/#evidence-gateway) lets you answer that one question with a signed assertion
instead of sharing the record. Three short tutorials take you from a copied example to a
verified answer, a value richer than yes or no, and a choice of who may ask.

## What you work with

Evidence answers with an [assertion](../../reference/glossary/#assertion): a signed payload that
carries the answer and none of the record behind it. Each question has a
[Requirement URI](../../reference/glossary/#requirement), such as
`urn:example:requirement:adult-status:v1`, and a caller names that URI to ask it.

You declare the questions, and how your own system answers each one, in an [Evidence project](../../reference/glossary/#evidence-project): YAML
files and small scripts you keep in version control. `evidencectl` checks, tests, and packages the
project; `evidence` serves the package and signs each assertion.

## Start here, whatever your role

1. [Your first assertion](../../tutorials/first-evidence-assertion/): copy the example project,
   check it, start it beside a synthetic source, prepare and send one request, and verify the
   signed response offline. The source returns a birth date and a private address; the
   assertion carries only `true`.
2. [Return a governed value](../../tutorials/return-a-governed-value/): ask the same project which
   region the subject lives in, and get back one of the values the project allows.
3. [Control who can request evidence](../../tutorials/control-who-can-request-evidence/): add a
   second caller and read the refusal Evidence returns when it asks what it was never granted.

All three run locally on synthetic data, with token checks, signing, and audit on.

## Then follow your role

- **You build an application that asks.**
  [Request Evidence from your application](../../tutorials/request-evidence-from-an-application/)
  sends the request and verifies the answer from code.
- **You run the service.**
  [Build and deploy an Evidence Gateway project](../../tutorials/build-and-deploy-evidence-project/)
  takes the project to a running deployment.
- **You design the questions.** [How Evidence works](../../explanation/how-evidence-works/) gives
  the model; then
  [Connect an institution API](../../tutorials/connect-an-institution-source/)
  starts a project from your own system's API description.

## Where the product stops

Evidence keeps no copy of your records: each answer comes from a fixed read of the system that holds
them. To hold and change the records themselves, use
[Base Registry Engine](../breg-quickstart/).
