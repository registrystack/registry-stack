Start with the maintained HTTP project.
It provides the shortest complete path from authored fixtures to the real
Registry Relay and Registry Notary development runtime.

## Complete the first run

[Build and run an HTTP registry project](../../tutorials/author-registry-project/)
creates a project from the released `http` template, executes its fixtures
offline, runs a disposable local environment, and builds unsigned inputs for
review.

The first run uses one terminal and synthetic data.
You do not need a source checkout, production keys, or a deployment package.

## Adapt the working project

After the first run:

- [Add an OAuth-backed Rhai adapter](../../tutorials/configure-project-script-adapter/)
  when one bounded consultation needs several same-origin HTTP calls
- [Connect your data](../../configure/) when you are ready to replace the
  synthetic source with reviewed institution-owned input
- [Validate your project](../../verify/) after each authored change

The only other public initialization template is `spreadsheet`.
Spreadsheet uses the same project, fixture, build, and development contracts
as HTTP.

## Move an older project

Pre-1.0 commands and generated runtime files do not have compatibility aliases
or an automated migration path.
Use the [pre-1.0 cutover guide](../pre-1.0-cutover/) to preserve reviewed
authored intent and recreate generated material.
