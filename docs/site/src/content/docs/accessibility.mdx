This site does not claim conformance to a WCAG level. No external accessibility audit has been
carried out, and no screen-reader test runs. The only automated contrast check covers diagram ink
against the diagram background, in both colour schemes. This page lists
the checks that do run and what they leave out.

## What is checked

{/* evidence: docs/site/scripts/check-built-accessibility.mjs, criticalPaths and checkPage;
     docs/site/package.json, check:accessibility:built and check:production;
     .github/workflows/ci.yml, check:production step. */}
The built-site check reads the generated HTML of a fixed list of critical-path pages, including
the home page. For each page it requires:

- a non-empty `lang` attribute on the `html` element
- no duplicate `id` values
- no positive `tabindex`
- exactly one `main` landmark, containing exactly one `h1`
- non-empty `alt` text on every image that is not marked decorative
- an accessible name on every link, button, form control, and other interactive element

The check parses static HTML. It does not run a browser, so it cannot see behaviour that
JavaScript adds. Continuous integration runs it through `npm run check:production`.

{/* evidence: docs/site/scripts/check-svg-a11y.mjs;
     docs/site/package.json, check:svg and check:source. */}
A second check covers the diagrams in `public/images`. Each named SVG diagram must exist and
carry a `<title>`, a `<desc>`, and `role="img"`.

{/* evidence: docs/site/src/styles/custom.css, :focus-visible;
     docs/site/scripts/svg-diagram-contrast.test.mjs. */}
Interactive elements keep a visible focus outline (2 px, with a 2 px offset). A site test checks
that the background behind the diagrams stays light in both themes, because the diagrams use a
light-only ink palette. It also asserts that each diagram ink colour meets the WCAG AA contrast
ratio for normal text (4.5:1) against that background.

## What is not checked

- Colour contrast of page text and interface components is not measured by any tool in this site.
- Keyboard operation and screen-reader behaviour are not tested.
- Pages outside the critical-path list are not covered by the built-site check.
- The site is published in English only.

Email [contact@registrystack.org](mailto:contact@registrystack.org) with the page address and
what you could not use or read.
