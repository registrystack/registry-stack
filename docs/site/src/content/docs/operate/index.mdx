The local development environment is disposable.
The governed path creates independently approved product lanes and a portable
deployment package that an operator can verify before activation.

## Handoff sequence

| Stage | Command family | Result owner |
| --- | --- | --- |
| Review | `registryctl review compare` | Independent reviewer |
| Build | `registryctl build` | Product-lane signers |
| Trust | `registryctl trust anchor`, `trust bundle`, and `trust approved-set` | Product trust owners and approved-set owner |
| Package | `registryctl deploy generate` | Deployment operator |
| Verify | `registryctl deploy verify` | Deployment operator |
| Run | Printed `docker compose` command | Deployment operator |

Each Relay lane and the Notary lane has its own bundle, anchor, identity, and
anti-rollback state.
The approved set proves that the three inputs belong to one compatible project
and environment.
It does not activate a product.

Bare `registryctl deploy` prints help and performs no action.
Generation and verification do not sign bundles, create production secrets,
initialize product state, or start Docker Compose.

## Record operator-owned inputs

Before generation, record:

- The exact approved baseline set and released image lock
- The public Relay, consultation Relay, and Notary owners
- The external secret files and their consumers
- The governed anchor sources and retained immutable copies
- The public endpoints and edge network
- The durable state, backup, restore, update, and replacement procedures
- The expected approved-set digest and generated closure root

Keep deployment bindings outside generated product configuration.
Use a declared Compose override, export the package, or translate the
platform-neutral deployment plan when the managed profile does not fit.
