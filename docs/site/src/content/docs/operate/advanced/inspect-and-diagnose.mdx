Start with the product's own check, health, readiness, and audit surfaces. Keep diagnostic output
bounded and value-free.

## Prerequisites

- Record the binary version, package or configuration revision, and trace identifier.
- Use a synthetic subject or non-production registry record.
- Keep tokens, credentials, source responses, and private keys out of tickets and logs.

## Diagnose the failure class

1. Confirm the process loaded the expected configuration and package.
2. Check health, then readiness. A healthy process may still refuse requests when a required source,
   audit sink, or key is unavailable.
3. Match the HTTP status and stable problem code to the product reference.
4. Use the trace identifier to locate the value-free audit or operational record.
5. Reproduce the request with the smallest supported client call.
6. Test the external dependency separately using its operator-owned diagnostic path.

## Common boundaries

| Symptom | Boundary to inspect |
| --- | --- |
| Startup refusal | Package integrity, closed configuration, secret references, and listener binding |
| Authentication refusal | Issuer, audience, algorithm, key set, token time, and required scope |
| Authorization refusal | Complete entitlement or access-profile match |
| Source unavailable | Fixed destination, transport trust, credentials, timeout, and response limit |
| Audit unavailable | Durable storage, permissions, replacement detection, and capacity |
| Response rejected by a client | Media type, schema version, trace identifier, and product-specific problem contract |

Do not enable broader source access, disable audit, accept an unknown configuration field, or log a
protected response to make diagnosis easier.

## Expected evidence

Keep the exact version and revision, bounded check output, relevant problem code, trace identifier,
value-free audit record, dependency status, and the recovery action. Redact credentials and source
values before sharing the evidence.

## Recover

Restore the last reviewed configuration or package when its credentials and data contract remain
valid. Otherwise, fix forward with a reviewed revision. Re-run readiness and one realistic request
before returning traffic.
