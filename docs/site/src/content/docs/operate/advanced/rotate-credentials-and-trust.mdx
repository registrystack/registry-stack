Use this procedure for Evidence Gateway caller trust, source credentials, transport trust, and
assertion-signing material. Product-specific configuration remains authoritative for the exact
fields and overlap windows.

## Prerequisites

- Preserve a verified recovery copy of the active configuration and referenced public keys.
- Record the active configuration revision and the credentials being replaced.
- Prepare the replacement secret in the operator's secret store without writing it into governed
  configuration or logs.
- Choose an overlap window that covers in-flight requests and the documented verification period.

## Classify the rotation

Decide whether the change affects caller authentication, source access, transport trust, assertion
signing, or several boundaries. Treat each boundary as a separate review item even when one
deployment revision carries them together.

## Rotate source credentials or trust

Evidence source credentials live in the secret plane. The governed bundle names them by secret
reference, so replacing a value at the same reference does not change the package or a requirement's
`configurationRevision`. Restart behavior depends on the provider and credential kind.

- `secret:env/<NAME>` reads the process environment. Restart and drain every process to apply an
  orchestrator environment change.
- File-backed `basic`, `static-authorization`, and `static-api-key` credentials are read on every
  source request. The next request after atomic file replacement uses the new value.
- File-backed `oauth2-client-credentials` and `oauth2-private-key-jwt` values are read when
  Evidence exchanges them for an access token. An unexpired token remains cached for at most `maximumCacheSeconds`, and a named
  `sourceConnections` entry shares that cache among its sources. Drain and restart every affected
  process when the old token must stop sooner; restart begins with an empty cache.

Write replacement bytes to a new regular file and rename it over the old file. Keep the file owned
by the service identity, mode `0400` or `0600`, with one hard link and no symbolic link. A failed
metadata check makes the next source request refuse the credential, makes readiness report the
source unavailable, and never falls back to the predecessor.

A credential spanning several files is not replaced atomically as a unit. Drain traffic before
replacing a Basic username and password or an OAuth client identifier and secret or assertion key,
then resume only after all files are in place. Keep the predecessor valid until the new credential
has served a synthetic request.

A source CA bundle is a runtime binding, not a secret. Evidence reads
`outboundTls.trustProfiles.<name>.caBundleFile` once at startup. Replacing the file therefore needs a
restart, but no new candidate when the logical trust profile is unchanged:

1. Write a non-writable PEM bundle to the named path. During CA rollover, include both outgoing and
   incoming certificates.
2. Run `evidencectl doctor --runtime-config "<deployment-target>/runtime.yaml" --without-audit-lock`.
   Doctor validates the runtime file and CA bundles without contending for the serving process's
   audit lock. `evidencectl test` checks an editable project and does not prove the runtime CA.
3. Restart each process, wait for `/ready`, and send one synthetic request through the source.

Changing a source endpoint, authentication policy, secret reference, trust-profile selection,
audience, or OIDC issuer binding is governed. Build and review a new candidate.

## Rotate caller trust

Coordinate issuer signing-key changes with the issuer's published key set and cache lifetime. Test
tokens signed by the new key before activation, then confirm expired or revoked credentials fail.
Changing issuer, audience, algorithm, or entitlement rules is an authorization change and requires
a reviewed configuration revision.

## Rotate Evidence Gateway signing material

Create the replacement non-exportable P-256 Transit key version, convert its public PEM with
`evidencectl jwk from-pem`, and publish the public JWK. Then switch
`signing.activePublicJwkFile` and the pinned signer version in a reviewed bundle, run
`evidence check --require-runtime-dependencies` on the target host, restart, and verify a stored assertion against independently retained
expectations. Retain the prior public key for the maximum assertion validity plus allowed clock
skew. Missing or failed signing is fail-closed; it never produces an unsigned assertion.

[Rotate Evidence Gateway signing keys](../../../tutorials/rotate-evidence-signing-keys/) provides
the complete sequence.

Audit hash-master rotation is separate. Generate a fresh master in a new secret file and build a
bundle revision whose `audit.hashKeyRef` names it and whose `audit.hashKeyVersion` is one higher.
Run `evidence check --require-runtime-dependencies` on the target host and restart. Every pseudonym records its version, allowing both versions in one
audit path. Never replace the bytes without raising the version because the runtime cannot detect
that substitution and the unchanged prefix would silently identify different pseudonyms. Retain
the old master as long as its pseudonyms must remain recomputable. See
[Rotate the audit master](../../evidence-audit/#rotate-the-audit-master).

## Expected evidence

Keep the `evidence check` report, readiness result, old and new public key identifiers, activation
time, staged source request result, audit records, revocation result, and operator approval. Never
record private keys, bearer tokens, or source credentials.

## Roll back or recover

Restore the previous reviewed configuration only while its credentials remain valid and its use is
authorized. If the old credential was revoked because of compromise, fix forward with a new
credential and configuration revision.
