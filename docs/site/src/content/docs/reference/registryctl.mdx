Registryctl 1.0 has seven ordinary workflow commands and three advanced namespaces.
The released command parser and `--help` output are the source of truth.

## Root commands

| Command | Contract |
| --- | --- |
| `init` | Copy a tested local template into an absent project directory |
| `test` | Execute authored fixtures offline through production semantics |
| `check` | Validate and explain authored intent without writing build state |
| `build` | Emit deterministic unsigned product-lane signing inputs |
| `dev` | Build and run an isolated disposable development environment |
| `deploy` | Generate or verify a governed deployment package |
| `doctor` | Diagnose host, released-artifact, and product prerequisites |
| `review` | Compare authored intent with an approved baseline |
| `trust` | Inspect and create independently owned trust artifacts |
| `tooling` | Print schemas and references or install editor support |

For removed pre-1.0 commands and their 1.0 replacements, use the
[pre-1.0 cutover guide](../../start/pre-1.0-cutover/).

## Project and environment selection

Registryctl walks from the current directory to the nearest parent containing
`registry-stack.yaml`.
Global `-C <project-directory>` or `--project-dir <project-directory>` selects another project
before discovery.

Environment resolution uses this order:

1. `--environment <id>`
2. `REGISTRYCTL_ENVIRONMENT`
3. The project default
4. The sole declared environment
5. A failure that names the declared environment ids

Signing, assembly, deployment generation, and initialization authority inputs are explicit.
Registryctl does not resolve those authority-granting inputs from environment variables.

`--format json` emits one versioned document on standard output where the command advertises the
flag.
Progress and diagnostics use standard error.
Human prose is not a machine contract.

## `init`

```text
registryctl init <project-directory> --template http
```

`init` is offline and copies a template embedded in the installed release.
The destination may be absent or a pre-existing empty real directory.
Registryctl validates the project and editor setup in private staging before publishing
the complete project. A staging failure leaves an absent destination absent and a
pre-existing empty destination empty.
OAuth-backed Rhai adapts the HTTP project; OpenCRVS, DHIS2, FHIR, and other systems are not init
templates.

## `test`

```text
registryctl test
registryctl test --integration <id>
registryctl test --integration <id> --fixture <name> --trace
registryctl test --integration <id> --fixture <name> --watch
```

`test` is offline.
It does not start Docker, resolve a secret, or contact a source.
`--trace` may show values from the selected synthetic fixture.
`--watch` supports human output only.
There is no live-test flag.

## `check`

```text
registryctl check
registryctl check --explain
registryctl check --explain --show-authored-values
registryctl check --format json
```

`--explain` includes the redacted acquisition, authorization, output, claim, disclosure, and
review plan.
`--show-authored-values` adds directly authored non-secret values to trusted local human output
and requires `--explain`.
It is unavailable with JSON output.

## `build`

```text
registryctl build
registryctl build --against <approved-set>
registryctl build --format json
```

An initial combined project can emit the closed lanes `relay-public`, `relay-consultation`, and
`notary`.
`--against` verifies the current approved set for an update and limits output to affected lanes.
`build` does not sign, assemble, deploy, or activate.

## `dev`

```text
registryctl dev
registryctl dev --detach
registryctl dev status
registryctl dev logs
registryctl dev smoke
registryctl dev down
```

Bare `dev` starts attached.
`--detach` applies only when starting.
Registryctl validates the project, rebuilds stale inputs, verifies the installed release lock,
and uses digest-locked images.

Each environment declares one default development scenario.
`dev` does not prompt or accept an integration or fixture selector.
It refuses production and evidence-grade environments.

Development anchors, credentials, bundles, and state are isolated and disposable.
`dev smoke` runs one denial and one authorized scenario and emits
`registryctl.dev_smoke.v1` with scenario ids, status classes, counter deltas, minimized claim
identifiers, and pass state.
It contains no credential or source-returned value.

## `deploy`

Bare `registryctl deploy` prints help and performs no action.

```text
registryctl deploy generate \
  --approved-set <file> \
  --binding <file> \
  --output-dir <directory>
registryctl deploy verify \
  --package <directory> \
  --expected-closure-sha256 <sha256> \
  --check-operator-files
registryctl deploy verify \
  --package <directory> \
  --approved-set <file>
```

Generation consumes one verified three-lane approved set and the signed release lock installed
with Registryctl.
`--binding` selects a closed deployment binding.
Omit it to generate safe loopback defaults into the package.
It does not sign bundles, create production secrets, initialize product state, or activate a
deployment.

Verification reports package ownership, freshness, closure integrity, and whether in-place
regeneration is safe.
`--expected-closure-sha256` compares the generated closure with a digest recorded outside the
package.
`--check-operator-files` checks each operator file's existence, isolation, mode, and owner without
reading its value.
It verifies the generated package only.
An operator-owned Compose application or include graph remains outside that result.
Generation and verification are offline.

## `doctor`

```text
registryctl doctor
registryctl doctor --profile <local|hosted_lab|production|evidence_grade>
registryctl doctor --format json
```

The profile selects diagnostics, not an operating contract.
The report distinguishes authored-environment, release-lock, Docker client, Docker daemon,
Compose 2.35.0, and digest-locked image readiness.
`doctor` does not fetch replacements.

## `review`

```text
registryctl review compare
registryctl review compare --against <approved-set>
registryctl review compare --against <approved-set> --fail-on-change
registryctl review compare --format json
```

Omit `--against` for initial review.
A comparison that reports changes exits with status `0` unless `--fail-on-change` selects a
negative predicate.
The report names exact affected lanes and performs no signing, deployment, source access, or
project mutation.

## `trust`

The trust namespace preserves product-lane authority:

```text
registryctl trust anchor create ...
registryctl trust anchor rotate ...
registryctl trust bundle inspect ...
registryctl trust bundle verify ...
registryctl trust bundle sign ...
registryctl trust approved-set assemble ...
```

### Create or rotate an anchor

```text
registryctl trust anchor create \
  --lane <relay-public|relay-consultation|notary> \
  --input <lane-signing-input> \
  --public-key <public-jwk> \
  --threshold <number> \
  --output-file <file>
registryctl trust anchor rotate \
  --current-anchor <file> \
  --next-public-key <public-jwk> \
  --next-threshold <number> \
  --key <key-locator> \
  --output-dir <directory>
```

Public-key and key flags are repeatable where a threshold requires several signers.
Rotation writes a fresh anchor and transition; it never edits the current anchor.

### Inspect, verify, or sign a lane

```text
registryctl trust bundle inspect --bundle-dir <signed-artifact-directory>
registryctl trust bundle verify \
  --bundle-dir <signed-artifact-directory> \
  --anchor <signed-artifact-directory>/anchor.json
registryctl trust bundle sign \
  --lane <relay-public|relay-consultation|notary> \
  --input <lane-signing-input> \
  --anchor <file> \
  --key <file:or-op-locator> \
  --output-dir <signed-artifact-directory>
```

The signed artifact directory is the root created by `trust bundle sign`.
It contains the `bundle/` directory, the selected `anchor.json`, and any anchor-history links.
Inspect, verify, and approved-set assembly all accept that same root.
An update signing command also supplies `--against <approved-set>`.
Registryctl accepts explicit `file:` and `op://` key locators.
An unprefixed path or unknown scheme fails before output creation.

### Assemble an approved set

Initial assembly supplies all three verified lane directories:

```text
registryctl trust approved-set assemble \
  --relay-public <signed-artifact-directory> \
  --relay-consultation <signed-artifact-directory> \
  --notary <signed-artifact-directory> \
  --output-file <file>
```

Update assembly supplies `--from <approved-set>` plus every affected replacement.
The approved set is an operator handoff, not a fourth signature or activation authority.

## `tooling`

```text
registryctl tooling schema --kind <project|environment|integration|fixture|entity>
registryctl tooling reference configuration
registryctl tooling reference xw
registryctl tooling editor
registryctl tooling language-server
registryctl tooling diagnostics --catalog <authoring|fixture|operator>
```

Tooling output derives from the running Registryctl release.
The namespace does not need Docker, source access, a secret, or a deployed product.

## Stable option meanings

| Option | Meaning |
| --- | --- |
| `--template` | Select an embedded initialization template |
| `--against` | Select the current approved set for comparison or update |
| `--approved-set` | Select an approved set for deployment generation or verification |
| `--binding` | Select a closed deployment binding instead of safe loopback defaults |
| `--expected-closure-sha256` | Compare a package with its externally recorded generated closure digest |
| `--check-operator-files` | Check operator-file existence, isolation, mode, and owner without reading values |
| `--output-dir` | Select one directory |
| `--output-file` | Select one file |
| `--environment` | Select a declared project environment |
| `--format json` | Select one strict machine document where supported |

Unknown fields, unsupported capabilities, and incomplete authority bindings fail closed.
An error identifies an authored field address when one exists.

## Exit status

```text
0  The requested operation completed and every selected predicate passed.
1  The operation completed with a negative domain result.
2  Usage or contract version is invalid or unsupported.
3  An operational dependency failed.
```

A failed fixture, failed smoke scenario, unmet readiness requirement, or selected comparison
predicate uses status `1`.
An unknown command or unsupported portable document version uses status `2`.
File input/output, Compose, or an explicitly selected secret-provider failure uses status `3`.

## Network behavior

`init`, `test`, `check`, `build`, `deploy generate`, `deploy verify`, `review`, `tooling`, and
`doctor` do not contact an authored source.
Trust commands using file-backed keys are offline.
`trust bundle sign` may contact an explicitly selected `op://` secret provider.

`dev` may pull an absent image only at the exact digest from the installed release lock.
After authorization, it may contact only the source mode selected by the authored environment.

Registryctl 1.0 performs no update checks.
`registryctl --version` is local and deterministic.
