## Authentication and profiles

Every route except `/health`, `/ready`, and `/.well-known/jwks.json` takes
`Authorization: Bearer <token>`. The producer routes that submit, read, cancel, and collect a
review request read the access profile from `Registry-Review-Profile`; every other route reads
`Registry-Casework-Profile`, except the two `/v1/task-grants` service routes, which take none. A
profile selects authority the token already holds and adds no scope. A refused token is
`authentication.refused` (401); a profile that does not cover the route is
`profile.not-authorized` (403).

Task, history, clock, and note routes also accept `Registry-Source-Profile`, which work whose context
comes from a context provider requires (`source-profile.required`). Producer, policy, and
accountability routes refuse it with `source-profile.not-applicable`.

## Policy and submission binding

`POST /v1/review-requests` submits a [ReviewRequest](../../glossary/#review-request) whose `policy`
names an `id`. Omit `version` and `digest` to take the policy active at admission, or send both to
require that exact `identity` from `GET /v1/review-policies/{policy_id}`; a differing pin is
`review.policy-mismatch`. Casework retains the binding it accepted, and the ReviewResult repeats it
with the subject and `submissionDigest`. The consumer checks that correlation and authorizes any
business change itself.

## Revisions and retries

A task or directory mutation sends the revision you read, quoted, in `If-Match` (`If-Match: "2"`).
Without it the call is `precondition.required` (428). A decision under a stale revision returned:

```json
{
  "status": 412,
  "code": "precondition.failed",
  "detail": "The item or directory changed since you loaded it. Reload and try again."
}
```

Keyed mutations, `POST /v1/review-requests` among them, send an `Idempotency-Key` of at most 128
bytes. After a lost response, resend the same key and body: the first submission returned `201`,
the resend `200` with the same `requestId`. A changed body under that key is
`idempotency.key-reused`; a fresh key is a fresh operation.

## Results

`GET /v1/review-requests/{request_id}/result` returns `202` with no body while the review is
pending, `200` with the ReviewResult once it settles, and `410` with no body after its retention
ends. `GET /v1/review-results` pages settled results as a resumable feed.

{/* Evidence: crates/registry-casework/src/http.rs, get_review_result, review_result_feed. */}

## Problems and validation

A refusal is `application/problem+json` with `type`, `title`, `status`, a fixed `detail`, a closed
`code`, and a `traceId`, and echoes nothing you sent. A decision naming an undeclared outcome
returned `request.invalid` (400) with these headers:

```text
registry-casework-validation-path: $.outcome
registry-casework-validation-reason: outcome-not-declared
registry-casework-validation-allowed: confirmed,rejected
```

Producer routes spell the first two `registry-review-validation-path` and
`registry-review-validation-reason`. Give your operator the `traceId`, never a token or body.

## Route families

Review policies: `/v1/review-policies` returns compiled policy closures, and `/v1/casework`
describes the deployed project.

Review requests and results: `/v1/review-requests` and `/v1/review-results` serve the producer;
history, clocks, and notes hang off one request.

Review tasks: `/v1/review-tasks` lists eligible work and carries claims, assignment, drafts,
decisions, holdings, supervision, and, where a project enables them, task grants.
`/v1/review-accountability/{event_id}` resolves a retained accountability record.

Directory and calendars: `/v1/directory` manages teams, absences, and holidays, and previews then
applies caseload moves and clock recomputation.

Activation has no HTTP route: [`caseworkctl apply`](../../cli/caseworkctl/apply/) activates a
package ([Deploy Registry Casework](../../../operate/casework/)).

## Source of truth

`generate_openapi.py` derives the OpenAPI document from the Rust DTOs, routes, and operation
contracts; `check-schemas.sh` refuses a committed document that differs. The service does not
serve the document. A runtime test holds the problem table's data to the problem catalogue.
