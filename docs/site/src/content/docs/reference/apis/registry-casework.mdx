## Routes

The caller is the role of the access profile the call selects: `requester` for a producer,
`staff` and `supervisor` for reviewers, `administrator` for the directory owner. A role that a row
does not name is refused with `operation.not-authorized`.

| Method | Path | Caller | Returns |
| --- | --- | --- | --- |
| GET | `/health`, `/ready` | Anyone, no token | `200`; `/ready` answers `503` while storage or the audit journal is unavailable |
| GET | `/.well-known/jwks.json` | Anyone, no token | Keys that verify task assertions |
| GET | `/v1/casework` | Any profile | The deployed project, without providers, calendars, or clocks for a requester |
| GET | `/v1/review-policies`, `/v1/review-policies/{policy_id}` | Any profile | The compiled ReviewPolicy closures the caller may use |
| POST | `/v1/review-requests` | Requester | `201` with the accepted [ReviewRequest](../../glossary/#review-request), `200` on recovery |
| GET | `/v1/review-requests/{request_id}` | Requester | The request's state |
| POST | `/v1/review-requests/{request_id}/cancel` | Requester | The cancellation |
| GET | `/v1/review-requests/{request_id}/result` | Requester | `200` with the ReviewResult; bodiless `202` pending, `410` erased |
| GET | `/v1/review-results` | Requester | A resumable page of settled results |
| GET | `/v1/review-requests/{request_id}/history`, `/clocks` | Reviewer or requester | History; clocks |

## Headers

| Header | Sent on | Rule |
| --- | --- | --- |
| `Authorization: Bearer <token>` | Every route except `/health`, `/ready`, and the key set | A missing, invalid, or expired token is `authentication.refused` (401) |
| `Registry-Review-Profile` | The five requester routes: submit, read, cancel, result, results feed | Names the access profile; at most 128 bytes of letters, digits, and `.`, `_`, `:`, `-` |
| `Registry-Casework-Profile` | Every other authenticated route except `/v1/task-grants/*` | Same bounds; a profile that does not cover the route is `profile.not-authorized` (403) |
| [`Registry-Source-Profile`](../../glossary/#registry-source-profile) | Task, history, clock, note, task grant, caseload, and clock recompute routes, by a reviewer | Selects the reviewer's source profile; work whose context comes from a context provider requires it (`source-profile.required`) |
| `If-Match: "<revision>"` | Task mutations and directory mutations | The revision you read, quoted; `"0"` creates a directory entry. Missing is `precondition.required` (428), stale is `precondition.failed` (412) |
| `Idempotency-Key` | Every mutation except previews, the two `/apply` routes, and grant revocation | 1 to 128 printable ASCII bytes, kept with the request body for recovery |
| `traceparent` | Any route, optional | W3C trace context; every response carries one |

A profile selects authority the token already holds and adds no scope. The `/v1/task-grants/*`
routes take a bare service token: either profile header there is `authentication.refused`.
`Registry-Source-Profile` is `source-profile.not-applicable` on the requester routes, the policy
routes, `/v1/directory/targets`, task release, and accountability, and from a requester on
history, clocks, and notes. Every response carries `Cache-Control: no-store`.

## Policy pins and retries

`POST /v1/review-requests` names a policy `id`. Omit `version` and `digest` to take the
ReviewPolicy active at admission, or send both to require the `identity` that
`GET /v1/review-policies/{policy_id}` returned; a differing pin is `review.policy-mismatch`. The
ReviewResult repeats the accepted binding with the subject and `submissionDigest`; the consumer
checks that correlation and authorizes any business change itself.

After a lost response, resend the same `Idempotency-Key` and the same body: the first submission
answered `201`, the resend `200` with the same `requestId`. A changed body under that key is
`idempotency.key-reused`, and a fresh key is a fresh operation. A `503` on a mutation does not say
whether the change committed, so recover it the same way before you choose another operation.

## Problems

A refusal is `application/problem+json` with `type`, `title`, `status`, a fixed `detail`, a closed
`code`, and a `traceId`, and echoes nothing you sent. A validation refusal names the field and
the reason in `registry-casework-validation-path` and `registry-casework-validation-reason`, plus
the accepted values in `registry-casework-validation-allowed` when the field takes a closed set;
requester routes spell the first two `registry-review-validation-path` and
`registry-review-validation-reason`. Give your operator the `traceId`, never a token or a body.
