Look up any key of a file Evidence Gateway (Evidence) reads: the deployment bundle and
`runtime.yaml`, and the `evidence.yaml`, target, and target authority documents you write. Each
entry gives the key's type, whether it is required, its accepted values and bounds, and the
schema's own sentence on what the key decides.

## Contract status

| Schema | Status | Source |
| ------ | ------ | ------ |
| `bundle/evidence.yaml`, `runtime.yaml` | Frozen Version 1 contract | [`bundle.schema.yaml`](https://github.com/registrystack/registry-stack/blob/main/products/evidence/contracts/bundle.schema.yaml) and [`runtime.schema.yaml`](https://github.com/registrystack/registry-stack/blob/main/products/evidence/contracts/runtime.schema.yaml) |

JSON Schema is not the acceptance path: a document these schemas accept still has to pass
`evidencectl check`, which applies the cross-field, file, and grant rules no schema can express
([Build and deploy an Evidence Gateway project](../../tutorials/build-and-deploy-evidence-project/)).

## How to read the tables

A property is written `name`, an array item `name[]`, and a map entry whose name you choose
`name.*`, as in `assertionDefinitions.*.acquisition.fetch[]`. A recursive
definition appears once, where it re-enters itself. Where a key has several alternative shapes,
Accepted values is the union of what they accept, and constraints joined by *or* are alternatives.
Required reads **Conditional** when the rest of the document decides whether you may or must write
the key. Bounds under *where a rule elsewhere applies* tighten whichever alternative you took once
the rule's condition holds: in the bundle, the `sources.*.baseUrl` of a source authenticating
with `none` must also match the loopback pattern listed there.

## How the keys fit together

An entry states what one key decides, not how keys combine. The deployment grammar is explained in
[`deployment-projects/CONFIG.md`](https://github.com/registrystack/registry-stack/blob/main/products/evidence/reference/request-adapter/deployment-projects/CONFIG.md)
and the authoring keys in
[`authoring-projects/CONFIG.md`](https://github.com/registrystack/registry-stack/blob/main/products/evidence/reference/authoring-projects/CONFIG.md).
[Configuration files](../configuration-files/) gives the YAML and environment substitution rules
every product shares.

## Check commands

Every file Evidence reads has a command that checks it offline, with no service running. Each prints
the diagnostics, JSON output, and exit codes that
[Check a file before you deploy it](../configuration-files/#check-a-file-before-you-deploy-it) describes.
