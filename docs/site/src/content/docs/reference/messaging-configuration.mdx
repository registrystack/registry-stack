Look up configuration keys for `messaging.yaml`, each template version's `template.yaml`, each
provider package's `provider.yaml`, and the operator's `runtime.yaml`.

## Scope

Keys follow the current grammar, which is not frozen.

`messaging.yaml` is the authored package: sender profiles, access profiles, and the templates and
providers it uses. `templates/<id>/<version>/template.yaml` declares one template version's channel,
locales, and parts. `providers/<id>/provider.yaml` declares an HTTP provider package and its
capabilities. `runtime.yaml` is the operator's deployment file: listener, database, package,
identity, authentication, provider connections, audit, and retention.

A schema-valid document still needs the checks `messagingctl check` runs, because cross-file
references, template rendering, and provider scripts cannot be expressed in a schema.
[Configuration files](../configuration-files/) describes the YAML rules and environment
substitution that apply when the runtime reads `runtime.yaml`.

## Read the tables

`fields[]` means an array item; `providers.*` means a map entry whose name you choose.
Required fields inside an optional object apply when that object is present.
Conditional fields depend on the selected variant or another configuration value.
Accepted values list the union across variants; constraints separated by `or` are alternatives.
A schema default applies only where that variant declares it. `Not specified` does not mean
that every value is accepted.
