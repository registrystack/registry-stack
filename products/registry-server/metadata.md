# Caller-filtered application metadata

`GET /v1/registry[?accessProfile=...]` returns one revision-bound application
contract. The existing `id`, `version`, `revision`, and `entities` members remain.
`metadataVersion: "1"` and `operations` add the route-specific contract. The
legacy entity summaries and `/v1/schemas/{entity}` may aggregate several authorized
routes; they do not establish an individual route's read or write authority.

Every operation is selected by the same compiled route, served-operation check,
and caller/profile authorization used for execution. Unknown and ungranted
profiles remain indistinguishable. No source reads are performed for discovery.
Clients must discard metadata, records, cursors, ETags, and drafts when the
identity/profile changes. A changed `revision` requires metadata refresh and
explicit draft review before a mutation.

## Operation shape

Each entry has `id`, uppercase `method`, exact `path` template, `operation`,
`sourceEntity`, `responseEntity`, `accessProfile`, and `requiredCapabilities`.
Substitute only declared path parameters such as `{record_id}`. A related-record
operation additionally has `readPath: {id, label}`. Its source identifies the
record whose path is followed; its response identifies the returned records.
Private join definitions are never included.

`requiredCapabilities` is empty for generic read and direct mutation operations.
Request lifecycle actions use `change_request_lifecycle`; a client must disable
an operation when it does not understand any required capability. Unknown
optional operation kinds can be ignored. Controlled entity writes remain
request-only: metadata must not expose controlled target mutations as direct
create or patch grants, and a writable field list never permits a client to
bypass a required mutation or record-state capability.

`fields` contains only the union of this operation's readable and applicable
writable fields. `readableFields`, `createWritableFields`, `patchWritableFields`,
and `titleFields` contain **logical IDs** and never grant rights to another
operation. The create set is populated only on Create, and the patch set only on
PATCH. Each field contains:

```json
{
  "id": "display-name",
  "apiName": "displayName",
  "label": "Display name",
  "schema": {"anyOf": [{"type": "string", "minLength": 0, "maxLength": 120}, {"type": "null"}]},
  "required": false,
  "nullable": true,
  "readOnly": false,
  "removable": true
}
```

Use `apiName` for HTTP data properties and query expressions, never a casing or
punctuation conversion. `schema` is the authoritative value schema generated by
the same field-schema helper as the generated JSON Schema and OpenAPI. Optional
stored fields and derived fields accept null through `anyOf`; `nullable` mirrors
that rule. Required stored fields reject null. `required` describes the stored
field's create requirement, not a requirement to include the field in PATCH.
`readOnly` identifies derived fields; only the applicable writable set grants a
write. `removable` is true only for optional PATCH-writable fields. Removal sets
the stored value to null, and nested JSON Patch paths are unsupported.

Schema formats and Registry extensions retain their server meanings: int64
requires lossless signed 64-bit values, decimals use fixed-scale strings,
structured values preserve their declared schema and byte bound, and CRS84
points preserve coordinate order and precision. Existing backend JSON parsing
also rejects integer literals that are not exactly representable by the parser's
numeric model, such as `9007199254740993`; the `int64` JSON Schema type does
not mean every signed 64-bit lexical integer form is accepted on the wire.
Clients should not coerce these values through lossy JavaScript numbers or
generic strings.

`entityLabel`, field `label`, and vocabulary `codeLabels` are presentation hints.
Only the same-profile authored Manifest entity titles, identifiers, and code
labels are reused. Localized authored labels use the first language in sorted
order; otherwise labels are humanized logical IDs/codes. `titleFields` chooses
one readable authored string identifier or the first readable string field in
logical-ID order. It may be empty. `identifier: {apiName: "id", location:
"envelope"}` provides the stable UUID fallback. Render labels as plain text.

## Request and lookup contract

`request.fieldNames` is `"api"`. `request.queryParameters` is the exact supported
query-key inventory for the operation's capabilities, excluding `accessProfile`,
which selects the operation's profile. Query values still require normal backend
validation. A caller must not combine `$skiptoken` with any other query option.

Create uses `request.body: "data_envelope"`, `contentType: "application/json"`,
`idempotencyKeyRequired: true`, `mutationSemantics: "direct"`, and a complete
`request.schema` for `{data: {...}}`.

PATCH uses `body: "json_patch"`, `contentType: "application/json-patch+json"`,
`patchPathPrefix: "/data/"`, `patchOperations: ["add", "replace", "remove",
"test"]`, `removeSemantics: "set_null"`, `ifMatchRequired: true`,
`idempotencyKeyRequired: true`, `mutationSemantics: "direct"`, and the generated
patch-document `schema`. Escape an API property as one JSON Pointer segment.
Use a fresh direct GET for the exact route/profile's edit baseline and ETag.
The generic patch-document schema describes syntax; field permissions, required
fields, whole-field paths, and at least one mutation remain runtime checks.
`test` requires a readable stored field. `move`, `copy`, `from`, missing values,
and extra members are not accepted.

Lookup uses `body: "selector_values"` and `contentType: "application/json"`.
`selectors` contains only that route/profile's grants:

```json
{
  "id": "by-code",
  "label": "By code",
  "valueOrigin": "request",
  "fields": [{"id": "record-code", "apiName": "recordCode", "label": "Record code", "schema": {"type": "string", "minLength": 0, "maxLength": 64}, "required": true}],
  "requestFields": ["recordCode"]
}
```

For `request`, submit `{selector: "by-code", values: {recordCode: "..."}}` with
exactly `requestFields`, all non-null. For `verified_claim`, `requestFields` is
empty and the request is `{selector: "by-code"}` with no `values` member. Selector
field definitions describe the permitted lookup input, not read access. Private
claim names, mappings, and claim values are absent. A claim-bound selector may
still resolve to the normal value-free unresolved response.

## References and query capabilities

A visible reference field adds `reference: {manualEntry: true, operations: [...]}`.
Only independently authorized direct GET, List, or Lookup routes in the **same
selected profile** appear. Bindings contain `operationId`, `accessProfile`, and
`labelFields` (logical IDs readable through that exact target operation).
`targetEntity` appears only when such a binding exists. The referenced operation
entry supplies its own selectors and query/page limits. A path grant never
creates a target binding or contributes a target label field. With no usable
target binding, only manual UUID entry/display is offered and the target identity
is omitted. A hidden reference field supplies no reference metadata.

Collection `query` describes the selected compiled query plan:

| Member | Meaning |
| --- | --- |
| `kind` | `list`, `current`, `as_of`, or `snapshot` |
| `selectableFields` | `{id, apiName}` entries |
| `filterableFields` | `{id, apiName, operators}` entries; operators are `equals`, `in`, `range`, `is_null`, `is_not_null`, `prefix`, `contains` |
| `sortableFields` | `{id, apiName, directions}` entries; currently `asc` only |
| `allowCount` | Whether `$count=true` is permitted |
| `defaultPageSize`, `maxPageSize` | Compiled page bounds; `$top` must be at least 1 |
| `maxFilterClauses`, `maxInValues` | Closed expression bounds |
| `pagination` | `{parameter: "$skiptoken", responsePath: "pageInfo.nextCursor", exclusive: true}` |
| `temporal` | null, `{mode: "current"}`, the required `asOf` parameter contract, or `{mode: "snapshot", snapshot: {...}, validAt: {...}}` with the optional opaque snapshot reference and typed validity parameter |

The temporal requirement applies to the first page; continuation is cursor-only.
The capability operator names describe the existing native query grammar, not
query-string keys. Use `$filter`, `$orderby`, `$select`, `$top`, and `$count` as
listed in `request.queryParameters`. A null `query` does not advertise a list or
search capability. Direct GET and Lookup allow `$select` using `readableFields`,
including request-origin and verified-claim lookups. Lookup selector inputs
remain in the body and follow the selector contract; projection only reduces
the response fields. Envelope `id` and `revision` are always present and may be
selected independently of data fields.

All HTTP responses, including caller-filtered metadata, schemas, OpenAPI,
protected reads, mutations, authentication refusals, and errors, use
`Cache-Control: no-store`. The policy does not change exact held response bytes,
ETags, preconditions, idempotency replay, or trace correlation.
