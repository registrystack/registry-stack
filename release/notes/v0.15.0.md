# Registry Stack v0.15.0

Registry Stack v0.15.0 is the beta-20 release. It is a breaking pre-1.0
release focused on a usable first-country authoring and local onboarding path,
with release evidence bound to the exact candidate bytes. The stopped v0.14.0
train was not published and is not part of this release lineage.

## Adopter onboarding and authoring

- Registryctl publishes a versioned installer and a canonical `spreadsheet`
  starter for creating, validating, starting, testing, and stopping a protected
  local Registry Relay API on Linux amd64.
- Project authoring adds value-free explanation, offline preflight, capability
  inventory, semantic comparison, promotion analysis, migration, fixture
  coverage, and generated-artifact provenance reports.
- Generated references cover the complete authoring and runtime configuration
  domains while keeping authoring, fixture, and operator diagnostics separate.
- Generated local runtime credentials remain owner-only, local listeners bind
  IPv4 loopback, and Registryctl validates through the exact digest-pinned
  Compose service instead of an ambient product executable.

## Relay and Notary

- Relay validates every materialized spreadsheet row before activation and
  rejects formulas, duplicate keys, strict-column drift, nulls, and incompatible
  types with bounded value-free diagnostics.
- BREAKING: governed attribute release is stable and enabled in canonical
  builds. Profiles require purpose, the exact identity-release scope, and
  subject type; expressions see only redacted rows and responses are
  non-storable.
- Relay rechecks consultation contract closure before source continuation, so a
  stale contract hash fails with zero source calls.
- Notary string claims can retain authored UTF-8 byte bounds. CEL workers must
  complete one bounded, type-correct protocol probe before activation, while a
  mixed replacement failure retains healthy workers.

## Release evidence and scope

- The pre-tag candidate path verifies independently built binary bytes, image
  configuration and ordered layers, scans, SBOMs, release-form behavior,
  candidate receipts, and immutable documentation archives before promotion.
- Release provenance freezes non-signature subjects before cosign material is
  generated, and final reconciliation verifies both payload and signature
  assets.
- Registry Manifest has no user-visible change. Crosswalk remains pinned at
  `1d44ec735fdc8a7c719264b339574371e8330337`.
- Solmara Lab repinning, hosted publication, external OpenID, OpenCRVS, DHIS2,
  wallet, verifier, and country-acceptance evidence remain separate gates.
  This source release does not claim those results.
