# Registry Stack v0.45.0

Registry Stack v0.45.0 is the beta-57 release. Registry Evidence sources move
into reviewed Adapter packs, and the Adapter adds governed ingestion jobs that
deliver source records to BReg or the Registry Coordinator. Base Registry
Engine (BReg) adds Record timers, a registry time zone, inclusive last-day
intervals, and a reported review hand-off refusal. Registry Coordinator can
follow BReg Proposals, read the record in force on a date, and look records up
by value. Every operator tool now writes one shared report envelope.

## Compatibility and upgrade

Use matching v0.45.0 runtimes, tools, and clients. Back up each deployment and
follow [upgrade and retire](https://docs.registrystack.org/operate/advanced/upgrade-and-retire/).

BREAKING: BReg and the Coordinator start fresh state:

- BReg's Proposal hand-off store keeps the refusal code in its own column, so
  the managed schema fingerprint changes. Keep the old database for
  reconciliation, create a fresh database, and build and apply a v0.45.0
  package. Every package built by this release declares the
  `record_timer_store` engine feature, including projects that define no
  timers; packages built by earlier releases are predecessor-only.
- Coordinator protected state schema version 5 refuses version 4 namespaces
  from v0.44.0, and the pure Function interpreter ABI is now `v2`, so every
  definition frozen by v0.44.0 is refused with `definition.abi`. Settle runs
  with the v0.44.0 binaries, then check and promote the project again on a
  fresh namespace and database identity. Upgrade the Coordinator clients with
  the server: v0.44.0 clients refuse the new inspection members.

BREAKING: every runtime refuses a configuration file with
`platform.runtime-config.unsafe-file` when the file or an ancestor directory is
not owned by root or the runtime user, or is writable by group or others. A
root-owned sticky ancestor stays allowed. This covers BReg, Casework,
Coordinator, Discovery, Evidence (including OID4VCI configuration and bundle
paths), Messaging, Render, and Scheduling. Check ownership and modes before
cutover.

BREAKING: `bregctl`, `caseworkctl`, `discoveryctl`, `evidencectl`,
`messagingctl`, `schedulingctl`, and `registry-manifest` adopt the shared
report envelope. Machine-readable reports open with `ok`, `command`, `status`,
`apiVersion`, and `kind`; command members are flat; and every report carries
the binary's displayed `version` and a `diagnostics` array. `status` is
`complete`, `domain-refusal`, `usage-error`, or `operational-failure`, matching
exit codes 0 through 3, and command-specific results such as `declined` or
`ready` move to `outcome`. `passed` and `failed` statuses become `complete` and
`domain-refusal`. Update automation that parses these reports.

## Evidence sources in Adapter packs

BREAKING: Evidence Source acquisition moves into reviewed Adapter packs. An
authored Source declares `pack`, `route`, `connection`, and `inputs`. The
tagged `http-json` and `sqlite-extract` Source form and the
`source-prepare/v1` and `source-extract/v1` Functions are retired;
`assertion-derive/v1` Functions stay for requirement derivation. The v0.44.0
tools cannot read the pack form, so rebuild projects and packages with
matching v0.45.0 tools.

A v0.44.0 Source:

```yaml
sources:
  household:
    type: sqlite-extract
    # transport members and a source-extract/v1 Function
```

becomes a pack binding:

```yaml
sources:
  household:
    pack: <reviewed pack>
    route: <route id>
    connection: <connection id>
    inputs:
      # route input name: request value
```

The quickest path for a SQLite extract source is to run the v0.45.0
`evidencectl init --transport sqlite-extract`, which writes the pack form, and
move the project's requirements onto it. Follow the
[migration steps](../../products/evidence/reference/authoring-projects/CONFIG.md#migrate-a-retired-source-project)
before importing current source exports.

v0.45.0 is the migration boundary for the retired Source form. A project
authored by v0.44.0 is refused with
`evidence.project.source-acquisition-retired` and has no in-place upgrade. The
project and bundle `apiVersion` values are unchanged; a v0.44.0 bundle read by
this runtime is refused with `config.removed-key` at each retired Source
member. The v0.44.0 to v0.45.0 Evidence upgrade is not rehearsed: the release
upgrade rehearsal skips its Evidence leg for this crossing, so audit stream,
JWKS, and Transit key continuity across the upgrade are unchecked. Migrate by
hand, keep the previous deployment and audit, and verify a fresh synthetic
assertion before cutover. Messaging upgrade continuity is still rehearsed.

Related Evidence contract changes:

- BREAKING: a target connection binds each pack endpoint under
  `connections.<id>.endpoints.<endpoint id>`. Move the flat v0.44.0 members
  `origin`, `authentication`, and `tlsTrustProfile` into the endpoint entry.
  `maximumConcurrency`, `admissionTimeoutMilliseconds`, and
  `tokenTimeoutMilliseconds` are retired; per-attempt time is the endpoint's
  `attemptTimeoutMilliseconds` and the acquisition budget is
  `sourceAcquisition`. A flat connection is refused with `config.removed-key`
  naming where each member moved.
- BREAKING: `acquisitionCapabilities` is retired from the bundle and runtime
  configuration, with the `source-batch` gate. An empty list is accepted and
  ignored for this release only; a non-empty list is refused.
- BREAKING: a source route can no longer turn a source failure into a lookup
  answer. Pack compilation refuses catch, exception, and circuit-breaker
  fallback shapes that answered `no-match` for an upstream failure. To answer
  a declared 404 as `no-match`, catch `upstream.http` with an `onWhen` status
  test.
- BREAKING: new authorized-material audit entries use
  `registry.evidence.audit/v3` and `registry.evidence.audit.request-batch/v3`,
  and each access-attempt record carries a closed `executionBounds` object.
  Retained `/v2` entries remain readable history. Update semantic audit readers
  before routing traffic to this runtime.
- BREAKING: a downstream assertion is capped at the earliest `validUntil` of
  its verified signed sources, and an already expired cap is refused.
- BREAKING: Transit `key_version` policy pins are quoted strings.
- BREAKING: the Node.js and Python clients rename a request's `requirement`
  member to `handle`, and add the error kinds `invalid-request` and
  `unavailable` (Python `InvalidRequestError` and `UnavailableError`) for 4xx
  and 5xx answers that were `protocol`.
- The acquisition deadline also gates admission to the terminal
  disclosure-release append. It is not a hard response wall-clock cutoff.
- Coequal fixture runs report every failing case with value-free details, and
  `evidencectl fixtures record-facts --write` refreshes optional
  `expectedFacts` for editable synthetic projects.
- `evidencectl check` locates a Source that maps no complete alternative of a
  route's `oneOf` lookup keys.
- The OID4VCI `jwt` proof ignores unused payload claims such as `jti` and names
  the failed check in `invalid_proof`. The SD-JWT VC verifier accepts a
  presentation that withholds whole optional outputs.
- `evidencectl oid4vci` refuses an `evidence-oid4vci` helper of another
  version, and `evidencectl explain` reports `validitySeconds`.

BREAKING: `bregctl generate evidence-source` exports a reviewed Adapter pack
under `adapter-packs/<source>/` in place of the `adapters/*.rhai` and
`schemas/*.yaml` artifacts. The export `apiVersion` is unchanged, so
regenerate every export with this `bregctl`, import it with a matching
`evidencectl`, and expect a new `behaviorRevision`. BREAKING:
`--authentication` selects the authentication the generated pack endpoint
declares (default `static-authorization`); a target that authenticates with
`oauth2-private-key-jwt` needs `--authentication oauth2-private-key-jwt` at
export time, and `evidencectl check --target` refuses a mismatch with
`evidence.source.authentication-mismatch`.

## Adapter governed ingestion

The Adapter adds governed ingestion jobs beside its facade. The `adapter-job`
binary reads bounded source pages from PostgreSQL, files, SFTP, RabbitMQ, or
HTTP sources, stores item identity and progress (never source payloads), and
delivers each reviewed projection either to a BReg Action, limited to the
operations the job declares, or to a Coordinator workflow. `adapterctl`
checks, compiles, and replays projects and jobs, and the `adapter` binary
serves the governed facade. Maintained ingestion packs for KoboToolbox and ODK
Central join the `dhis2-tracker` and `opencrvs-events` facade packs. The
configuration formats are `v1alpha1` and may change without migration. The KoboToolbox pack's `testedVersions` records the
version the pack was written against; no live drill record backs it yet.

The Adapter ships as source in v0.45.0, with no binary, installer, image, or
client package. Build it from the tagged source. Binary releases are planned
next.

BREAKING for Adapter projects authored against unreleased source:
`asyncCompletion.mode` is renamed `asyncCompletion.type`. A project that still
writes `mode` is refused with `config.removed-key` naming the replacement.

## BReg authoring and operation

- Add root-granted Record timers that invoke bounded timer-only immediate
  Actions from current governed Record controls and facts, with status, list,
  show, pause, resume, and exact-occurrence retry. BREAKING: `bregctl explain
  access` emits `v1alpha8` with a required `timers` inventory.
- BREAKING: today's date is taken in the registry's time zone,
  `project.timezone` (an IANA name such as `Asia/Colombo`); earlier releases
  used UTC. A project with a date-interval Record type, a `currentDate`
  requirement, an `evaluation_date()` field, or a statistics dataset fails
  `bregctl check` with `breg.timezone.required` until it adds the line.
  `timezone: UTC` keeps the earlier dates.
- BREAKING: `:as-of` on a date-interval Record type takes a calendar date; any
  other value answers `400 query.invalid` naming `asOf`. Collection `meta`
  echoes the `asOf` each `:current` and `:as-of` read used.
- Add `lastDayField` to date intervals for an inclusive last day in force, and
  an `x-registry-temporal` marker on generated record-type schemas.
- Add `handoffRefusal` to Proposal reads while the review authority refuses
  the current submission, a `handoff` member on review-status reads, and
  `createdAt` on Proposal documents. The Rust, Node.js, and Python clients
  read them; update the Rust client with the server.
- Add `atLeastFromInput` and `atMostFromInput` Action commit guards, and an
  optional native `pattern` on `string` and `text` Action inputs.
- Add an opt-in standing-agent `get-review-context` grant for a verified
  trusted actor with an exact requester-client ceiling.
- Add experimental `bregctl generate odrl` for a partial ODRL description of
  configured `get` and `list` permissions, for operator review only.
- `GET /v1/proposals` no longer returns empty or short pages when the `action`
  or `state` filter matches few Proposals.
- `breg-mcp` shares MCP transport, authentication, and durable audit with the
  configurable supporting service and keeps its configuration, tools, and
  audit identity.

BREAKING wire and authoring changes, before the 1.0 freeze:

- Registry Record v1 renames `entityTypeIdentifier` to
  `recordTypeIdentifier`, edited in place; the Rust client field becomes
  `record_type_identifier`.
- Batch writes use `recordIdentifier`, `revisionIdentifier` (a string), and
  `domainData` in place of `recordId`/`id`, `revision`, and `data`.
- Direct Create, Patch, and Tombstone responses no longer carry
  `data.snapshot`; take a snapshot token from a Batch response or a
  `:snapshot` read.
- An authorized caller of `GET /v1/proposals` or an ingestion run list gets
  `400 query.invalid` for an unknown or malformed query parameter, where it
  got a concealed `404`.
- Proposal lifecycle event subjects carry `proposalReference` and
  `proposalRevision`.
- The Node SDK renames `entitySchema`/`entityRoute` to
  `recordSchema`/`recordRoute` (Python `record_schema`/`record_route`), Node
  Proposal calls take plain objects in place of JSON text, Python patch
  arguments become `if_match` and `patch`, and Python hooks receive headers as
  ordered pairs.
- Action `plan.capabilities` is removed; declare Evidence dependencies in
  `evidence`.
- Database pool defaults change (wait 1000 ms, create and recycle 2000 ms),
  and startup refuses a pool budget that reaches the HTTP request deadline.
- `authentication.oidc.deniedKids` is renamed `revokedKeyIds`.
- The migration descriptor names a changed Record type as kind `record-type`.
- Proposal Submit and Apply answer `412 action.guard_failed` when a field
  commit guard fails against a value the selected profile can re-read.
- A direct write that moves a visible Record outside the access profile's row
  boundary answers `403 write.outside-boundary` in place of
  `412 precondition.failed`.
- PublicSchema model-selection and statistical-dataset diagnostic codes
  replace `entity` with `record-type`; the retired codes are not emitted as
  aliases.

## Coordinator

- Add BReg Proposal operations `breg.read-proposal/v1`,
  `breg.start-proposal/v1`, `breg.submit-proposal/v1`, and
  `breg.cancel-proposal/v1`. The host follows a Proposal until it is applied,
  rejected, cancelled, or returned to the party. No operation decides a
  Proposal. A `breg` connection takes `resultCheckSeconds` (default 900) and a
  `requestLink` template.
- Add `breg.read-in-force/v1`, `breg.lookup-record/v1`, and
  `breg.read-record/v2` (with provenance). The BReg profile must grant
  `lookup` and `get` for them.
- Add Check now (`POST /v1/runs/{run}/check`, `coordinatorctl check-now`),
  nested `fields` mappings, `choose` routing on `type: compare`, and run-list
  filters for `proposal` and `turn`. List cursors issued by v0.44.0 are
  refused.
- Functions can call Rhai's string helpers and deterministic number helpers;
  `coordinatorctl explain functions` lists them, and `coordinatorctl check`
  reports an unknown call with its position.
- BREAKING: generated `EventSubject` schemas are an `anyOf` of the Record and
  Proposal subject shapes, and `breg.read-record` output follows the renamed
  Registry Record v1 contract.

## Casework

- Add default-off delegated staff-reader policies and assigned-task list and
  context routes for an explicitly trusted gateway and represented Staff
  profile, with paging cursors bound to their reader policy.
- A request body refused with `422 request.unprocessable` names the failing
  JSON path in a validation header, without echoing submitted values.
- The reviewer who recorded a task's decision can read that task's
  current-source context after the source applies the decision, within the
  result's retention.

## Other changes

- Wasmtime LTS is updated to 48.0.8 for RUSTSEC-2026-0422, RUSTSEC-2026-0423,
  and RUSTSEC-2026-0424.
- BREAKING for Rust platform crate users: `registry-cli-api` exit classes
  change (configuration and credential failures exit 1, HTTP 5xx exits 3), and
  `registry-platform-config` adds trusted-ownership checks.
- `registry-platform-resilience` adds retry delays and a circuit breaker, and
  `registry-platform-ratelimit` adds a rolling-window limiter.
- `registry-manifest` exits 3 with `manifest.io-failure` for a filesystem
  failure.
- `messagingctl check` suggests `--project` or `--package` when given a bare
  directory.

Registry Document Store remains source-only in v0.45.0, as does the Adapter.
