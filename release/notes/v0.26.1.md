# Registry Stack v0.26.1

Registry Stack v0.26.1 is the beta-38 patch release. It publishes the first
unified Node.js and Python clients for Registry Stack and makes client-package
promotion reuse the exact candidate artifacts. Runtime APIs, configuration,
Registry Manifest formats, and Registry Record responses are unchanged from
v0.26.0.

## Unified Registry Stack clients

- Node.js users can install `@registrystack/client@0.26.1`. Python users can
  install `registry-stack-client==0.26.1`.
- Each package exposes `discovery`, `evidence`, `relay`, and `breg` namespaces.
  The native Base Registry Engine binding joins the existing Discovery,
  Evidence, and Relay bindings behind those public facades.
- The Node.js release includes implementation packages for macOS arm64, Linux
  arm64 GNU, and Linux x64 GNU. The root package selects the matching native
  implementation at runtime.
- The Python wheel keeps the four product namespaces separate while preserving
  the public class and exception identities exposed by their native bindings.

## Client package migration

- Releases through v0.26.0 keep their immutable product-specific npm and PyPI
  packages. Starting with v0.26.1, Registry Stack publishes only the unified
  `@registrystack/client` and `registry-stack-client` projects.
- Existing applications may remain on the v0.26.0 product packages. Applications
  adopting v0.26.1 should import the corresponding namespace from the unified
  package instead of expecting new product-specific package versions.

## Release maintenance

- Candidate construction builds and smoke-tests each client artifact once.
  Publication promotes those exact bytes, publishes native implementation
  packages before the Node.js root package, and reconciles exact prior npm or
  PyPI state during a retry.
- Unified client artifacts participate in the same checksums, candidate
  manifest, attestations, and public registry digest verification as the rest
  of the release closure.

## Release boundaries

- Beta publication promotes one verified candidate from protected `main`
  without rebuilding binaries, client packages, documentation, or runtime image
  manifests.
- Candidate image scanning and every applicable advisory decision must pass
  before the release tag is created.
- A mismatched immutable image, GitHub Release asset, npm package, or PyPI wheel
  requires a new release version. Exact partial publication remains retryable.
- Hosted deployments, external conformance, and adopter-specific rollout
  exercises remain outside this release's critical path.
