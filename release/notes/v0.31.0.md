# Registry Stack v0.31.0

Registry Stack v0.31.0 is the beta-43 release. It adds institutional contextual
authorization across Registry Casework, ThunderID, Evidence Gateway, and Base
Registry Engine, and retires Registry Mint from the current distribution.

## Compatibility and migration

- BREAKING: Registry Mint is no longer built, packaged, installed, or included
  in the v0.31.0 image roster. Historical v0.30.x manifests and release
  inventories remain unchanged. Replace Mint configuration with the stock
  ThunderID issuer used by the maintained development journeys, or with another
  compatible identity provider, before upgrading. Rebuild current projects and
  deployment inputs without the retired `mint` service and CLI flags.
- BREAKING: contextual task grants no longer carry the signer-chosen
  `registry_grant_authority` claim or its Casework, BReg, Evidence, status-client,
  selector, and client configuration fields. The exchange issuer derives
  `registry_grant_source_issuer` from the verified subject-token `iss`. Update
  integrations to key source identity by that verified issuer, regenerate
  schemas and clients, and remove authority-label matching. There is no
  compatibility layer for the unpublished earlier task-grant shape.
- BREAKING: BReg access profiles rename `grants` to `permissions`. Rename the
  field in authored registry projects and regenerate and reseal packages before
  starting v0.31.0.
- Local development databases containing task grants or Casework drafts from
  before the issuer-bound contract no longer load. Stop the development stack,
  remove its owned local state with the maintained cleanup command, and start
  it again from the updated project.
- Source-backed Casework development now preflights credentials for every
  configured source. Supply each required client secret before startup. The
  check reports the missing source binding without printing secret values.

## Institutional contextual authorization

Casework officers can approve governed task templates for institutional agents.
An agent exchanges a short-lived Casework assertion through stock ThunderID
1.0.1 for access constrained to the approved client, resource, purpose,
subjects, permissions, approver, and grant deadline. Casework exposes approval
and exchange through its maintained Rust, Node.js, and Python clients.

Evidence preserves signed requester context and enforces the grant deadline.
BReg routes task-authorized writes through governed change requests and checks
fresh grant status during retries, approval, and application. Token re-exchange
does not extend the approved deadline, and revocation takes effect without
changing the protected resource.

## Development and documentation

- `bregctl` and `caseworkctl` add maintained local token and task-grant flows
  backed by the stock issuer. The Casework tutorial now includes officer review
  and application of a governed BReg change.
- Source-backed Casework configuration separates bootstrap and status clients,
  binds readers explicitly, and exposes only the issuer's public JWKS material.
- The documentation removes current Mint guidance and a stale Solmara Lab call
  to action while preserving the historical Solmara tutorial.
- The unified Node.js and Python clients include the task approval, exchange,
  status, webhook verification, and Evidence context contracts used by this
  release.
