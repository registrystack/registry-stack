# Registry Stack v0.46.0

Registry Stack v0.46.0 is the beta-58 release. Releases now publish the
Registry Adapter binaries `adapter` and `adapterctl`. Rhai scripts in Base
Registry Engine (BReg), Messaging, the Adapter, and Evidence run on a
deterministic engine, and the products share one configuration vocabulary for
access profiles, display labels, and holiday sets. Registry Render seals
documents with PAdES baseline B-B and B-T signatures. Registry Evidence can
take facts from a wallet-presented credential, adds an OpenID4VP verifier
front end, and adds an experimental public certificate check. BReg names the
competent authority in its Registry Manifest and matches Unicode-equivalent
spellings in blind-index lookups. Registry Coordinator admits callers by exact
subject and holds a run it cannot restore instead of stopping. `rstack`
generates hosted ThunderID configuration from each product's identity facts.

## Compatibility and upgrade

Use matching v0.46.0 runtimes, tools, and clients. Back up each deployment and
follow [upgrade and retire](https://docs.registrystack.org/operate/advanced/upgrade-and-retire/).

BREAKING: Casework and Scheduling start fresh state:

- Casework does not read review state stored by v0.45.0 or earlier. A stored
  review policy that names `role` on an access profile is refused with a
  message naming the member, and Casework history and decided reviews still
  in their result window are not readable after the upgrade. Start Casework
  on a new database; activation refuses while any stored review, in any
  lifecycle, holds the earlier shape.
- Scheduling does not read state stored by v0.45.0 or earlier: a stored
  policy that still holds `holidaySets[*].because` is refused. Put Scheduling
  on a new database.

BREAKING: the Coordinator does not restore what v0.45.0 froze. The pure
Function interpreter ABI is now `v3`, so every definition frozen by v0.45.0
records `v2` and is refused with `definition.abi`, whether or not it uses
`curry`. A workflow snapshot whose project presentation, function, or
operation holds `title` is refused with `definition.snapshot`. Settle open
runs with the v0.45.0 binaries, then check and promote every project again
with v0.46.0. A live run whose retained definition this release does not
restore is held alone instead of stopping the deployment; a pinned package it
does not restore still stops startup.

BREAKING: Coordinator admission accepts a token only when its exact `sub` is
listed in the caller policy's `subjects`, and refuses any token that carries
an `act` claim; both answer 403 `operation.not-authorized`. Add `subjects`
to every `deployment.authentication.policies` entry: the
client's own service-account subject for a producer, and each operator's
subject for an operator policy.

This release reads the Evidence and Messaging database state v0.45.0 kept.
The release upgrade rehearsal starts from that state, re-authors the
Messaging project for `actsAs`, repackages it, and activates it over the
retained database. The rehearsal covers Evidence and Messaging only. For
BReg, rebuild the package of each project that the Manifest authority or
script engine change below affects; the Manifest change rewrites no stored
row.

BREAKING: Rhai scripts run on a deterministic engine, so the deadline or
budget each product sets holds for every call a script can make. The engine
no longer provides `timestamp`, `elapsed`, `sleep`, `exit`, `take`, `tag`,
`set_tag`, `parse_json`, or `get_fn_metadata_list`; string `pad` with an
empty padding string, which never returned, now fails; and a script that uses
the `curry` keyword no longer compiles. Remove those calls. This covers:

- BReg Action plans and Rhai hook programs. `bregctl check` and the package
  compile refuse a call by literal name (direct, as a method, or through
  `Fn("name")`) with `breg.action.plan-function-unavailable`, naming the
  function and its line. The runtime rederives a package when it loads it, so
  it refuses to load a package an earlier release built with such a call. A
  call the compile cannot see fails the invocation with
  `action.handler.execution`, and a hook program that makes one fails its
  delivery attempt. Pass any time a plan needs as an action input, and
  rebuild the package.
- Messaging provider `prepare`, `interpret`, and `receipt` scripts. A
  `prepare` script that makes such a call fails the delivery with
  `provider.prepare-failed` and sends nothing.
- Adapter pack scripts, including the packs Evidence Sources run. A script
  that makes such a call fails like any failing script, and
  `adapterctl check` does not flag it.

BREAKING: Coordinator Functions can no longer call `curry`;
`coordinatorctl check` refuses a source that uses it and suggests passing the
value as an argument.

BREAKING: the products share one configuration vocabulary, with no alias.
Rename these keys before you check, package, or activate with v0.46.0 tools.
Each old key is refused with `config.removed-key` naming its replacement,
unless noted:

- Casework, Messaging, and Document Store access profiles write `actsAs`
  where they wrote `role`, with unchanged values. The schema definitions
  `CaseworkRole` and `AccessRole` are now `CaseworkActsAs` and `ActsAs`, the
  diagnostic `casework.access-profile.missing-role` is now
  `casework.access-profile.missing-acts-as`, and the `caseworkctl dev` and
  `messagingctl` reports carry `clients[].actsAs` and
  `accessProfiles[].actsAs`.
- A Casework holiday-set file names itself with `id` where it wrote
  `holidaySet`; a calendar still names its set in
  `calendars.<id>.holidaySet`. A Scheduling holiday set writes `label` where
  it wrote `because`, and the schema definition `HolidaySetPolicy` is now
  `HolidaySet`; `because` is unchanged on every other Scheduling item.
- A Coordinator project, function, operation, and step write `label` where
  they wrote `title`. `check --explain` reports `presentation.label`, and the
  duplicate-title diagnostics are now
  `coordinator.project.duplicate-function-label`,
  `coordinator.project.duplicate-operation-label`, and
  `coordinator.project.duplicate-step-label`.
- The Render runtime file's `auth` block is `authentication`; its `oidc` and
  `apiKeyRef` members are unchanged. A file that still says `auth` is refused
  at `/auth`.
- The `evidence-oid4vci` runtime member `offers.authorizedClients` is
  `offers.allowedClients`. The old name is refused as an unknown key.

BREAKING: `registry.assertion-evidence/v1` carries a required, signed
`channel` member, `source` or `holder-presented`. Assertions signed before
this release lack it and are refused as malformed payloads; reissue them.
Verification policies accept only `source` unless they list another channel
in `acceptedChannels`, and a BReg governed Action accepts only
`channel: source`, refusing others through `action.evidence_failed`. Rebuild
relying-party bindings and regenerate golden fixtures that carry assertions
without a `channel`.

## Registry Adapter

Registry Stack releases now publish the Adapter's `adapter` facade and its
`adapterctl` tool for Linux amd64, Linux arm64, and macOS arm64, with an
`adapter-v0.46.0-install.sh` installer and an `adapter` component for
`rstack install`. `rstack adapter` runs `adapterctl`. There is no Adapter
container image, and the `adapter-job` ingestion host is not released yet:
build it from the tagged source. `adapter` gains `--version`, and
`adapter-job --version` reports the Registry Stack display version.

The facade serves GovStack Digital Registries Read and direct Write from
source packs. The Write path (direct Create and conditional Update) is
experimental; `CONSULTATION.md` lists what a source must offer to back it,
and BReg is the one maintained source that does.

BREAKING for Adapter projects and jobs built from v0.45.0 source:

- The facade no longer sends the
  `x-registry-idempotency-replay-window-seconds` response header. Capability
  discovery publishes the window as `write.idempotencyReplayWindow` on every
  Create and Update entry; a read-only deployment publishes none.
- Lookup and Search answer an invalid field or value with the problem type
  `https://govstack.global/problems/digital-registries/invalid-content`
  instead of `.../invalid-field`, the type Write already used.
- The configured `govstack-consultation` profile, the `dhis2-govstack`
  example, and its fixtures are removed. Declare a `consultation:` section in
  the project to use the built-in GovStack Consultation profile (see
  `examples/dhis2-consultation`); a configured profile named
  `govstack-consultation` no longer gets any GovStack behaviour.
- The `dhis2-tracker` routes `page-tracked-entities` and
  `page-tracked-entities-by-org-unit` take a required `tie_breaker_attribute`,
  the UID of a unique program attribute, because DHIS2 2.43 refuses
  `trackedEntity` as a sort key. Add it to each templated route that uses
  them and re-lock the project.
- A local file job source must declare how it knows a file is complete:
  `doneFileName`, `readLock: changed`, or `producerAtomicHandover: true`.
  `adapterctl job check` and `adapter-job` startup refuse a source with none.
  `readLock: changed` suits a producer you do not control.
- The `kobotoolbox` pack authenticates with the account's API token
  (`static-authorization`, `scheme: Token`) instead of Basic, so a leaked
  credential no longer signs in to the Kobo web UI. Replace the `kobo-api`
  credential's `usernameRef` and `passwordRef` with
  `type: static-authorization` and a `tokenRef`, bind the token of an account
  restricted to the form, and repin the pack digest in `project.yaml` and the
  job file. To keep Basic, pin your own copy of the pack with `type: basic`.
- The Kobo Coordinator workflow finishes an unresolved-lookup revision as
  `unresolved-reviewed` instead of `revised-reviewed`. A client that matches
  that outcome must match the new one.
- Job item and check codes are renamed with no alias. A destination's
  refusal is stored as `adapter.job.breg.<word>` or
  `adapter.job.coordinator.<word>`; rows written by an earlier release keep
  the old spelling, so match both until those rows are settled.
  `adapter.job.trigger-hook-unserved` splits into
  `adapter.job.trigger-hook-binding`, `adapter.job.trigger-hook-path`, and
  `adapter.job.trigger-member`. Postgres send member faults move to
  `adapter.job.postgres-send-members`, and the missing JSONL key pointer to
  `adapter.job.poll-key-pointer`. The host code
  `adapter.job.hook-configuration` splits into
  `adapter.job.hook-configuration-trigger`,
  `adapter.job.hook-configuration-ingress-missing`,
  `adapter.job.hook-configuration-ingress-unused`,
  `adapter.job.hook-configuration-binding`, and
  `adapter.job.hook-configuration-path`, and
  `adapter.job.hook-not-compiled` into
  `adapter.job.hook-not-compiled-trigger` and
  `adapter.job.hook-not-compiled-ingress`.

Also when upgrading a source build:

- Continuation cursors are bound to the client the caller acts through
  (`azp` or `client_id`) as well as the issuer and subject. Cursors issued
  before the upgrade are refused with `invalid-cursor`; restart the traversal
  from its first page.
- GovStack Update ETags also bind the companion read's route and the pack's
  code maps, under closure domain `v3`. ETags issued before the upgrade
  return 412 and need a fresh companion read.
- A pending direct BReg delivery is fenced before it is retried, and a retry
  whose destination or mapped operation differs stops the pass before any
  BReg call as `adapter.job.breg-receiver-changed` or
  `adapter.job.breg-body-changed`. A direct BReg item left pending by v0.45.0
  has no recorded identity, so its first retry under this release adopts the
  current destination and mapping: settle those items with v0.45.0, or keep
  the destination and mapping unchanged, before upgrading. A row staged
  before store schema 103 stops as `adapter.job.breg-identity-unrecorded`.
- A pack route's `writeSupport` is flat: `type` is `create-one` or
  `conditional-update-one`, with `replayWindowSeconds`, and the single-value
  `identity`, `replay`, and `precondition` members are removed. The unused
  `range`, `set-membership`, and `prefix` source comparisons are removed;
  only `equality` remains.
- The `dhis2-tracker` pack's Evidence lookups send `orgUnitMode=SELECTED`
  with their organisation unit. The `dhis2-tracker` and `kobotoolbox` pack
  digests change.
- Regenerate committed `generated/openapi.json` files with
  `adapterctl compile`: the GovStack OpenAPI declares the `recordId` and
  `Idempotency-Key` bounds the facade enforces.

Mapping, authoring, and the facade:

- Add the declarative AdapterMapping format (`kind: AdapterMapping`).
  `adapterctl mapping check`, `mapping generate`, and `mapping preview` check
  a mapping against the target schema, generate the pinned Rhai script from
  it, and preview it over sample inputs, all offline, and
  `adapterctl job lock` rewrites a job's mapping digest pin.
  `mapping check` reports the target schema as `targetTree` and its root
  `title` as `targetTitle`, each finding about one field names it in
  `target`, and the `adapter.mapping.script-drift` warning names its `cause`.
- Preview samples can record their expected result in
  `preview/expected.yaml`; a result that differs raises
  `adapterctl.mapping-preview-mismatch` and exits 1. `mapping preview` also
  takes `--deny-warnings`.
- A quoted selector key or filter literal takes any Unicode character except
  a control character, a text-direction control, or a line or paragraph
  separator, so a source key such as `prénom` can be mapped. Keys compare
  byte for byte.
- `adapterctl job check` warns with `adapter.job.mapping-unprojected` when a
  generated `direct-breg` mapping reads a source key that the job's
  `projection.fields` does not list.
- A project needs less configuration: a Consultation collection's `view`
  defaults to its `dataSchema`, its `transform` applies to every Retrieve,
  Lookup, List, and Search binding of that record type unless
  `bindingTransforms` names one, `recordTypes` entries with no fields are
  derived from the collections, `maximumUpstreamCalls` defaults to 4, and a
  Write Update's `companionRead` is inferred when exactly one Retrieve or
  `writable-read` binding serves the record type. The explicit forms stay
  valid. A job profile may omit `read` when
  its source route reads no file and no PostgreSQL row.
- `adapterctl check` and the Adapter's load refuse a `writable-read` binding
  that no Write Update names, instead of stopping the Adapter. The mapping
  commands refuse a `mapping.targetSchema` that a symbolic link resolves
  outside the model's directory, and an integer constant above 2^53 that only
  rounds to a target `enum` or `const` member (it used to fail every record
  at run time). A job pass stops as
  `adapter.job.projection-flat-dotted-name`, before staging any item, when a
  dotted projection field misses as a path but the row has a flat member of
  that name.
- GovStack Update replays its stored answer for a retry under the same
  `Idempotency-Key` and fingerprint even when its If-Match no longer opens,
  no longer returns 406, and refuses an object-valued merge-patch member with
  422 `invalid-content`. A Lookup identifier that cannot travel as a source
  path segment answers 404 `record-not-available` instead of 500.

## Evidence wallet presentations and public checks

- An assertion definition's `acquisition` accepts an optional
  `holderPresented: {source, selectorProfiles}` block beside `source`, and a
  request's selector profile selects exactly one channel, with no fallback.
  The built-in `wallet-presentation-v1` host protocol reads a holder's
  presentation from the wallet protocol service, verifies it in Evidence, and
  hands the route only the declared claims. Holder binding is always
  required, a `status` of `required` is refused until status checking is
  available (state `not-checked`), a holder-presented definition answers only
  as a signed JWS assertion, and `maximumCredentialAgeSeconds` accepts up to
  ten years. For a definition granted on both channels, the Discovery entry
  states its `channel` and, for an entitled caller, an `alternatives` member
  with the holder-presented shape. No wallet is claimed until a reviewed
  real-wallet receipt exists.
- Add the `registry-evidence-oid4vp` OpenID4VP verifier front end, with
  `x509-san-dns`, `x509-hash`, `decentralized-identifier` (`did:web`), and
  `pre-registered` client identifiers. It implements OpenID4VP 1.0 and the
  HAIP 1.0 verifier flow profile and is not certified. A presentation is
  consumed by its first successful read. Rate limit its wallet-facing paths
  per source at your ingress.
- `evidence-oid4vci` adds an optional OpenID4VCI Draft 13 compatibility
  profile (`draft13Profile: {}`) for wallets that accept third-party issuance
  only over Draft 13. It is served at its own issuer identifier beside the
  1.0 Final profile, whose routes and wire behaviour are unchanged.
- `evidence-oid4vci` sends the shared security headers, bounds request
  bodies, and rate limits requests, answering 429 `temporarily_unavailable`
  with `Retry-After` past a budget. The optional `rateLimits` block sets the
  budgets (defaults: `offersPerPrincipalPerMinute` 600, `offerBurst` 60,
  `walletRequestsPerMinute` 3000, `walletRequestBurst` 300); check that they
  suit your wallet traffic before upgrading a busy deployment. Framework
  rejections answer in the service's JSON error shape, and a token form that
  cannot be decoded answers 400 `invalid_request` instead of 422.
- A bundle's signing block takes an optional `signing.certificateChainFile`.
  With it, issued SD-JWT VC credentials and the served JWKS entry for the
  active key carry the chain as `x5c`; without it, issued headers and the key
  set are unchanged.
- Experimental public certificate check: a target authority activates a
  definition's `publicCheck`, and `POST /v1/public-check` answers, without
  authentication, the status, printed fields, and evaluation time of one
  certificate from a `documentNumber` and a 24-character `checkCode`. The
  answer is unsigned and Evidence does not rate limit the route: expose it
  only through a path-restricted proxy that limits each client and keeps no
  client addresses. See `examples/public-check/`.
- `normalise_name(profile, value)` is a Rhai primitive for one exact name
  comparison under the `name-match-v1` profile, which keeps the marks that
  are part of a spelling, such as a Devanagari virama, nukta, or anusvara.
- BREAKING: a source that answers 409 or 422 is recorded as a status answer.
  The request log and audit `safeErrorCategory` read `source-status` instead
  of `source-protocol`, and a 409 or 422 no longer counts toward
  `evidence_source_shape_drift_total`. The caller still receives
  `source.unavailable`. Update audit readers, log queries, and alerts that
  match `source-protocol` for a source 409 or 422.
- BREAKING: on the single and batch evaluate routes, a selector value that
  passes its profile but that the Source's inputs schema refuses answers
  `400 request.selector-invalid` instead of `503 service.unavailable`. It
  counts against the caller's selector-failure budget, and one such item
  refuses the whole batch. A caller that retried that 503 should correct the
  selector instead.
- BREAKING: `evidencectl check`, `test`, and the other project commands
  refuse a directory with no `evidence.yaml` with exit 1 and
  `evidence.project.not-found`, where they exited 3. Update scripts that
  match exit status 3 for a missing project.
- BREAKING: `evidencectl check` and bundle loading refuse a fixture without a
  `common` or `privacyExpectation` mapping as `evidence.fixture.missing-block`;
  a coequal acceptance fixture needs only `privacyExpectation`. Add
  `common: {}` and `privacyExpectation: {}` to a fixture that lacks them.
- `evidencectl target new --local` declares the source connections and
  extract bindings of the project's `local-target.yaml`, so a fresh starter
  checks and packages against it, and `target new` accepts a bare file or
  directory name. The `evidencectl package --format json` report carries
  `requirements[]` with each requirement's `configurationRevision`.
- Startup and `evidencectl doctor` name the source, endpoint, and broken rule
  when a pack source does not compile against its connection, reported as
  `evidence.deployment.refused`. A malformed `pack.yaml` is reported at its
  file, line, and key, and a Source `route` the pack does not declare as
  `evidence.pack.route-missing`.

## BReg

BREAKING: `manifestProjection` declares the identified public authorities
the Registry Manifest names in a required `authorities` list (`id`, `name`,
optional `iri` and `authorityType`, shaped like `catalog.publisher`), and
`publicService` names the authority legally competent for it in a required
`competentAuthority`. The Manifest carries them in `authorities[]` and
`public_services[].competent_authority`, so CPSV-AP renders
`hasCompetentAuthority` for that authority instead of the catalogue
publisher. A project without either key is refused with `config.missing-key`;
an empty list with `breg.manifest-projection.authorities-empty`; a repeated
id with `breg.manifest-projection.authority-duplicate`; an empty name with
`breg.manifest-projection.authority-name-empty`; a lookalike id with
`breg.manifest.authority-id-collision`; and an id that names no authority
with `breg.manifest-projection.competent-authority-dangling`. To keep the
previous Manifest output, copy the publisher as the single authority:

```yaml
manifestProjection:
  authorities:
    - id: <catalog.publisher.id>
      name: <catalog.publisher.name>
  publicService:
    competentAuthority: <catalog.publisher.id>
```

Carry `iri` and `authorityType` across when the publisher writes them. Dataset
`owner` is unchanged, and `bregctl init --from` writes both keys. Rebuild the
package. The artifact revisions of a project that projects a Manifest
change; its SQL, Action fingerprints, and stored rows do not.

- Blind-index `lookup.normalization` gains `nfc` and `case-fold`, so the
  composed and decomposed spellings of one name match and a `unique` index no
  longer accepts both. List `nfc` first for name-like fields; existing steps
  keep their digests.
- Changing only the `normalization` list of an encrypted lookup is now a
  reviewed `field-encryption-backfill` re-index. The registry stays in
  maintenance and serves no Record reads or writes for the whole re-index,
  and once the first chunk commits the target cannot be reverted, only
  resumed by retrying the same `apply`. `bregctl field-encryption preflight`
  reports each step's row count and the records that would collide, and
  holds an `ACCESS EXCLUSIVE` lock on the Record type's table for the whole
  scan: run it in a quiet window.
- A reviewed plan whose authored SQL writes a blind-index column is refused
  with `BlindIndexWrite`, a re-index step over its `maxTotalRows` is refused
  before any write, and a `field-encryption-backfill` step whose object names
  another Record type is refused as an invalid descriptor. Every
  field-encryption check runs before the apply commits anything, so a
  refused flip stays `revertible`.
- `breg.access-profile.task-grant-rows-unbound` flags a task-grant profile
  that binds no rows on a non-public Record type.
- A `record_timer.worker.iteration_failed` warning carries a closed `error`
  field naming the failure class, never a record, SQL, or handler value.
- An infinite metric value renders `+Inf` or `-Inf`, as the Prometheus text
  format requires.

## Coordinator

- BREAKING: a live run whose retained definition this release does not
  restore is held alone instead of stopping the deployment. It shows state
  `attention` with failure code `definition-refused`. Nothing runs for it,
  and `retry-same`, `reconcile`, and `cancel` refuse it with 409
  `run.definition-incompatible`. Startup, readiness, admissions, apply, and
  every other run continue; `attention=true`, doctor (`state.heldRunCount`,
  `state.heldRuns`), and `deployment-status` (`heldRuns`) list held runs. A
  pinned package this release does not restore still stops startup.
- Restore refusals give operator context: a pinned package refusal names its
  package digest and workflow, and a held run names its run id and workflow.
- BREAKING: `coordinatorctl check` refuses a
  `casework.cancel-review-request/v1` step unless its `request` maps the
  whole output of a `casework.submit-review-request/v1` step in the same
  workflow (`definition.review-request-not-run-owned`). The service does not
  start on a pinned package that breaks the rule, and a run admitted under
  such a definition is held.
- BREAKING: the Rust client's `RunListQuery` is `#[non_exhaustive]`, so a
  struct literal no longer compiles. Build it with `RunListQuery::new(limit)`
  and chain `with_cursor`, `with_state`, `with_attention`, `with_proposal`,
  `with_turn`, and `with_outcome`.
- `GET /v1/runs` and `coordinatorctl list` take `outcome=<name>`
  (`--outcome`), and the Node.js and Python `list` take it as a last
  argument.
- A Proposal wait whose read shows BReg applying the Proposal automatically
  (`submitted`, `turn: nobody`) reads again at the read floor (default 30
  seconds) instead of after `resultCheckSeconds` (default 900).
- `workflow.eventTriggers.<id>` takes an optional `label` and `description`,
  which never change the `workflowRevision`.

## Render document seals

- Add optional PAdES sealing at baseline B-B and B-T. A document type names a
  `seal` in its manifest, and the runtime file's `signing.seals` binds each
  seal to a signer, a certificate chain file, a timestamp policy
  (`timestampAuthority` for B-T, or `withoutTimestamp` for B-B), and the OIDC
  clients allowed to use it. The signer is an ECDSA P-256 key in Vault or
  OpenBao Transit, reached through a signing proxy on a Unix socket and
  pinned by `mount`, `keyName`, and `keyVersion`, or, under the `local`
  profile, a `local-jwk` key file.
- A runtime that declares a seal also declares `assuranceProfile`.
  `production` seals sign only through Transit; `local` seals sign only with
  a `local-jwk` key file and are test seals, marked so in the answer, an
  `X-Registry-Seal-Test-Only` header, `/ready`, and the audit.
- `POST /v1/seal/{type}` needs the `render:seal` scope, which `render:render`
  does not imply and the legacy API key never has. It answers the sealed PDF
  with labelled digests. A failing timestamp fails the request and never
  falls back to B-B. Seal requests add the problem kinds
  `signing-unavailable` (26), `seal-certificate-invalid` (27),
  `timestamp-failed` (28), `document-not-sealable` (29), and
  `seal-client-not-allowed` (30).
- `registry-render keygen` writes a seal key and a PKCS #10 certificate
  request, or has a Transit key sign the request, and
  `compile --preview-seal` renders a template's sealed variant offline.
- Render makes no eIDAS qualification claim. `EVIDENCE.md` records the
  pyHanko, EU DSS, and veraPDF runs on sealed files.
- BREAKING: a package without its `SHA256SUMS` is refused as
  `package-checksums-missing` (HTTP code `render.package-checksums-missing`)
  instead of `bundle-unsealed`; the exit code stays 5.
- The render route adds `pdfDigest` and `dataDigest`, and the
  `X-Registry-Pdf-Digest` and `X-Registry-Data-Digest` headers; `pdfSha256`,
  `dataSha256`, and their headers are deprecated and still sent.
  `registry-render-client`'s `RenderedDocument` requires the new members, so
  it needs a v0.46.0 server. `RenderClientError` reports an uncertain
  exchange through `is_outcome_unknown()` in place of a public field, and the
  seal types are `#[non_exhaustive]`.
- Every render worker starts from an empty environment apart from the
  dynamic loader's library search paths, so a credential in the parent's
  environment, `RAYON_NUM_THREADS`, and `MALLOC_ARENA_MAX` no longer reach
  it. On Linux, `serve` marks itself non-dumpable. The render timeout also
  bounds a worker's exit after it answers.

## Hosted identity generation

- `rstack identity generate thunderid --deployment FILE --output NEW_DIR`
  runs each selected product's `generate identity-facts` command, merges the
  facts, and writes the hosted ThunderID configuration. Select products with
  `--breg-project` and `--breg-runtime-config`, `--casework-project` and
  `--casework-runtime-config`, `--evidence-project` and `--evidence-target`,
  and `--messaging-runtime-config`. The driven tools must be the same release
  as `rstack`. No secret is read or printed, and an existing output directory
  is refused. `rstack identity check` checks an identity facts document or
  deployment file offline.
- `bregctl`, `caseworkctl`, `evidencectl`, and `messagingctl` add
  `generate identity-facts`, which writes a `registry.identity-facts/v1`
  document from the product's configuration, so the generator gives each
  principal the claims and actor kind the product requires or refuses the
  grant.
- BREAKING: identity generation derives every principal `sub` and the scope
  trees from the issuer, in separate namespaces for machine clients, browser
  apps, users, extension user types, connections, organization units, and
  roles. Every `sub` changes once, and a product keyed on `sub` sees new
  principals: update every stored `sub`, token mapping, and scope reference
  from `identity-receipt.json`. No compatibility shim exists. Changing the
  issuer string, even by a trailing slash, re-keys every principal.
- BREAKING: `registry-thunderid-tooling` refuses a machine-client JWKS with
  private or symmetric key members in development mode too, and accepts only
  RSA, EC, and OKP public keys with a unique, non-empty `kid` and the lengths
  ThunderID requires.

## Other changes

- Every runtime image overlays zlib1g `1:1.3.dfsg+really1.3.1-1+deb13u1`
  from DSA-6613-1 for CVE-2026-76844, CVE-2026-85091, and CVE-2026-27171,
  beside the libc6 and libssl3t64 overlays.
- BReg, Casework, Coordinator, Document Store, Messaging, and Scheduling each
  publish a `SECURITY-MODEL.md`.
- The products share the platform access-token algorithm roster,
  framework-rejection normalization, stop-signal handling, and Prometheus
  exposition; the accepted access-token algorithms are unchanged. BReg,
  `breg-mcp`, `registry-mcp`, Discovery, Evidence, `evidence-oid4vci`, and
  Render now refuse startup when a stop-signal handler cannot be installed.
  `breg-mcp`, `registry-mcp`, Coordinator, Document Store, and Messaging
  install SIGINT at startup alongside SIGTERM.
- Messaging bounds `messaging_http_requests_total` at 512 series and
  `messaging_authentication_refusals_total` at 8, logging a warning by metric
  name past the bound.
- Casework, Messaging, Document Store, and Evidence target-authority access
  profiles take an optional `label` and `description`, and a Scheduling
  holiday set's `label` is optional.
- BREAKING for Rust platform crate users: `registry-platform-script` replaces
  `RhaiBaseEngine::Standard` with `RhaiBaseEngine::Deterministic`, and
  `registry-platform-hooks` hook programs run on it;
  `registry-platform-sdjwt` no longer exports the holder-proof functions and
  types, which moved to `registry_evidence_verifier::holder_proof`; and
  `registry-mcp-edge` re-exports the `registry-platform-oidc`
  `AccessTokenAlgorithm`, whose `jsonwebtoken()` is now `to_jsonwebtoken()`.
- New platform crates `registry-platform-text`, `registry-platform-metrics`,
  and `registry-platform-x509`. `registry-platform-crypto` adds compact JWS,
  ECDH-ES JWE decryption, XChaCha20-Poly1305 sealing, and the opt-in
  `cms-signing` feature for PAdES signatures.

Registry Document Store remains source-only in v0.46.0, as do the Adapter's
`adapter-job` host and `evidence-oid4vp`.
