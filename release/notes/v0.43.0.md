# Registry Stack v0.43.0

Registry Stack v0.43.0 is the beta-55 release. It extends shared checks for
authored display text and local identifiers, preserves BReg presentation and
source locations through compilation and inspection, and locates Casework
routing findings on the authored rule or stage. BReg activates display-only
successor packages as metadata updates while retaining compatible frozen
Proposals, and enforces active references between Records. The embedded
Wasmtime LTS is updated to 48.0.7.

## Compatibility and upgrade

Use matching v0.43.0 runtimes, tools, and clients. This release continues the
forward state path from v0.42.0; it does not introduce another fresh-database
baseline. Back up the deployment and follow
[upgrade and retire](https://docs.registrystack.org/operate/advanced/upgrade-and-retire/),
including the BReg preparation below. The PostgreSQL 17 and UTF8 requirement
for BReg, Node.js 24.11.0, Python 3.11, and standalone Linux glibc 2.34 floors
are unchanged.

### BReg active references and packages

BREAKING: an active Record cannot reference a tombstoned target, and a target
cannot be tombstoned while another active Record references it. Conflicts
remain value-free `409 mutation.conflict` responses. Tombstoned Records and
history retain their reference IDs; no reference is automatically cleared or
cascaded.

Before switching an existing BReg runtime:

1. Build a successor package with the v0.43.0 tooling, naming the deployed
   package as `--baseline-package`.
2. Apply the successor to a representative restored-data copy.
   `bregctl plan` checks activation prerequisites but does not inspect live
   rows, so a successful plan alone does not validate existing references.
3. If validation finds active references to tombstoned targets, repair them
   through the current package, refresh the restored-data copy, and repeat
   validation.
4. Activate the validated successor package before switching the production
   runtime.

Rebuild governed packages after upgrading even when authoring changes affect
only presentation. Dataset and access-profile display metadata now contributes
to compiled revisions and artifact bytes. Display-only successors activate as
metadata updates and retain compatible frozen Proposal submissions. Unchanged
rebuilds remain empty plans.

BREAKING: BReg model, access, and actions explanations advance to `v1alpha6`,
proposals to `v1alpha2`, and lifecycle to `v1alpha7`. Select the matching
schemas in inspection consumers. Model inspection includes authored JSON
Pointers per source document and object source bindings, helping consumers
distinguish authored values from compiled defaults. Lifecycle inspection adds
each state's possible `turns` and the conditions for submitted work. Access
inspection describes each Action target's runtime-enforced authority and its
relationship to direct Record grants. These inspection additions do not grant
authority.

### Authored text and identifier checks

BREAKING: current product readers and checks extend the shared display-text
and identifier rules across authored projects, packages, fixtures, records,
and runtime configuration. Run the applicable product checks before cutover
and repair the locations they report:

- Human-visible fields using the shared display-text contract refuse bidi
  embedding and override controls U+202A to U+202E, isolates U+2066 to U+2069,
  line and paragraph separators U+2028 and U+2029, U+FEFF, and Unicode
  noncharacters. Remove the prohibited character from the named field.
  Supported multilingual shaping and direction marks remain accepted, and
  accepted text is preserved exactly.
- Two local identifiers in one checked definition namespace cannot differ
  only by `-` versus `_`. Rename one definition and update its references.
  Identifiers remain distinct; the check does not normalize them or change
  their authority.
- Equivalent peer labels produce warnings at the checked peer definitions.
  They become refusals when the command is run with `--deny-warnings`.
  Labels never select identities or authorize effects.

The owning rules are
[CFG-VAL-11 and CFG-ID-8](https://github.com/registrystack/registry-stack/blob/v0.43.0/products/platform/CONFIG-CONVENTIONS.md).
Coverage follows each product's explicit fields and definition namespaces;
this release does not claim every authoring diagnostic has source provenance.

Discovery's current publication parser applies the display-text restriction to
`title` and `description`. Its published v1alpha1 JSON Schema, context, and
SHACL bytes remain unchanged. The historical schema predates the current
parser restriction, so schema acceptance alone does not establish parser
acceptance. Check provider publications with the current tooling before
rebuilding the index.

## Other changes

- Casework routing errors identify the authored rule or stage, without
  duplicate findings for derived projections or queues. Independent findings
  are retained together, and a projection field-count refusal points at the
  policy's `routing` list.
- BReg inspection retains authored display on access profiles, datasets,
  hooks, and derived fields. Caller workspace metadata includes the labels and
  descriptions of readable derived fields. Index-field, profile read-path,
  and target-permission findings retain their owning authored item, including
  module extension blocks.
- Wasmtime 48.0.7 addresses
  [RUSTSEC-2026-0378](https://rustsec.org/advisories/RUSTSEC-2026-0378.html) and
  [RUSTSEC-2026-0379](https://rustsec.org/advisories/RUSTSEC-2026-0379.html).
- The Messaging development gateway refuses provider path segments that are
  not provider IDs. Installer scripts pass the maintained shell checks.
- Documentation streamlines the maintained product journeys and clarifies
  Manifest profile publication outputs. Archived documentation labels
  unpublished products as `main source (unreleased)`.

Registry Coordinator remains source-only. Its binaries, image, and unified
client namespace are not published in v0.43.0. The release otherwise retains
the v0.42.0 product roster.
