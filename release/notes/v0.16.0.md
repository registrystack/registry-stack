# Registry Stack v0.16.0

Registry Stack v0.16.0 is the beta-23 release. It completes the maintained
spreadsheet and HTTP adopter journeys and strengthens the security, recovery,
and operator contracts needed on the path to 1.0.

## Adopter journey

- Registryctl exposes `spreadsheet` and `http` as the closed public starter
  pair. Both use the same authoring, offline test, disposable development,
  build, trust, and deployment workflow.
- Generated deployments separate public Relay and private consultation Relay
  artifacts, operations, and secrets. Signed baselines bind both lanes, and
  generated Relay and Notary services write hash-chained audit records to
  managed persistent volumes.
- Public Relay clients must configure OIDC or an API key. Empty client sets
  fail during project validation instead of producing an unusable deployment.
- Project trust commands now use one signed-artifact root contract, and
  pre-1.0 anti-rollback state must be recreated as reviewed 1.0 acceptance
  lineage.

## Registry Relay

- Relay can start directly from a verified signed Config Bundle without an
  unsigned bootstrap configuration or break-glass fallback.
- Consultation contracts support bounded closed object and array outputs.
  Sensitive reads remain fail-closed even when source metadata is omitted.
- Missing active snapshots are reacquired through the normal governed refresh
  path instead of leaving an active dataset unavailable.
- Script execution budgets exclude Relay-owned credential, permit, TLS, and
  source waits while the existing absolute durable consultation deadline still
  bounds the whole exchange.
- Strict no-expiry OAuth credentials disable token caching. This changes the
  pre-1.0 consultation state-plane capability fingerprint.

## Registry Notary

- The `self_attested` evidence mode is removed. Every configured claim now
  requires one compiler-pinned Relay consultation.
- Structured registry claims, authenticated registrar offers, and
  representative credential issuance retain bounded transaction, proof,
  subject, and status bindings.
- Delegated consultations must consume their configured target, and delegated
  Relay results are checked for expiry again after the Relay call returns.
- The PostgreSQL state catalog advances by one attested version.

## Upgrade requirements

- Regenerate projects with Registryctl v0.16.0 and recreate reviewed 1.0
  acceptance lineage. Do not edit or reset governed state in place.
- Quiesce consultations and cleanly re-bootstrap the pre-1.0 Relay state plane
  before upgrading. Do not run older and v0.16.0 Relay binaries against one
  state plane.
- Stop Notary writers, take a verified backup, then run the v0.16.0 `state
  install` and `state doctor` commands before admitting traffic. Older or
  drifted catalogs require a sequential upgrade, a matching backup and binary,
  or a fresh installation.

## Release boundaries

- Crosswalk remains pinned at
  `1d44ec735fdc8a7c719264b339574371e8330337`.
- Hosted publication, Solmara repinning, external OpenID, OpenCRVS, DHIS2,
  wallet, verifier, and country-acceptance evidence remain separate gates.
  This source release does not claim those results.
