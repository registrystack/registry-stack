# Registry Stack v0.17.0

Registry Stack v0.17.0 is the beta-27 release. It adds Evidence as the
maintained minimum-disclosure assertion product, retires Registry Notary from
the current release, and tightens Registry Relay attribute release.

## Product scope

- Evidence ships the `evidence` runtime, `evidencectl` adopter tooling, and
  Registry Mint supporting token issuer for Linux amd64, Linux arm64, and
  macOS arm64.
- The Evidence relying-party SDK prepares requests before network I/O and
  verifies responses through the portable verifier. Native Node and Python
  packages for all three release platforms are GitHub Release assets. They are
  not published to npm or PyPI. Linux client packages require glibc; the Node
  asset names carry an explicit `-glibc` platform suffix.
- Registry Relay remains the maintained protected-read product. Registry
  Notary is retired and is absent from the v0.17.0 binaries, images, installer,
  and current documentation surface. Historical Notary releases and records
  remain immutable.
- Registry Manifest and Registry Platform remain shared stack components.
- Crosswalk remains pinned at
  `1d44ec735fdc8a7c719264b339574371e8330337`.

## Evidence

- Evidence evaluates fixed, versioned requests against authoritative sources
  and returns signed, minimum-disclosure assertions as flattened JWS JSON or
  SD-JWT VC responses.
- The service enforces bounded source acquisition and derivation, closed
  output schemas, caller authorization, signing-key state, response
  verification, rate limits, and durable value-free audit records.
- `evidencectl` creates deployment key material, prepares authoring workspaces,
  checks projects, drives local fixtures, and verifies responses without
  adding Evidence semantics of its own.
- Registry Mint issues short-lived access tokens for deployments without an
  existing identity provider. Evidence does not depend on Mint at runtime.

## Registry Relay changes

- BREAKING: Attribute-release claims are scalar-only. A projected or computed
  object or array is unavailable. A required structured claim denies release,
  and an optional structured claim is omitted. Relay emits only value-free
  diagnostics. Move structured minimum-disclosure assertions to Evidence.
- Sensitive datasets with aggregate-only execution now report
  `relay.aggregates.privacy_budget_untracked`. Aggregate routes enforce
  per-result suppression but do not track a longitudinal privacy budget.
- SP DCI response schemas never resolve remote or file references. Inline all
  referenced definitions in `response_schema_path`.

## Registryctl and installation changes

- BREAKING: Approved baseline documents use schema version `2.0`. Registryctl
  rejects version `1.0` approved sets and retired Notary lane bindings.
  Re-approve the baseline with the v0.17.0 toolchain.
- The promoted documentation archive serves the canonical Registryctl
  installer at `https://docs.registrystack.org/install.sh`.
- The Evidence installer verifies and installs `evidence`, `evidencectl`, and
  `mint` together. The normal release checksum file covers all binaries,
  installers, client packages, documentation, and release evidence.

## Upgrade requirements

- Preserve any historical Notary state, audit records, and evidence required
  by the deployment before upgrading. Registry Stack does not migrate a Notary
  deployment into Evidence.
- Rebuild current deployment projects with Registryctl v0.17.0 and re-approve
  the baseline under schema version `2.0`. Do not carry a retired Notary lane
  or its cross-lane interface digests forward.
- Review every Relay attribute-release profile. Replace structured claim
  values with scalar claims or model the structured assertion in Evidence.
- Review the privacy-budget warning for every sensitive aggregate deployment.
  Leave the warning active as an accepted limitation signal or record a dated
  deployment waiver.

## Release boundaries

- The Node and Python client archives are source-bound GitHub Release assets.
  This release does not create npm or PyPI packages.
- Beta publication promotes one verified candidate from protected `main`
  without rebuilding its payloads or image manifest.
- Hosted publication, external conformance, adopter deployments, and 1.0
  readiness remain separate from this source release.
