# Registry Stack v0.19.0

Registry Stack v0.19.0 is the beta-29 release. It introduces Relay V2 as the
supported read-only registry API and adds bounded multi-subject Evidence
request batching. The release path is limited to Registry Manifest, Relay V2,
and the existing Evidence product closure.

## Product scope

- Relay ships the `relay` runtime for Linux amd64 and the `relayctl` adopter
  tool for Linux amd64, Linux arm64, and macOS arm64.
- Evidence ships `evidence`, `evidencectl`, Registry Mint,
  `evidence-oid4vci`, and the Node.js and Python relying-party clients.
- Registry Manifest ships the `registry-manifest` command for Linux amd64.
  Its public format has no user-visible change in this release.
- Crosswalk remains pinned at
  `1d44ec735fdc8a7c719264b339574371e8330337`.

## Breaking Relay replacement

- BREAKING: `relay` replaces the legacy `registry-relay` runtime. The old
  runtime, Rhai worker, PostgreSQL release closure, and public image are not
  included.
- BREAKING: `relayctl` replaces `registryctl` for Relay V2 authoring and
  inspection. The old binary, installer, and image lock are not included.
- Relay V2 uses a governed registry contract and generated package artifacts.
  Existing Relay V1 configuration is not an in-place upgrade input.
- Relay V2 exposes bounded Record reads, named lookups and searches, CRS84
  Point data as GeoJSON or JSON-FG, and a profiled SDMX data and structure read
  subset. Access profiles remain independent from wire-format selection.

## Evidence changes

- Evidence accepts one bounded request batch containing distinct subjects and
  returns results in the same order. The outer request is validated before any
  source access, and the batch shares one authorization and execution budget.
- Fixed sources can use optimized batch acquisition when the reviewed source
  contract declares it. Per-subject fallback remains bounded and preserves the
  same response contract.
- Existing single-subject request and response formats remain available.

## Packaging and installation

- The GitHub Release contains only the current Manifest, Relay V2, and
  Evidence payloads, plus their checksums, software bill of materials, and
  security evidence.
- The public Relay image is `ghcr.io/registrystack/relay:v0.19.0`. Candidate
  bytes are promoted to that tag without rebuilding.
- A Registry Docs archive is not part of this release. Current public docs can
  be updated independently without delaying the runtime release.

## Upgrade requirements

- Build a Relay V2 registry project with `relayctl`, review its generated
  access and disclosure artifacts, and deploy `relay` with the new project.
- Replace automation that downloads `registry-relay`, `registryctl`, or the
  registryctl image lock with the `relay` and `relayctl` assets.
- Evidence clients that need multiple subjects can adopt the batch endpoint;
  existing single-subject clients require no wire-format migration.

## Release boundaries

- Beta publication promotes one verified candidate from protected `main`
  without rebuilding payloads or the Relay image manifest.
- Legacy Relay, registryctl, Registry Docs packaging, hosted deployment,
  external conformance, and adopter deployment exercises remain outside this
  release's critical path.
