# Registry Stack v0.35.0

Registry Stack v0.35.0 is the beta-47 release. It is the supported upgrade
bridge from v0.34.0: a registry whose active package v0.34.0 built can now be
the predecessor of a v0.35.0 package. It also moves every runtime to one
shared `runtime.yaml` loader, one package format, and one audit writer, adds
BReg import authorities and instance claims, and gives BReg operators a sound
PostgreSQL baseline.

Upgrade to v0.35.0 before any later release. The next minor release removes
package signing, and with it the only way to read a predecessor package that
has no `SHA256SUMS` envelope. Deployments on v0.34.0 or earlier must pass
through v0.35.0 to upgrade across it.

## Compatibility and migration

Run the same release on every runtime, tool, and client, and upgrade in the
order [upgrade and retire](https://docs.registrystack.org/operate/advanced/upgrade-and-retire/#upgrade-in-this-order)
describes: BReg first, then Casework, then Evidence, then the clients. Take
the database, package, and runtime-file backups it names first; no product
migrates backwards.

### Upgrade Base Registry Engine from v0.34.0

- A registry whose active package v0.34.0 built can be upgraded in place.
  `bregctl diff --runtime-config`, `test --baseline-runtime-config`,
  `package --baseline-runtime-config`, `apply`, and the field-encryption
  preflight read a predecessor without the shared `SHA256SUMS` envelope and
  verify it from its signed manifest: the BReg signature against the trust
  anchor, every file's digest, and a closure that refuses any file the
  manifest does not list. Test, package, and apply a successor with the
  v0.35.0 `bregctl`; do not rebuild the active package, which changes its
  revision and schema fingerprint. `breg` startup, `verify`, and
  `migration explain` still refuse a package without `SHA256SUMS` and say to
  apply a successor. Remove a `package.expectedDigest` pin on such a
  predecessor until the successor is active; it is refused as
  `package.digest_pin_unverifiable`. The migration rehearsal reports the
  predecessor's measured schema drift as the finding
  `migration.rehearsal.baseline_fingerprint_drift` instead of refusing.
- After the first `bregctl apply` with v0.35.0, a registry upgraded from
  v0.34.0 or earlier needs one
  `bregctl instance-claim adopt --acknowledge-original-retired` against its
  runtime configuration before `breg` starts. Such a registry records no
  instance claim, and `breg` refuses to serve it until the claim is adopted.
  See [upgrade and retire](https://docs.registrystack.org/operate/advanced/upgrade-and-retire/#upgrade-in-this-order).
  A later release is expected to remove this step.
- BREAKING: BReg writes audit as JSON Lines to a file or standard output
  through the shared audit writer, and keeps no audit state in PostgreSQL.
  Add `audit.path` to each runtime configuration (a file destination is the
  default, and a configuration without `audit.path` is refused at startup).
  If you must retain the old journal, export it with the v0.34.0
  `bregctl audit export` before upgrading. The first apply refuses while
  `registry_internal.registry_audit` or `registry_audit_head` still holds
  rows; archive them (for example with `pg_dump --table`), then apply with
  `--acknowledge-retired-audit-discard`. `bregctl audit verify`, `export`,
  and `prune` are removed. Audit-writing `bregctl` lifecycle commands write
  to a sibling file such as `audit.bregctl.jsonl`.
- BREAKING: published BReg packages carry the shared `SHA256SUMS` envelope.
  `bregctl package` reports `packageDigest`, `--revision` adds a
  hash-covered `REVISION`, `breg` verifies every listed file at startup, and
  `package.expectedDigest` pins the digest.
- BREAKING: `breg` reads `runtime.yaml` through the shared loader and takes
  it as `--runtime-config FILE`; `--config` is refused with the replacement
  named, and the container image passes the new flag. `${VAR}`,
  `${VAR:-default}`, and `${VAR:?message}` are substituted as text after
  parsing, so write numbers and booleans directly in the file; an expression
  in a `*Ref` field, under `secretProviders`, or in the authored project is
  refused. An empty YAML scalar is now null, so quote `""` where an empty
  string is meant. `authentication.oidc.issuer` must be `https` (plain
  `http` only on an IPv4 loopback host), and `jwksSource` gains `kind: uri`.
- BREAKING: `breg` refuses a database other than the one its instance claim
  names, so a logical restore (`pg_dump` and `pg_restore`) or a `pg_upgrade`
  move no longer starts until the original is retired and
  `bregctl instance-claim adopt --acknowledge-original-retired` moves the
  claim. A physical copy keeps its identity. `bregctl instance-claim status`
  reports the claim. A Rust `match` over `StartupError` must handle
  `InstanceClaimMismatch`.
- BREAKING: every `reference` field gets a btree index unless a declared
  index or an unconditional unique constraint already leads with it, and
  `bregctl check` reports `entity.list.unindexed_filter` and
  `entity.list.unindexed_sort`, which fail only under `--deny-findings`. The
  successor the upgrade applies adds these indexes as compatible additive
  changes; each plain `CREATE INDEX` blocks writes to its table until the
  migration commits.
- BREAKING: `bregctl test --baseline-runtime-config` rehearses the successor
  migration on the disposable test database before it writes a receipt, so a
  plan that failed only at `apply` now fails `test`. An unrebuildable
  predecessor is refused as `migration.rehearsal.baseline_unavailable` or
  `migration.rehearsal.baseline_not_reproducible`.
- BREAKING: a refused statement after `bregctl apply` began maintenance is
  reported as `apply.migration.statement_failed`, naming the SQLSTATE and
  object, instead of `apply.migration.failed`. `registry-breg` adds
  `MigrationError::StatementFailed` and `PostgresKernelError::Statement`.
- BREAKING: a reviewed `chunked_backfill` step appends one history revision
  per changed row in the chunk's commit, caps `chunkSize` at 1,000, and must
  be a single `UPDATE` of the declared entity that leaves record metadata
  alone.
- BREAKING: `bregctl history rebaseline` accepts a registry of any size,
  verifying live rows in pages of 1,000 in one transaction that holds every
  entity table exclusively; size its maintenance window from a rehearsal. The
  live-row budget codes and `MAX_REBASELINE_LIVE_ROWS` are gone.
- BREAKING: ingestion runs gain the `blockedReason` and attempt outcome
  `importAuthorityClosed`; the Rust, Node.js, and Python clients carry the new
  enum value. `bregctl data import` reports a `412` run creation as
  `data.import.ingestion_run.import_authority_required` or
  `data.import.ingestion_run.precondition_failed`, and a blocked run as
  `data.import.ingestion_run.import_authority_closed` or
  `data.import.ingestion_run.blocked`.
- Runtime sessions carry `jit=off` and a 120-second
  `idle_in_transaction_session_timeout` as startup options and name
  themselves in `pg_stat_activity`. Poolers must run in session mode; one that
  drops startup options needs the settings on the runtime role.

### Upgrade Registry Casework

- BREAKING: Casework and its BReg sources run in lock-step. The Casework BReg
  adapter reads BReg's `Registry-Engine-Version` header and refuses a source
  of another release as a source outage. Upgrade each BReg source first, then
  Casework, to v0.35.0.
- BREAKING: Casework writes audit through the shared writer (schema
  `registry-casework-audit/v1`) instead of a hash-chained journal published
  from PostgreSQL. Run v0.34.0 until its publisher drains
  `casework_audit_outbox`, because `casework migrate` refuses while the
  outbox holds unpublished records. Then archive the old audit file and every
  numbered sibling, and use a fresh `audit.path`. Retention deletes aged
  sealed files under that path.
- Run `casework migrate` before serving: schema version 17 drops the audit
  outbox, and schema version 18 records reconciliation outcomes. `GET /ready`
  answers `503` once a source's reconciliation has failed five consecutive
  passes.
- BREAKING: Casework reads `runtime.yaml` through the shared loader.
  `listener.bind` is required, `authentication.oidc.jwksUri` becomes a
  `jwksSource` of `kind: uri`, the issuer must be `https` (IPv4-loopback
  `http` only under `development-loopback`), and under
  `operator-controlled-upstream` `authentication.oidc.allowedClients` must
  name at least one client. An environment expression in `casework.yaml` is
  refused.
- BREAKING: a Casework package is the shared package format.
  `caseworkctl package` writes `SHA256SUMS` in place of
  `casework.package.json` and reports `packageDigest`;
  `package.expectedPolicyDigest` is renamed `package.expectedDigest`. The
  runtime verifies `package.root` in every listener mode, so rebuild every
  deployed package, and `caseworkctl dev` serves a package it builds on start.
- BREAKING: the runtime refuses a policy package that would strand in-flight
  work pinned under an earlier package, naming each conflict; let the work
  finish, or set `package.acknowledgeStrandedWork` to the package digest the
  refusal names. `caseworkctl doctor` previews the same comparison.
- BREAKING: `caseworkctl doctor` names the failed check with
  `casework.doctor.check-failed`, and the `--format json` wire contract moves
  to `caseworkctl/v1alpha2`.

### Upgrade Evidence

- BREAKING: Evidence writes audit through the shared writer. The bundle
  `audit` section is `hashKeyRef` and `hashKeyVersion`, and the runtime
  `auditStorage` block becomes `audit` with `destination`, `path`,
  `rotateBytes`, and `retainDays`. Archive the old chained files and point
  `audit.path` at a fresh file in a directory that holds no old sealed
  segments. `evidence verify-audit` and the
  `evidence_audit_segments` and `evidence_audit_bytes` metrics are removed.
  Entry schemas move to `/v2`; update audit readers before routing traffic.
- BREAKING: Evidence Gateway reads `runtime.yaml` through the shared loader.
  The file opens with
  `apiVersion: registry.registrystack.org/evidence-runtime/v1alpha1` and
  `kind: EvidenceRuntimeConfig`, `bundleDirectory` is `package.root`,
  `listener.bind` is one `host:port`, and the governed bundle's
  authentication fields move under `authentication.oidc`. Every subcommand
  that reads the runtime file takes `--runtime-config FILE`; the global
  `--runtime` flag and `REGISTRY_EVIDENCE_RUNTIME` are gone.
- BREAKING: `evidencectl package` publishes one environment-neutral package
  directory with `SHA256SUMS` and no copied `runtime.yaml`; the gateway
  verifies every listed file and `package.expectedDigest` pins it. The
  separate bundle and runtime revisions are removed, and `evidencectl build`
  is refused with `evidencectl package` as the fix.
- BREAKING: `evidencectl` refuses a derivation whose `answer` reads a fact
  its source does not declare, as
  `evidence.authoring.derivation-fact-undeclared`, so a BReg field rename is
  caught before `source update` installs it or a candidate is packaged.

### Upgrade Relay, Discovery, and Scheduling

- BREAKING: Relay reads `runtime.yaml` through the shared loader
  (`registry.registrystack.org/relay-runtime/v1alpha1`,
  `kind: RelayRuntimeConfig`); `server.bind` is `listener.bind`,
  `packagePath` is an absolute `package.root`, `authentication.issuer` is
  `authentication.oidc`, and `secret:file/` references resolve under
  `secretProviders.file.root`. `relay check` and `relay serve` take the
  required absolute `--runtime-config FILE`.
- BREAKING: Relay writes audit through the shared writer
  (`registry.relay.audit/v2alpha2`). Rename `audit.sink` to `audit.path`,
  delete `audit.integrityKeyRef`, and move the old log aside. `relayctl
  package` writes the shared `SHA256SUMS` format in place of
  `relay-package.json`; reseal every package.
- BREAKING: Discovery reads `runtime.yaml` through the shared loader
  (`registry.registrystack.org/discovery-runtime/v1alpha1`,
  `kind: DiscoveryRuntimeConfig`), `listener.address` is `listener.bind`, and
  the binary takes `--runtime-config FILE`. `discoveryctl` builds the index
  as a shared package, and the runtime verifies `SHA256SUMS` under
  `package.root` before it serves `discovery-index.json`.
- BREAKING: Scheduling writes audit through the shared writer
  (`registry-scheduling-audit/v1`). Run v0.34.0 until its publisher drains
  `scheduling_audit_outbox`, then run `migrate` to schema version 8, archive
  the old audit files, and use a fresh `audit.path`.
- BREAKING: Scheduling reads `runtime.yaml` through the shared loader:
  `listener.bind` is required, `authentication.oidc.jwksUri` becomes a
  `jwksSource` of `kind: uri`, and `schedulingctl package PROJECT --output
  DIRECTORY` writes the shared package format that the runtime verifies at
  every start.
- Registry Manifest has no user-visible changes in this release.

## Base Registry Engine

- Upgrades from a package the previous release built, as described above.
  `diff --runtime-config` classifies changes against the running package's
  signed migration baseline, so it reports a compiler-owned reference index
  the successor adds as a lock risk.
- The `import` operation and import authorities load a governed entity in
  bulk without granting `batch`, `create`, or `patch` to a direct-write
  profile. An operator opens an authority with
  `bregctl import-authority open` for one entity and one profile, bounded by
  a window of at most 30 days and a maximum item count, with optional pinned
  input digests.
- `breg` and `bregctl doctor` report value-free PostgreSQL advisories about
  pool size against usable connections, `autovacuum`, `track_counts`, and
  `pg_stat_statements`. Advisories never refuse startup.
- Raising a `text` field's `maxLength`, or lowering a `string` field's
  `minLength` under the same `maxLength`, is a compatible
  `field_length_widened` change applied live.
- `bregctl diff` reports every removed field or entity as
  `diff.history.removed_values_retained`, because the values remain in
  earlier revisions and backups until `bregctl history erase` removes them.
- An accepted review whose result lookup answers an empty `404` reports
  `result-unknown-to-authority`, and `bregctl review-recovery resubmit` and
  `close` recover or stop waiting on a review the authority lost.
- Every audited request entry is answered: work that ends after its attempt
  without a terminal entry writes an `unfinished` response under the same
  correlation.
- Removing or narrowing an access profile drops the predecessor's obsolete
  row-level security policies during successor apply, and startup names a
  missing review authority binding with its retained-submission count.

## Registry Casework

- The optional `metricsListener.bind` serves `/metrics` and `/version` on an
  operator-private address.
- Database connections fail within seconds when the server stops answering,
  through default connect, keepalive, and TCP user timeouts.
- One item a reconciliation or event-synchronization pass cannot apply no
  longer stops the rest of the pass.
- Review grants retire in the same template-activation transaction as
  ordinary grants, so reintroducing an identical template cannot revive
  either old grant.

## Evidence

- An access-token issuer behind a private certificate authority can be
  trusted through a named `tlsTrustProfile` on the bundle's `authentication`
  block, for the `jwksUri` connection alone.
- `evidencectl doctor --without-audit-lock` and
  `evidence check --require-runtime-dependencies --without-audit-lock` check
  a candidate staged beside the running instance.
- `evidence check` and `serve` name the fault that stopped a Transit signer
  from initializing, without paths, provider responses, or key material.
- `evidencectl` output formats match what each command renders: human-only
  commands refuse `--format json` with `evidencectl.format.unsupported`, and
  `audit show` gives specific refusals.

## Shared platform and clients

- The shared platform crates add the runtime configuration loader and its
  shared blocks, the shared package format, and the `AuditWriter` every
  product uses, and remove the audit hash chain. See the platform changelog
  for the Rust API changes.
- Registry Render adopts the shared loader, package format, and audit writer.
  It is not a release artifact.

## Release process

- The upgrade rehearsal reads a predecessor package the previous release
  built, and exercises the Evidence upgrade through a packaged production
  target.
- The heavy integration tier and release recipes run after review, on the
  merge queue and protected `main`.
